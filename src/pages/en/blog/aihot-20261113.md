## ★ Most Worth Your Attention Today

**SGLang used the Summit to formalize "production-grade" into v1.0, but the GitHub official tag is still at v0.5.23 — a "declared, not yet tagged" milestone, not a version you can install and upgrade to today.**

The trouble here is not technical, it is **reachability**:

1. **Declared**: at the inaugural SGLang Summit (11/12–13, San Francisco) v1.0 was announced — 330+ organizations, 217 models on day one, Miles v0.2 released alongside. The three pillars are a Rust-rewritten critical path + zero-overhead scheduling + speculative decoding/megakernel + HiCache tiered cache + PD disaggregation.
2. **But the tag didn't move**: the GitHub Releases official tag is still **v0.5.23**, and the release notes are pending. In other words, most of the v1.0 kernel is an integration of existing v0.5.x capabilities — there is no corresponding tag in the repo yet.
3. **Security unpatched**: SGLang still carries **CVE-2026-111391** (fixed only in main, no patched release, v0.5.23 unpatched), and the v1.0 announcement said nothing about the fix; on the same day vLLM had no equivalent vulnerability.

**Actionable conclusion**: treat v1.0 as "roadmap confirmation," not "installable version." Wait for the tag + release notes before upgrading; in the meantime stay on v0.5.23 and watch the CVE.

> Worth saying separately: this "**Summit draws the picture, repo has no tag**" rhythm looks a lot like the pre-v0.5.x era. What actually matters to production users is not the keynote deck but the day `git tag` and the release notes land — until then, v1.0 is a narrative, not a binary.

## 2. vLLM & SGLang Community Tracking

**Version status**: vLLM **v0.34.0rc0–rc2** (released 11/9–12, GitHub Latest still shows **v0.33.0**); SGLang announced **v1.0** at the Summit, but the official tag is still **v0.5.23**.

### vLLM v0.34.0 RC

**New features / notable PRs**:

- **rc0: Gemma / StableLM migrated to the Transformers backend** (#66393) — the direction is to consolidate upstream definitions and cut maintenance cost, at the price of short-term regression in fused operators.
- **rc1: XPU speculative-decoding fix** — `greedy_argmax` treated NaN as `-inf`, which is fixed to remove cross-hardware garbage risk.
- **Model support**: **Kimi K3.1 Pro needs vLLM ≥ 0.34.0** (MXFP4, TP8, ~1.56 TB on disk); the stable v0.33.0 only contains K3 code and cannot run K3.1 Pro.

**Breaking changes**: no explicit breaking list this cycle (see release notes); but rc0's "move back to the Transformers backend" means downstream depending on custom model definitions / fused operators must re-test — a **hidden breaking change** (see Standing Topics).

> ⚠️ **If you need to run Kimi K3.1 Pro**: the stable v0.33.0 is not enough — you need ≥0.34.0 (currently RC). TP8 + 1.56 TB on-disk weights mean confirm your machine can even hold it before deciding to chase the RC.

**Architecture / performance (v1.0 three pillars)**:

**Community signal**: attendees relayed that roughly **95% of merged PRs are now written by agents** (vibe coding) — a year ago they were basically hand-written. This says more about the community's productivity shift than any single benchmark.

**Known pit (see the ★ section)**: v1.0 is declared only, the tag is still v0.5.23, and **CVE-2026-111391 is unpatched** — treat it as "declared, not yet tagged" before upgrading.

### Under the Hood: HiCache Tiered KV Cache

The most worthwhile technical read of the day.

**The path**: **GPU HBM → host memory → lower storage tiers**.

The core idea: split KV into **hot / cold tiers**, and each agent round only pulls back the "new suffix + selected history blocks" instead of permanently holding the entire long context in VRAM.

> It **complements** rather than replaces vLLM's "low-precision KV + prefix cache": vLLM goes the "compress volume" route, SGLang goes the "tiered offload" route. Step 5's sparse attention (3 sliding windows + 1 sparse layer) is the **model-side** counterpart of the same idea.

The benefit is direct: **long-context agent workloads no longer occupy the most expensive memory permanently for every cold session.** The cost is a one-time I/O tail latency on cold restore, landing on P99 — the line interactive experience is most sensitive to. DeepSeek-V4-Flash multi-turn measured 15.5× throughput, 98% hit rate; Novita's coding-agent TTFT dropped 56%, showing this trick already works in agent scenarios.

### Standing Topics

**PD disaggregation**: vLLM pushes NIXL + MRV2 (needs NIXL 1.5+); SGLang from v0.5.21 adds PD instance hot-swap (#28403) + KVShard + DSpark-NIXL + Mooncake + sgl-router (Rust) cache-aware; Step 5's routing layer reuses prefixes by KV events; the Summit pushed the NVIDIA Dynamo + SGLang + Vera Rubin plan.

**Architecture evolution**: SGLang's Rust critical path + megakernel headline; speculative decoding diverges into MTP / EAGLE / DFlash / DSpark; NVFP4 4-bit + ROCM_OCTAVE 3–4bit low-precision KV; Step 5 hybrid attention as the representative new long-context architecture.

**PyTorch vs transformers**: a **reverse signal** — vLLM v0.34.0rc0 moves Gemma / StableLM **back to the Transformers backend** (unified definitions, lower maintenance), at the cost of short-term fused-operator regression. Conclusion: **production frameworks converge on "Transformers definitions + in-house runtime,"** and the pure-PyTorch stack retreats to research / extreme-optimization niches.

**Step adaptation**:

- **Step 3.7 Flash** (198B MoE) ships four weight formats (BF16 / FP8 / NVFP4 / GGUF, Apache 2.0) + official vLLM / SGLang deploy commands; NVFP4 + MTP measured **1.13×–1.45×**.
- **Step 5 Preview** (600B / 27B active, 1M ctx, image-text) is **Day-0 on both frameworks**: SGLang contributed the StepFun sparse-attention kernel, FlashInfer TRT-LLM ~299 tok/s, MegaMoE @64 ~740 tok/s/GPU, MTP accept 2.85.
- Edge / multimodal: Step-3-VL-10B runs locally (RTX 4090 24GB); Step-Video / Audio Huawei Ascend Day-0 adaptation is in progress.

> The Step thread is worth its own look: **equal treatment of vLLM and SGLang, Day-0 on both, and Day-0 on domestic accelerators (Ascend / Moore Threads)** — a "framework-neutral + domestic-hardware-first" playbook, completely different from the old route of binding to a single framework.

## 3. AI Papers + Industry Hotspots

**Today's highlight (1 line)**: InstructBLIP's single minimal change — "instruction into Q-Former" — takes a VLM to zero-shot SOTA across 13 unseen datasets, while the embodied-AI supply chain enters the "brain (Walker S2 mass delivery) / data (G1-D data-collection)" realization phase.

### Paper Core

**InstructBLIP** (Salesforce, arXiv:2305.06500) — the first systematic study of vision-language instruction tuning. Three core lines: ① the instruction text feeds into Q-Former's cross-attention, not just the LLM; ② same image, different instruction → different 32 visual tokens, the instruction becomes a filter for visual features; ③ ablation shows "remove instruction-awareness" only hurts held-out → the gain is generalization. Impact: establishes the VLM instruction-tuning paradigm (cited by Qwen-VL, etc.) and is the source of language-conditioned vision in RT-2 / OpenVLA / Hi Robot.

**Operator explainer · Perceiver Resampler** (Flamingo) — arbitrary frame features → constant 64 latents, keeping LM input length stable. Key points: ① zero-initialized tanh gate protects frozen weights; ② fixed length = information bottleneck, but edge VLA needs constant control latency (SmolVLA's 64-token approach is the same idea).

**Performance optimization · SGLang HiCache three-tier KV** — solves the GPU VRAM capacity ceiling of RadixAttention prefix cache (L1 GPU / L2 DRAM / L3 cluster storage + HiRadixTree); DeepSeek-V4-Flash multi-turn 15.5× throughput, 98% hit rate, Novita coding-agent TTFT -56%.
