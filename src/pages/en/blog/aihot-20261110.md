## ★ Most Worth Your Attention Today

**Low-precision KV closes on both engines — vLLM spreads it across the stack, SGLang fuses persistent kernels, and Step 3.7 Flash runs NVFP4+MTP day-0/1 on both for the first time.**

Both frameworks hold their 11-02 stable closes over the last 72 hours (vLLM v0.33.0 / SGLang v0.5.23), with no new release; the main line is Summit warm-up plus low-precision KV closing on both engines. What actually matters is **the same main line taking shape on both engines at once**:

1. **vLLM v0.33.0 spreads low-precision KV across the whole stack**: NVFP4 KV covers SM8x/SM12x/SM90, AMD adds ROCm Octave 3–4bit KV (RX 7900 XTX reaches 4.6× the FP16 token volume), GLM-5.3-Flash defaults to FP8 KV (+9.8% end-to-end throughput); effect: ~4× VRAM capacity for long-context / high-concurrency without touching hardware.
2. **SGLang v0.5.23 low-latency**: optional NVIDIA megakernel / AMD monokernel fuses DSv4.1-Flash decode into a persistent kernel — +44% single-user decode on GB300, +75% on MI350X; DSv4.1 prefill +1.5× on GB300, 32K–64K TTFT -28%.
3. **Step 3.7 Flash day-0/1 on both frameworks**: vLLM stepfun37 image / 0.34 nightly, SGLang dev-step-3.7-flash, four-format weights, NVFP4+MTP measured at 1.13×–1.45× decode speedup, already upstream in llama.cpp.

**Actionable conclusion**: low-precision KV plus fused persistent kernels is the shared monthly main line — for long-context / Agent / RAG workloads, turning on low-precision KV is usually cheaper than swapping GPUs; the cost is a tiny amount of error (Step's NVFP4+MTP quality stays within noise).

### Under the Hood: Why Low-Precision KV Gives ~4× Capacity

The most worthwhile technical read of the day.

**Inference VRAM ≈ fixed weights + KV cache that grows linearly with concurrency × context**; FP16 → FP8 → 4bit halves twice, so same-GPU context capacity is roughly **4×**. vLLM v0.33.0 rolls out NVFP4 / ROCm Octave 3-4bit across the stack, and GLM-5.3-Flash fp8_ds_mla reaches up to **+31%** throughput.

The cost is a tiny amount of error (Step's NVFP4+MTP quality stays within noise) — for long-context / Agent / RAG workloads, turning on low-precision KV is usually cheaper than swapping cards.

> My read: low-precision KV plus fused persistent kernels is the shared monthly main line for both engines. It asks for no hardware change yet pushes the VRAM ceiling of long-context / Agent workloads up about 4× — provided you accept a tiny numeric error. For RAG / Agent loads that are "long context, insensitive to occasional precision," turning on low-precision KV first beats stacking GPUs.

## 3. AI Papers & Industry Hotspots

### Paper Core · Concertina: Actions as Continuous Latent Tokens

**arXiv:2611.07513 (2026-11-05, code / weights open)**

- One-liner: encode "one control step's D=20 action vector" as a single continuous latent token in the diffusion VLM's hidden space, then reconstruct the action block with the backbone's native mask-and-fill operator — dropping both the action tokenizer and the action expert.
- Core idea, three lines: ① an action block = a run of continuous latent tokens, so generating actions degrades to "fill in the masked tokens"; ② bidirectional within a block, causal across blocks, [C, Z̃, Z] packed into one forward pass supervising M blocks; ③ loss lands on physical coordinates (translation : rotation : gripper = 500:10:1, 1/t inverse weighting), not token cross-entropy.
- Key numbers: action params 9.49M / **0.21%** (π0 16.51%, X-VLA 35.10%); LIBERO **98.15%**, LIBERO-Plus 85.9% (8615/10030), CALVIN AvgLen 4.142 (SR@5 64.9%, still behind X-VLA 78.8%).
- Impact: the VLA parameter ledger may be rewritten (no need for "7B backbone + 3B expert"), loosening on-device VRAM / latency budgets; competes head-on with the dual-system S1/S2 route. Risk: benchmarks saturating, RoboColosseum shows cross-embodiment ranking consistency of only Kendall W=0.24.

### Operator Note · Masked Diffusion / absorbing-state

- Positioning: turns serial generation into "mask a whole block — fill in parallel," the common substrate of LLaDA / Dream / BARD-VL / DiffusionGemma.
- In-use models: LLaDA 8B (w(t)=1/t, semi-autoregressive 32-token blocks), Dream 7B (Qwen2.5-7B diffusionized + CART), BARD-VL (Qwen3-VL block merging 4→8→16→32 + mixed-noise "error correction"), DiffusionGemma (256-token blocks, 1000+ tok/s).
- Key point: what it saves is serial depth (L→T), not FLOPs — every step is full-length bidirectional with no KV cache; bidirectionality is something AR structure cannot do, but the commit rule injects sampler bias.

### Performance Optimization · Model Cascade Routing (Cascade / Router)

- Positioning: optimizes "cost per successful task," not single-forward kernel.
- Flagship work and gains: RouteLLM saves 85% cost while keeping 95% of GPT-4 quality (only 14% of requests need the frontier model), FrugalGPT up to 98%; honest production range 40~70% (Cursor 60%, Ramp 40%).
