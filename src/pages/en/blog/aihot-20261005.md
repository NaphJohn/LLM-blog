### Under the Hood: vLLM #56158 — Root Cause and Fix of the "HiSparse+MTP+FULL Graph" Silent Garble (the correctness pit graph replay bypasses)

- **Root cause**: HiSparse clears per-batch host mirror metadata on the **Python eager path every step**; **FULL graph replay bypasses that prep** → freshly written KV never copied to host → overflow reads **uninitialized data** → silent garble. Reproduced: GLM-5.3 16×H200 @1024 concurrency, ~**13.9k context**.
- **Fix**: rebuild the mirror state + add a guard **before `run_fullgraph()`**; deployments using sparse attention / speculative decoding must run a **long-context high-concurrency regression** and watch for **anomalous draft-acceptance drops**.

> My read: this is a classic case in the "strip Python from the scheduling/cache hot path" trend — once bookkeeping enters graph replay it escapes the Python guard, and correctness can only be held by explicit rebuild + guard. vLLM 0.31 making MRV2 default and removing PagedAttention is the thorough fix that migrates such bookkeeping onto GPU-Native/Triton; during the migration the old path (FULL graph) can still bite at long-context high concurrency, so rc4's fix outranks feature increments.
