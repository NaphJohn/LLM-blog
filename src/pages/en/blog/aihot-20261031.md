## ★ Most Worth Your Attention Today

**SGLang's all-versions RCE (CVE-2026-111391, CVSS 9.2): the fix is in main, but no release carries it.**

This is the only item today that will **hand an attacker code execution on your cluster** — and, just like September, the trouble is not the vulnerability itself but the **reachability of the fix**.

Three layers of fact:

1. **Symptom / scope**: SGLang's **Dumper `eval()` RCE**, CVSS **9.2**, **affects every installable version from 0.5.10 to 0.5.22**. In other words, every SGLang you can `pip install` today is vulnerable.
2. **Fix**: PR **#44205** (AST whitelist evaluator) has been merged to **main**.
3. **The problem**: it is **in no release yet**; the latest **v0.5.22 is still affected**.

**Reachability read**: the default `DUMPER_SERVER_PORT` is unset → this is not a public-net worm-level mass exploit, but the risk is **very high in long-lived clusters with the debug port left exposed** (shared debugging environments, forgotten dev deployments).

**Actionable mitigation (the only thing you can do until a release ships the fix)**:

- `unset DUMPER_SERVER_PORT` (close the dangerous surface)
- Block **`/dumper/configure`** at the network layer
- Set an **independent `admin_api_key`**

> Worth saying separately: this is once again a case of "**the fix is in main but the release channel hasn't caught up**." It is the same story as SGLang's NVFP4 bug back in September — and it proves, again, that your dependency-management strategy needs both an **emergency path for building from main** and a **security-advisory subscription**: otherwise a CVSS 9.2 can sit silently on every node of your production environment without you ever knowing.

### Under the Hood: vLLM Push-Based NIXL KV Transfer

The most worthwhile engineering read of the day — it turns "how PD disaggregation gets fast" from jargon into a flippable switch.

**The bottleneck in default pull mode**: on the first-token critical path it serially runs "router forwards metadata → decode allocates target blocks → NIXL READ pulls" — three round-trips all stuck on the latency-sensitive critical path.

**What push mode does**: it lets the **decode instance register target blocks early** — while prefill is still computing KV, the target blocks are already registered. Transfer coordination and setup are moved to the **prefill side plus a background thread**, so there is no round-trip or decode-side setup blocking on the critical path.

**The payoff**: 1P1D (Qwen3-32B, P5en EFA) **TTFT up to 3×, TPOT +30%**; **accelerator-agnostic** (validated on Trainium, then contributed to vLLM, so GPUs benefit too).

> My read: teams already doing PD disaggregation + NIXL **can turn on the push connector right now** — this is a "flip a config and get 3×" win, not worth waiting for the next release. It confirms a trend once more: the competitive front in inference engines is shifting from "single-GPU throughput" to "cross-instance scheduling latency."

## 3. AI Papers & Industry Hotspots

> The papers + industry digest is present today; what follows is the core extraction (alignment genealogy part 3 / operators / performance optimization / industry).

### Paper Core: DPO (Direct Preference Optimization, arXiv:2305.18290, NeurIPS 2023)

**One-line position**: no reward model, no RL — learn alignment directly from paired preference data, because **the LM itself is the implicit reward model.**

**Core idea**: KL-constrained reward maximization has a **closed-form optimal solution** → invert `r = β·log(π/π_ref) + β·log Z` → substitute into Bradley-Terry, and the partition function **cancels** in the win/lose difference → the loss collapses to **`L = −log σ(βΔ_w − βΔ_l)`**, a **binary classification loss.**

**Impact**: the default for Zephyr / Llama 3 / Tülu 3; TL;DR win rate **61% vs PPO 57%** at about **1/3** the cost; a large variant family (IPO/KTO/SimPO/GRPO); pitfalls = **likelihood displacement** and **offline, no exploration.**

> This lands especially well today: as inference engines (above) push complexity to operating-system scale, the alignment side uses DPO to compress RLHF's "two-stage engineering" into a single classification loss — **the two sides' engineering philosophies run exactly opposite: one is adding layers, the other is removing them.**

### Operator Walkthrough: Weight Tying (Press & Wolf, EACL 2017)

The input word embedding and the output projection **share one V×d matrix**, saving a whole set of parameters (about **13%** on Llama-3-8B); GPT-2/Gemma/Qwen3 small sizes tie, Llama 7B+ untie. In-use models: Gemma, Qwen3 0.6B–4B, SmolVLA backbone SmolLM2. Key point: RT-2/WorldVLA share the action-token space with the language embedding, its multimodal extension; pitfall = **don't double-quantize tied weights.**

### Performance Optimization: Fiddler (UT Austin, arXiv:2402.07033, ASPLOS)

**MoE single-GPU inference when the model exceeds VRAM** — **move activations, not weights** (three orders of magnitude less transfer) + **shadow execution parallel race** to hide memory access; a **24GB GPU runs unquantized Mixtral-8x7B (>90GB) at >3 tok/s, up to 22.5×.** Embodied relevance: the robot's onboard small GPU + strong CPU is a **third edge-cost-reduction path.**
