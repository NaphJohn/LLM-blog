## ★ Most Worth Your Attention Today

**vLLM v0.33.0 was officially promoted to stable on 11-02 — but it is a "barbed" upgrade: a basket of breaking changes (Python 3.10 dropped, dependency floor transformers≥5.16.1, and max_tokens semantics flipping from "reserved window" to "output cap") means upgrading an existing deployment is not "just bump the version" but "reconcile first." On the same day SGLang 0.5.23 pushes PD disaggregation to production grade — the two frameworks are no longer racing on who drafts faster, but on who runs disaggregated deployment more stably, more cheaply, and more observably.**

Three layers of fact:

1. **Version body**: vLLM v0.33.0 (11-02, promoted from rc3; previous stable v0.32.0 was 10-17); SGLang v0.5.23 (11-02 release / 10-30 tag) has no new tag within the window, conclusions held; the Step series also has no new weights.
2. **Breaking changes (will directly break production)**: Python 3.10 no longer supported (floor 3.11, up to 3.14); dependency floor transformers≥5.16.1, tokenizers≥0.23.2; `max_tokens` semantics inverted — long prompt + large max_tokens no longer rejected, so billing / truncation logic must be re-aligned; removed cascade attention, mamba_cache_mode="all", torch.compile sequence parallel, AsyncTP compile pass, a batch of old deprecated APIs and LoRA Tensorizer; Responses API streaming events renamed; the Rust frontend qwen3_xml now parses Qwen3-Coder XML (JSON uses qwen3_json).
3. **Common mainline**: PD disaggregation pushed to production grade synchronously (vLLM NIXL V2 cross-layer KV + Mooncake built-in bootstrap; SGLang KVShard), speculative decoding (MTP / EAGLE / DFlash) + low-latency kernel fusion.

**Actionable conclusion**: if you run an existing vLLM deployment → before bumping to 0.33.0, reconcile the breaking-change list first (especially max_tokens semantics and the Python version); don't close the ticket the moment the version number hits 0.33.0. New installs are more memory-efficient by default (shared-memory tensor arena, GLM-5.x SM100 defaults to FP8 KV) but behavior drift needs watching.

> Worth saying separately: this confirms a hard rule — a version number's "stable" is not the same as "zero cost for you." When max_tokens flips from "reserved window" to "output cap," your billing / truncation logic may silently change after the upgrade; when Python 3.10 is dropped, your old image may simply fail to boot. Your upgrade checklist must carry a line that reads "reconcile breaking changes item by item," not a ticket you close at version 0.33.0.

## 2. vLLM & SGLang Community Tracking

**Version status**: **vLLM v0.33.0 (11-02) is promoted to latest stable, no new tag**; **SGLang v0.5.23 (11-02 release / 10-30 tag) is still the latest, no v0.5.24**; the Step series has no new weights / releases within the window. After release, both mainlines turned toward "engineering hardening + pushing PD disaggregation to production."

### vLLM v0.33.0 (post-promotion mainline)

**Breaking changes (deployment must-read)**:

- **Python 3.10 no longer supported** (floor 3.11, up to 3.14) — old images may simply fail to boot.
- **Dependency floor raised**: transformers≥5.16.1, tokenizers≥0.23.2.
- **`max_tokens` semantics inverted**: from "reserved context window" to "output cap" — long prompt + large max_tokens no longer rejected, so **billing / truncation logic must be re-aligned**.
- **Removed**: cascade attention, mamba_cache_mode="all", torch.compile sequence parallel, AsyncTP compile pass, a batch of old deprecated APIs and LoRA Tensorizer support.
- **Renamed / changed**: Responses API streaming events renamed; the Rust frontend qwen3_xml now parses Qwen3-Coder XML (JSON uses qwen3_json).

**New default behavior (cheaper and faster, but drift needs watching)**:

- Shared-memory tensor arena on by default.
- GLM-5.x on SM100 with `--kv-cache-dtype auto` defaults to FP8; ROCm defaults to MRV2; SM90 prefers the Humming kernel over Marlin.

**New features / performance (quantization-kernel breadth)**:

- **AlphaMoE NVFP4 MoE fused batch kernel** (2-stage output buffer + 256B L2 promotion, up kernel preloads top-k): per PR, on GB300 / B200 NVFP4 MoE peaks at about **1.133×**, W8A8 MoE about **1.078×**.
- Added unquantized / MXFP4 / WNA16 / scaled_mm / FP8 MoE kernels, ARM KleidiAI INT4, NVFP4 / FP8 on Turing, and TP>4 FP4 GEMM → **low-precision MoE speeds up and costs less across broader hardware (NVIDIA / AMD / Intel / ARM / IBM Z)**.

**PD disaggregation improvements (deployable + observable)**:

- Mooncake connector refactored with a bootstrap server (#31034); NIXL Connector V2 cross-layer KV cache layout (#33339); KV offloading connector metrics (#27942); P / D disaggregation with labeled prompt-token metrics (#33290) → large-scale disaggregated deployment is easier to land and more observable.

### SGLang v0.5.23

**No new release, conclusions from 11-02 held**: DeepSeek-V4.1 performance + low-latency megakernel / monokernel + Paged Experts + TPU7x + quantized MoE LoRA + HiCache L3 + KVShard / PD enhancement.

**Standing conclusion**: PD disaggregation needs KV integrity checks (`--disaggregation-enable-kv-checksum` / `--kv-canary`); DeepSeek-V4.1 defaults to MegaAttention under PD and requires prefill and decode to **upgrade simultaneously** (KV-layout handshake), and decoder **SWA bounded replay is on by default** (numerics not fully identical to complete prefill; disable with `--no-enable-decoder-swa-bounded-replay`).

### Step Series (no new weights within window)

- SGLang v0.5.23 has listed **Step 5 Preview** under its "preview models" support list; the official README gives a vLLM / SGLang / Transformers production deployment matrix (FP8 single H200 8-card DP2×TP4 EP8, BF16 dual H200 16-card, etc.).
- **Measurement reference**: OpenZeka measured Step 5 Preview (DGX B300 FP8, vLLM TP4, MTP k=3) at **145.1 tok/s** single-request, TTFT **51ms**, estimated capacity **512 (chat) / 141 (agentic)**; Artificial Analysis intelligence index **43.7**.

### Under the Hood: PD Disaggregation Pushed to Production Grade in Both Frameworks

The most worthwhile technical through-line of the day — both frameworks pushed disaggregated deployment from "runs" to "production-ready" on the same day.

- **vLLM NIXL Connector V2 "cross-layer KV cache layout"**: multi-layer KV contiguous layout, fewer transfer descriptors, higher RDMA effective bandwidth; the Mooncake connector ships a **built-in bootstrap server**, removing external bootstrap and lowering connection-establishment failures.
- **SGLang v0.5.23 KVShard**: MTP KV sharding + 0SM KV Cache Allgather + host-free PD transfer, with prebuilt decode-batch inputs copied straight to GPU.
- **Shared mechanism**: both "reduce KV-transfer metadata overhead + cut CPU involvement" → directly raise effective throughput of disaggregated deployment and lower TTFT.

### Standing Topics

**PD disaggregation**: vLLM v0.33.0 lands the Mooncake refactor (#31034) + NIXL V2 cross-layer KV (#33339) + P / D labeled metrics (#33290); SGLang v0.5.23 advances with KVShard (MTP KV sharding / 0SM Allgather / host-free sync) + per-GPU UCX device selection + Mooncake default failed-session probe. Quant gains: SGLang CP QSA (CP4 8K prefill latency -26.5%), KVShard 0SM Allgather.

**Architecture evolution**: vLLM low-precision MoE kernels (NVFP4 / W8A8 fused batch ~1.13× / 1.08×, FP8 block quant, ModelOpt MXFP8, NVFP4 / FP8 on Turing); SGLang low-latency megakernel / monokernel (DeepSeek-V4.1-Flash single-user decode GB300 +44% / MI350X +75%), FlashAttention draft-extend CUDA graph capture (bs1 single-layer MoE drafter ~1.5× decode throughput), Breakable CUDA Graph (V4.1 GB300 TP4 8K prefill +33%, +DP attention +37% / +50%), DFlash / DFlash2 CUDA attention DP, deterministic seeded rejection sampling.

**Pure PyTorch vs transformers**: TensorRT-LLM switched to a PyTorch default backend from v1.0.0 (2025-09-24) and removed the TensorRT backend from v1.3.0rc20 (2026-06-30), so PyTorch is now the only execution backend; Step 5 Preview ships a standalone Transformers implementation (inference / model.py + vision_encoder.py + kernel.py with Triton / CUDA ops), i.e., the model vendor's own PyTorch inference stack. Motivation: more controllable ops, lower overhead, easier custom attention / sampling, fewer dependencies and version coupling; cost: must self-implement tokenizer / model loading / parallelism. Conclusion: production uses a framework with transformers as the bridge; research / teaching / extreme control use a pure-PyTorch in-house kernel.

**Step adaptation**: SGLang v0.5.23 lists Step 5 Preview in preview support; Step 5 Preview and Step 3.7 Flash both have official vLLM / SGLang deployment guides with dedicated stepfun / step3p5 reasoning / tool-call parsers and MTP / EAGLE speculative decoding, both relying on `--trust-remote-code`; Step 3.7 Flash is near first-class, Step 5 Preview entered the SGLang official list via v0.5.23; the domestic-hardware Day-0 matrix (Ascend / MetaX / Biren / Moore Threads / Hygon) continues.

## 3. AI Papers & Industry Hotspots (Sources Present This Issue)

### Core Paper

**GR-2** (ByteDance Research, arXiv:2410.06158, 2024-10) — video-generation pretraining → VLA joint fine-tuning, the flagship of ByteDance's route. Stage1 runs "text + current frame → autoregressively predict future VQGAN frame tokens" over **38M videos (50B+ tokens)**; Stage2 simultaneously predicts future frames and cVAE action trajectories over about **5,000 trajectories**, with video prediction kept as an auxiliary task = physical-consistency grounding. Impact: together with the RT family (VLM pretraining) and the π0 family (flow-matching action expert) it forms three VLA routes; **105 tasks at 97.7%**, few-shot 50 trajectories / task at **73.9%**, bin-picking **79.0% vs GR-1 33.3%**, CALVIN **85.9%**; ByteDance Seed GR-3 continues.

### Operator Explainers

**InfoNCE contrastive loss** (Oord 2018, arXiv:1807.03748) | positioning: turn "pull positive pairs, push negative pairs" into a batch-in softmax classification. In-use models: CLIP (τ learnable, init 0.07, logit scale clipped at 100), SigLIP (sigmoid variant), Qwen3-VL SigLIP2, OpenVLA / Flamingo vision-alignment front-end. Key points: the batch forms mutually negative samples (CLIP 32768 batch → **32,767 free negatives**); small batches use a MoCo queue; don't hand-tune τ to a dead value; embodied tie-in = VLA vision tower / edge small-vision-tower distillation foundation.

### Performance Optimization

**vLLM V1 unified scheduler** (2025-01 alpha) | positioning: merge prefill + decode into a single queue to fix the mixed-load problem where prefill starves decode; chunked prefill + zero-overhead prefix cache on by default. Representative work: vLLM V1 alpha (FA-3, disaggregated prefill); combined with DeepSeek V4-Flash PD disaggregation + DSpark it forms the "scheduler layer + algorithm layer" benchmark. Gains: long prompts no longer block generation sessions; multi-robot scenarios get free prefix-cache hits, keeping control instructions at a high-priority **10Hz VLA control flow**.
