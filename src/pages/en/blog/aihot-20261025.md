## ★ Most Worth Your Attention Today

**Both frameworks caught up to DeepInfer within a week using the same-source kernel — the open-source inference-engine "same-frame race" has closed its async gap.**

Three lines of fact, one positive and two concrete: the speed catch-up, the latency plugin, and the correctness fix.

Three layers of fact:

1. **Speed catch-up**: vLLM matched DeepInfer on the SemiAnalysis AgentX benchmark, hitting **954K tok/s/GPU** on GB300 NVL72 via **P/D disaggregation + Wide-EP** (**7.9×** per node); the DEP32 config alone already approaches DeepInfer's EP64DP64 decode curve. With Mega kernels + SWA Bounded Replay + Engram, SGLang reaches **1.04×** DeepInfer prefill on 4×GB300/B300 and **+7.4%** decode on 64×GB300 — filling in the production components DeepInfer lacks.
2. **Low-latency plugin**: SGLang shipped its **Low-Latency Mode plugin architecture** (sgl-nvidia-mega / sgl-amd-mono); DeepSeek-V4.1-Flash decode-layer latency drops **96.8 → 68.4 µs (-29.3%)**, single-user GB300 **671 → 928 tok/s (1.38×)**, AMD MI355X **332 → 516 tok/s (1.56×)**.
3. **Correctness fix (actionable)**: vLLM **#60174** fixes a high-integrity-risk **output-corruption** bug in v0.30/v0.31 under DFlash2/DSpark + prefix-cache hits; it is merged into v0.32.0. For V4.1-Flash speculative decoding + prefix cache, **upgrade to v0.32.0+**.

> My read: only a week passed after DeepInfer went open-source, and both community engines pulled it back into the same frame with the same-source kernel — which means DeepSeek has also handed over the "production-grade serving stack" moat. What still differs is the KV / PD / load-balancing engineering layer, and that is exactly where vLLM / SGLang fill in. Conclusion: **don't treat DeepInfer as the only answer; the open-source pair now gets the same-tier curve at day-0 with light tuning.**

### Under the Hood: How SGLang's Low-Latency Mode Uses PDL to Kill Kernel Switching

The most worthwhile technical read of the day.

**Core approach**: SGLang's Low-Latency Mode uses **PDL (Programmatic Dependent Launch)** to make dependent kernels ready early and routes the epilogue to the peer GPU directly via **NVLink multicast**; on the AMD side it **collapses the decode layer into 2 persistent kernels** and **folds all-reduce into the kernel**, eliminating small-kernel switching and sync stalls.

This is a directly reusable pattern for OpenInfer / DFlash / DSpark low-concurrency deployments — the bottleneck is not how fast a single kernel is, but **how many kernel launches and cross-GPU syncs** you pay:

- **Net effect**: decode-layer median latency **-29.3%**, single-user decode on 1M context **43.5 → 61.1 tok/s**.
- **Takeaway**: low-concurrency interactive workloads (agents, single-user long context) are often dominated by accumulated "launch + sync" overhead, not compute itself. Persistent kernels + dependent launch are a more direct lever than squeezing single kernels further.

## 3. AI Papers & Industry Hotspot

### Today's Highlight

**TacitVLA uses a single attention-mask cell to prove "a thinking robot need not think out loud"** — the reasoning benefit is internalized into the representation; four benchmarks match explicit reasoning in success rate while cutting latency by up to **3.4×**, hitting straight at the embodied-AI second-half pain point of being "smart and fast" at production scale.

### Paper Core: TacitVLA (arXiv:2610.17540, NVIDIA / UIUC et al.)

- **Core idea**: the explicit-reasoning benefit comes from the **backbone representation shaped by training supervision**, not from the text being read by the action expert; a **shared training sequence + a single −∞ mask cell** is a clean controlled experiment.
- **Mechanism**: MoT backbone + flow-matching action expert; for non-memory tasks it **skips text generation** during reasoning, for memory tasks it **writes the ledger asynchronously**; RoboMME **82.7%** / RMBench **77.5%** set new records, **+17.1%** over no-reasoning.
- **Impact**: slow thinking and high-frequency control coexist; together with Shallow-π / RTC / speculative decoding it forms the **on-device VLA latency-reduction puzzle**.

### Operator Deep-Dive: Think Token Masking

`M[i,j] = −∞` if `j ∈ r_t`; the action expert's attention to the current-step reasoning token is 0, while **reasoning gradients still flow through the backbone (supervision kept, conditioning cut)**. In use: TacitVLA; same lineage as LLM implicit CoT (Coconut / pause token). Key point: **zero-parameter, zero-overhead**; pitfall = historical ledgers must not be blanket-masked.

### Performance Optimization: Reasoning-Supervision Distillation (Latent CoT)

Reasoning acts as an auxiliary task shaping the representation (`G = ∇L_task + λ∇L_reason`), with the action not conditioned on text. Representatives: TacitVLA **3.4×**; Shallow-π **364 → 110 ms**. Payoff: **zero latency + full reasoning benefit**.
