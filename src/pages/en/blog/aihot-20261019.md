## ★ Most Worth Your Attention Today

**vLLM's high-concurrency "token swallowing": output doesn't error out, it silently gets dumber.**

This is the same class of "outright destroy your production output" item as the NVFP4 endless-repetition bug from 09-01 — except this one hides behind a healthy throughput curve. Three layers of fact:

1. **Symptom**: under multi-node multi-GPU high concurrency, the model runner's state-update path silently drops tokens; the same model produces lower-quality output ("lower IQ") under load rather than throwing an error or merely losing throughput. Root cause: `_update_states` in `gpu_model_runner.py` tracks concurrent request state incompletely.
2. **Fix**: Paradigm's PR **#41133** is merged to main; it ships in the next release. Nightly is testable but not recommended for production.
3. **Consequence**: this is not a "throughput benchmark looks good so we're fine" bug — it only surfaces under concurrency stress, invisible at single-request load.

**Actionable conclusion**: before going live on any high-concurrency deployment (especially 1P1D / multi-node multi-GPU), beyond tokens/s, run an accuracy pass with **lm_eval or similar**. Don't trust the throughput curve alone.

> Worth saying separately: like the 09-01 NVFP4 bug where "the fix was in main but the release channel was pinned," this kind of **silent correctness degradation is more dangerous than a crash** — a crash you notice immediately, a drop in IQ you blame on the model. It is another reminder that your dependency management needs an emergency path for building from main / validating on nightly.

### Under the Hood: vLLM's High-Concurrency "Token-Swallowing" Correctness Bug (PR #41133)

The most worthwhile technical read of the day — it is not about throughput, it is about correctness.

**Symptom**: under extreme concurrency, the model runner's state-update path **silently discards some tokens**. No error, no OOM — the output just gets "dumber." The same prompt answers correctly at low concurrency and wrong at high concurrency.

**Root cause**: `_update_states` in `gpu_model_runner.py` tracks **concurrent request state incompletely**, missing the bookkeeping for some tokens during the multi-node multi-GPU high-concurrency state update.

**Fix**: Paradigm's PR #41133 is merged to main; it ships in the next release. Nightly is testable but not recommended for production.

**Landing advice**: beyond throughput benchmarks, **pressure-test accuracy with lm_eval** in any high-concurrency scenario. Watching tokens/s alone completely misses this bug — it only appears when concurrency is maxed out.
