2. **Architecture evolution (lossy spec verifier into mainline)**: **FLy #53987 merged (10-19)** — standard rejection sampling demands strict distribution match (lossless); FLy relaxes it: where the target's top-3 entropy ≥0.3 (uncertain) and the following W draft tokens pass normal verification, it tolerates one isolated rejected draft token for higher acceptance / throughput; **plus a fix for the MTP + thinking_token_budget hang #58231** (reasoning model + speculation + top_p<1 keeps emitting token 0, ~3× throughput drop — must upgrade for such deployments).
3. **Paper signal**: **EvoVLA (Peking Univ. Tang Hao group, arXiv:2511.16166) uses Gemini 2.5 Pro to split 74 stages + generate hard-negative triplets for contrastive learning, cutting long-horizon "stage-hallucination" (faking completion to fool the VLA evaluator) from 38.5% to 14.8%**, real-robot success 54.6% (+11pp), joining FD-VLA/SVA/StableVLA/GeoVLA as the VLA-reliability quintet.

**Actionable conclusion**: keep production locked on **v0.32.0 (vLLM) / v0.5.22 (SGLang)**, but two deployment classes must upgrade — anything running reasoning + speculation + top_p<1 should move to a build containing #58231; before enabling FLy by default, confirm eval / alignment evals are off (worst fidelity ~96.3%). On the SGLang side, kill the Dumper endpoint first. EvoVLA's "LLM-as-Teacher error-set feeds RL" paradigm transfers to this author's vehicle/embodied VLA line.

> Worth emphasizing: FLy pulls "lossy speculative verification" — previously a DFlash/DSpark block-level / adaptive-verification track — formally into vLLM's mainline, on the same line as this author's OpenInfer/Qwen3-4B DSpark. Its cost is that the distribution is no longer strictly faithful (worst fidelity ~96.3%), so **eval and alignment evals must turn FLy off**; the production throughput dividend (up to +31%) is only eaten where "distribution slack is acceptable".

### Under the Hood: FLy (Faithful-yet-Lossy, #53987) — "give way where the target is uncertain" lossy spec verification

- **Approach**: standard rejection sampling demands strict distribution match between draft and target (lossless); FLy relaxes it — when the target is uncertain at a given token (top-3 entropy ≥0.3) and the following W draft tokens all pass normal verification, it tolerates **that one** isolated rejected draft token.
- **Benefit**: higher draft acceptance → higher decode throughput, measured AMD 1.055–1.310×, NVIDIA 1.041–1.273× (up to +31%); the cost is the distribution is no longer strictly faithful, **worst fidelity ~96.3%**, so **eval and alignment evals must disable FLy**.
- **Positioning**: same **block-level / adaptive verification** track as OpenInfer/DFlash/DSpark, a reference paradigm for this author's Qwen3-4B verifier — "where to give way, and how much" is a tunable knob, not a one-size-fits-all lossless cut.

> My read: this round's version numbers are stable (v0.32.0 / v0.5.22); increments concentrate on four lines — "lossy spec verifier into mainline (#53987) + MTP thinking-budget fix (#58231) + RL zero-disk weights (#62267) + PD bidirectional KV". FLy makes "distribution slack for throughput" a default option — the right engineering trade, but **the fidelity floor must be held by the eval switch**. SGLang has no new version this round; CVE-2026-111391 unpatched is a security debt hanging overhead, and disabling Dumper is the only present remedy.

### Paper Core (EvoVLA · arXiv:2511.16166)

- **One-line positioning**: **cure long-horizon "stage-hallucination"** — the model fakes completing a stage to fool the VLA evaluator (e.g. reports "grabbed" while not actually gripped), the most hidden reliability gap before deployment.
- **Approach**: ① **SAR stage-alignment reward**: Gemini 2.5 Pro splits 74 stages + generates **hard-negative triplets** (true-done / fake-done / boundary) for contrastive learning + temporal smoothing; ② **POE pose exploration**: curiosity anchors the gripper-object **relative pose** rather than pixels; ③ **long-horizon memory**: Top-K retrieval + gated fusion.
- **Result / impact**: Discoverse-L 69.2% (+10.2pp), hallucination 38.5→14.8, sample efficiency 1.5×, real-robot 54.6% (+11pp); the "LLM-as-Teacher error-set feeds RL" paradigm — isomorphic to this author's vehicle/embodied VLA line, wire "hard-negative generation" into the training loop first.

### Operator Deep-Dive: FSQ (Finite Scalar Quantization, ICLR 2024)

- **Positioning**: per-dimension level round + mixed-radix indexing + straight-through gradient, **zero codebook, zero auxiliary loss** curing VQ-VAE codebook collapse.
- **Key point**: MAGVIT-v2 / VideoPoet tokenizer candidate, VLA action discretization (FAST family) base; pitfall = levels around [8,6,5], use FSQ for low-dim, LFQ for high-dim.

### Performance Optimization: KV Cache Tiered Offload

- **Positioning**: hot HBM / warm DRAM / cold NVMe + blockized async prefetch; represented by Mooncake / LMCache / SGLang tiered cache.
- **Benefit**: long-prefix hit cuts TTFT 5~10×, concurrency multiplies; divides labor with KV cascade recall (**what to read vs where to put**); embodied meaning = cost-down base for multi-robot concurrent inference.
