## ★ Most Worth Your Attention Today

**Low-precision KV officially moved from "a one-off trick" to "structural cost-down" this week, while a CVSS 9.2 unpatched RCE still hangs over SGLang v0.5.22.**

Two threads, one positive, one negative:

1. **Positive: low-precision KV goes dual-line.** vLLM `main` added a **native Octave KV (`ROCM_OCTAVE`) 3-bit backend** (10-26), extending low-precision KV from NVIDIA **NVFP4 4-bit** all the way to **AMD 3-bit**. For the first time, both major GPU camps have an official path to "compress KV to 4, even 3 bits" for long-context / high-concurrency — structurally lowering the VRAM bill for long-context deployment.
2. **Negative: the SGLang RCE still isn't in release.** **CVE-2026-111391** (Dumper `eval` injection → RCE, CVSS **9.2**) has a community PR **#44205** (replacing `eval` with an AST whitelist evaluator), but it **landed only in `main`, not in release**; **v0.5.22 is still affected**.

**Actionable conclusions**:

- If you run SGLang, immediately **`unset DUMPER_SERVER_PORT`** and **block the `/dumper/configure` endpoint** — that is the only mitigation available on v0.5.22; the fix waits for the next tag or a build from `main`.
- For long-context AMD deployments, you can start evaluating Octave 3-bit KV — but the **calibration flow must be standard** (see the deep-dive); get it wrong and the model collapses.

> This is the same class of problem as September's NVFP4 bug where "the fix is in main but the release channel is pinned": **"the fix exists, but release can't reach it."** Your dependency strategy must include an **emergency path to build from main** — this time it isn't repeated output, it's an RCE, an order of magnitude more severe.

### Under the Hood: Low-Precision KV Cache (NVFP4 4-bit / Octave 3-bit)

The most worthwhile technical thread of the day.

**How**: via **`vo_split` head splitting** + **per-layer `amax / 6.0` calibration** + **llm-compressor / compressed-tensors storage**, compressing each KV value from **2 bytes down to 4, even 3 bits**.

**How real the gains are**: MiniMax **M3.1** measured **−43.75% KV per token**, and **4×B300 @ 256K** concurrency went **28 → 76 (~2.7×)**. The long-context VRAM bill drops by nearly half, and the high-concurrency ceiling rises nearly 3×.

**The cost is equally clear**: calibrate right and it is **near lossless**; calibrate wrong and the **model collapses**. This is not "tweak a parameter" — it is hard engineering that **must follow a standard calibration flow plus accuracy regression**.

> My read: low-precision KV is moving from "a few people's black magic" to "a default option both camps endorse." Once it is on by default, the economics of long-context inference change — but only if your calibration pipeline earns that trust. If nobody on your team owns KV-quantization accuracy regression yet, now is the time to name someone.

### Paper Core: SmolVLA

**SmolVLA** (Hugging Face / Sorbonne / valeo.ai, arXiv:2506.01844, 2025-06, open-source) — a 0.45B "civilian VLA": **SmolVLM-2** backbone + ~100M flow-matching action expert.

- **Layer truncation**: the action expert reads only the VLM's first **16 / 32 layers** (78.5 vs 80.3, truncation beats skip-layer).
- **64 visual tokens / frame** + CA / causal-SA alternating action expert (**85.5 vs pure CA 79.0**).
- **Full community data**: 481 episodes / 22.9k trajectories / 10.6M frames (SO-100 / 101).
- **Async inference**: 9.7s vs 13.75s (**+29.5%**), 19 vs 9 runs in 60s (**~2.1×**).
- **Impact**: the LeRobot community route becomes the de-facto open-source embodied standard; lightweight edge VLA = a key cost-down lever for the robot brain.

### Operator Explainee: Logit Soft-Capping (Gemma 2)

**tanh soft truncation** caps the logits upper bound (attention **50** / output **30**); gradient `sech² ≤ 1` is smooth, and **BF16 avoids FP32 upcast**. Gemma 3 dropped it for **QK-Norm**; the sibling technique is **QK-Clip** (MuonClip τ=100). Embodied relevance: a **zero-cost stabilizer** for edge BF16 fine-tuning of VLA.

### Performance Optimization: GPTQ / AWQ Weight-Only Quantization

**From the algorithm-kernel angle** — GPTQ **Hessian error compensation** (175B ~4 GPU-hours) / AWQ **1% salient-channel scaling**; **Marlin W4A16** decode **3.87×~5.7×**. Embodied relevance: 0.45B~3B VLA quantized onto **Jetson**, forming an edge trio with **Helix dual-system / TeaCache**.
