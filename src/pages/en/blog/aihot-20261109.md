## ★ Most Worth Your Attention Today

**Shrike and NanoInfer in the same frame: in-house inference stacks are going from slideware to usable engineering.**

Both frameworks hold their 11-02 stable closes over the last 72 hours (vLLM v0.33.0 / SGLang v0.5.23), with no new release; the main line is Summit warm-up plus main-branch hardening. What actually matters is **two "framework-free" in-house stacks surfacing at once**:

1. **Shrike (pure PyTorch)**: zero-dependency MHA / RoPE / SwiGLU, PagedAttention (16-token fixed block), continuous batching, speculative decoding, OpenAI-compatible API; attention uses torch.compile to hand-write the non-contiguous KV kernel, and multi-sequence KV is copy-on-write shared to save VRAM.
2. **NanoInfer (pure CUDA)**: no PyTorch, no TensorRT — hand-written CUDA kernels run GPT-2 INT8 on A100 at **1180 tok/s, 0.85 ms/token (roughly TensorRT FP16)**.

**Actionable conclusion**: both lines confirm that "leave transformers, maximize control" has gone from concept to usable engineering — production uses vLLM / SGLang + transformers as the format bridge, research / extreme optimization uses pure-PyTorch / pure-CUDA in-house kernels.

> Worth saying separately: another day of "**capability is on main, stable line lags**." Kimi K3.1 Pro's official recipe needs vLLM 0.34.0+, but the stable line is still 0.33.0 — self-host teams must keep an emergency path for pulling hotfixes / new capability from main, or they'll either sit on an old version or get quietly burned by "runs but misaligned" training quality.

### Under the Hood: Shrike Turns PagedAttention Into a 16-Token Fixed Block

The most worthwhile technical read of the day.

Shrike's PagedAttention implementation:

- **16-token fixed blocks**, with a block allocator handling free / reclaim / sharing;
- **attention hand-written with torch.compile as a non-contiguous KV kernel**, bypassing the framework's fusion limits;
- **multi-sequence KV copy-on-write shared** to save VRAM.

Motivation = readability + customizable attention / sampling + decoupling from dependencies; the cost = you must implement tokenizer / model loading / parallelism yourself.

> My read: the division of labor "production framework + transformers bridge vs research pure-PyTorch / CUDA" is hardening. It does not replace production frameworks, but it gives teams that "want to change attention, squeeze sampling, or drop version coupling" a clean path — the cost is you own the tokenizer / parallelism. NanoInfer pushes that path to the extreme of "no PyTorch either."

## 3. AI Papers & Industry Hotspots

### Paper Core · BLIP-2: The Learnable-Query Bridging Paradigm

**Salesforce, ICML 2023, arXiv:2301.12597**

- One-liner: a lightweight Q-Former bridges frozen unimodal giants — train only the translator, not the giants — with **54× fewer** params than Flamingo-80B and **8.7% higher** zero-shot VQAv2.
- Core idea: ① 32 learnable queries cross-attn to the frozen ViT to pull information → a fixed 32-token visual summary (information bottleneck); ② two stages = ITC / ITM / ITG three-loss representation learning (same weights, different attention masks) → OPT / FlanT5 generation learning (ITG continues training); ③ removing the bridge drops VQA sharply — the bridge is indispensable.
- Impact: direct ancestor of InstructBLIP / MiniGPT-4 / mPLUG-Owl; EmbodiedGPT's 580-query variant enters embodied AI; lesson = the bottleneck is lossy → Qwen-VL switched to the full-token route; the ideological source of on-device VLA visual compression.

### Operator Note · SigLIP 2 Four-Way Loss

**arXiv:2502.14786**: the vision tower gains alignment / generation / localization at once; in-use model = the Qwen3-VL vision-tower base; key points = L_cap generative semantics + L_loc self-distilled masked prediction + L_dbg online debiasing (negative-sample gradient decay), with distillation requiring stop-gradient.

### Performance Optimization · CacheGen

**SIGCOMM 2024, arXiv:2310.07240**: targets the KV-cache cross-machine transfer bandwidth / latency bottleneck; flagship work = UChicago, stacking with H2O / LLMLingua for another **3.3~4.2x** bandwidth saving; gains = KV **3.5~4.3x** compression, total latency **3.2~3.7x**, and **1.67~1.81x** faster than 8-bit quantization.
