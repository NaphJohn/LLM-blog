## ★ Most Worth Your Attention Today

**vLLM v0.34.0 stable has landed — extensible KV cache is on by default and Model Runner V1 is gone. It is the only stable release from either framework this week, but the words "on by default" bring both a throughput windfall and a migration you now have to do.**

This is the one item today that lets you decide immediately whether to go to production. The trouble is not the version number — it is that three memory- and startup-related things changed at once.

Three layers of fact:

1. **Landed**: v0.34.0 shipped at 23:22 UTC on 11-16, **1061 commits / 412 contributors**; **extensible KV cache on by default** (#56492), **Model Runner V2 exclusive**; **10 new models** (Mistral Large 4, MiniMax-M3.1-Flash, Nemotron-3.5-Transcribe, and more), and **Kimi K3.1 Pro promoted to stable** — K3.1 Pro can finally leave nightly and use the official image.
2. **The windfall**: on H200, MiniMax-M3's KV cache goes **433k → 672k tokens**; **Step5 NVFP4 MoE hits up to 1.95x decode on 4xGB200** (#65152), **GLM-5.3-Flash 1.6x throughput** (#60895), and **TTFT 1.24–1.40x** (#63956).
3. **The cost**: this is no free lunch — a bigger cache pushes the working set past the L2 / bandwidth comfort zone, so **TPOT rises 6–18% at concurrency 128**; meanwhile **Model Runner V1 has been removed** (#63373), and **custom V1 logits processors must be migrated or startup will fail**.

**Actionable conclusion**: throughput-oriented batch workloads should take the default-on win directly; single-stream low-latency workloads need A/B testing, with `--no-enable-extensible-kv-cache` or `--gpu-memory-utilization 0.9` as fallbacks. Before upgrading, audit whether you have any custom V1 logits processor.

> Worth saying separately: **SGLang's v1.0 has been announced for a week while its tag is still v0.5.23** (11-02, 1007 PRs / 257 contributors), with notes unpublished and CVE-2026-111391 unpatched. In the same week vLLM pushed stable forward a big step while SGLang stayed at "announced, not tagged" — **who is delivering on a release cadence and who is still at the announcement stage is spelled out plainly by today's timeline.**

### Under the Hood: Extensible KV Cache's "Capacity for Latency"

The most worthwhile technical read of the day.

**The mechanism** (#56492): KV memory moves from "estimated by `gpu_memory_utilization` before startup" to "**sized from actual free memory read after warmup + CUDA graph capture**". On H200, MiniMax-M3 therefore goes **433k → 672k tokens**.

The essence is **capacity traded for latency**: a bigger cache makes the working set more likely to spill past the L2 / bandwidth comfort zone, hence **TPOT +6–18% at concurrency 128**.

> My read: the right way to use this is to fork by workload shape — **default-on pays off most for throughput-oriented batch jobs; single-stream low-latency workloads must A/B it**. It turns "how much memory to reserve" from a human guess into a runtime measurement, but the price is trading some determinism for tail-latency variance. Do not treat it as a free, no-brainer speedup.

**PyTorch vs transformers**: **no new "off transformers, in-house stack" PR this week**; vLLM takes **Gemma / StableLM back into the Transformers backend** (dependency tightened to hf_hub>=2.0.0), while SGLang goes the other way with a **Rust critical path + CUDA megakernel** to bypass Python overhead. Conclusion = **for coverage choose the transformers bridge; for extreme low latency choose the in-house kernel**.

## 3. AI Papers + Industry Hotspots

**Today in one line**: BLIP-3's "remove the Q-Former + unified autoregression" architectural subtraction proves the winning factor in multimodality is data, not the bridge — and the same idea is seeping into embodied intelligence along the VLA backbone-lightweighting route; on the industry side, Huawei Cloud open-sources a world model and JD's Double-11 humanoid sales rise 700%, giving a volume reference.

### Paper Core

**BLIP-3 / xGen-MM** (Salesforce, arXiv:2408.08872, 2024-08) | an open-source 4B-class multimodal base family, closing the BLIP trilogy (BLIP-2 → InstructBLIP → BLIP-3). Three subtractions plus one addition: ① **Q-Former (188M / ITC+ITM+ITG triple loss) → Perceiver Resampler** (128 tok per view, arbitrary resolution with ≤12 patch concatenation, budget 128x(1+n)<=1664); ② **a unified autoregressive loss at every stage**, `L=-sum log p(x_t|x<t,V)`, with visual tokens fed into the sequence directly as special tokens, SigLIP frozen + phi3-mini 3.8B; ③ **data engineering fills the gap** — MINT-1T 32.5% / KALE 25% / OCR-200M 5% / GROUNDING-50M 5% / OBELICS 17.5%, in four stages 100B tok → HD 30B → SFT 3M → DPO safety version. Impact: **"lighten the backbone, weight the data" leads straight into the VLA lightweighting route of pi0 / pi0.5 / SmolVLA**; interleaved image-text input is the prototype for robot multi-view + instruction + history frames.

### Operator Explained

**The ITM head** (Image-Text Matching) | a binary image-text matching classification head, `s = w^T·h(img,text) + BCE`, mining hard negatives with ITC similarity; two-stage retrieval = **ITC coarse ranking → ITM fine ranking** | in use: **BLIP-1/2, ALBEF, InstructBLIP**; **dropped in BLIP-3 / CLIP / SigLIP**, with the idea surviving as reranker / hallucination-filter heads | key point: nearly all the gain comes from hard-negative quality; the discriminative/generative head gradient conflict is exactly BLIP-3's motivation for subtraction; embodied link = **a VLA instruction-execution verifier**.

### Performance Optimization

**Multimodal embedding caching** | an image is a pure function, so encoder outputs are cached by content hash; a hit skips the compute-bound ViT forward (~**8 MB per image** bf16 @1024x4096); stacking visual-token prefix KV reuse saves prefill too | representative work: **SGLang `--enable-mm-global-cache`** (the EPD encoder stage is a natural cache point) and vLLM multimodal prefix caching | payoff: TTFT drops sharply in the high-frequency pattern where the image stays fixed and the question changes, and it is orthogonal to PD / EPD / prefix caching.
