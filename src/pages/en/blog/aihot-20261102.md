## ★ Most Worth Your Attention Today

**SGLang × Cloudflare co-disclosed a real cross-request KV cache leak under PD disaggregation — not a PoC, but a real incident where 155 responses leaked someone else's KV. And that CVSS 9.2 Dumper RCE is still not closed.**

This is the only item today that will **literally hand another request someone else's session KV**, and — like the September and October cases — the danger is not the bug itself, it is the **reachability of the fix**.

Four layers of fact:

1. **The incident**: Cloudflare's context window is **1,048,576 tokens**, but the prefill KV pool is only **681,280**. In PD mode, SGLang's admission check only looks at `finished()`, not `rejected` — so a rejected request was still wrongly admitted. The prefill computed a **1-token placeholder** and flagged "transfer complete", while the decode read the full reserved 8 pages, of which **1–7 pages held another request's KV**. Incident window **08-27 → 09-09**, **155 responses affected**.
2. **The fix**: SGLang **v0.5.23** (10-30 Stable) carries the PD robustness fix **#45973**, plus cross-request KV isolation **#36988 / #38935** (rejected requests terminate before bootstrap / allocation / KV transfer; decode verifies transferred token count == reserved count).
3. **Mitigation (do it now)**: upgrade to **v0.5.22+** and enable **`--disaggregation-enable-kv-checksum`** / **`--kv-canary`** for KV integrity checks + canary probing.
4. **Dangerous companion · Dumper RCE (CVE-2026-111391, CVSS 9.2)**: affects **every installable version 0.5.10–0.5.22**; fix PR **#44205** (AST evaluator replaces `eval()`) is merged to main, but sources disagree on whether it shipped in v0.5.23. Mitigation = `unset DUMPER_SERVER_PORT` + a separate `admin_api_key` + block `/dumper/configure`.

**Actionable conclusion**: if you run **PD disaggregation with a KV transport backend**, request isolation and KV integrity verification are **mandatory**, not optional.

> Worth saying separately: neither framework cut a major feature release this week; the through-line is "**security + stability convergence**." KV cache has gone from "a performance optimization target" to "a first-class security object" — which means your threat model needs a new line: under PD disaggregation, the KV transport channel itself is an attack surface that must be verified, isolated, and audited.

### Under the Hood: Root Cause of the Cross-Request KV Leak Under PD Disaggregation

The most worthwhile engineering post-mortem of the day — it turns "how PD disaggregation leaks" from jargon into a reproducible incident.

**The root-cause chain**:

1. **The pool is too small**: Cloudflare's context is **1,048,576 tokens**, but the prefill KV pool is only **681,280** — by construction some requests can't get a full reservation.
2. **A hole in the admission check**: in PD mode SGLang's admission only looks at `finished()`, not `rejected`. Rejected requests land in `to_finish`, keeping their `finished()` False, so a request that should have been terminated was **wrongly admitted**.
3. **A placeholder fools the transfer**: the prefill computed a **1-token placeholder** and flagged "transfer complete" while sending 1 KV page; the decode read the full reserved **8 pages**, of which **1–7 pages held another request's KV** → leak.

**Two cuts of the fix**: ① rejected requests terminate **before** bootstrap / allocation / KV transfer (#36988/#38935); ② the decode side verifies **transferred token count == reserved count** and rejects on mismatch.

> My read: this root-cause chain is the classic "optimization assumptions meet boundary conditions" — the reservation + placeholder optimization made for more concurrency got amplified by an admission-check hole into a cross-request leak. It confirms again: **in any architecture that shares KV across instances, request isolation and KV integrity verification are not polish, they are the foundation.**

## 3. AI Papers & Industry Hotspot

> Both the papers and industry digests are in today; the core takeaways follow (paper / operator / performance optimization / industry).

### Paper Core: RoboCat (DeepMind, arXiv:2306.11709, 2023-06)

**One-line positioning**: a robot foundation model that "collects its own data" — turning robot learning from **pure supervision** into a **self-improving data flywheel**.

**Core idea**: ① Gato 1.18B multimodal decoder-only, image 16×16 patches + actions discretized into 256 bins, whole-sequence next-token; ② **data flywheel**: 100 demos for a new task fine-tune a derived model → real-robot self-collects **10,000 trajectories** (successes and failures weighted equally) → fed back to retrain the next generation from scratch, **4 generations** total; ③ **unseen-task success rate 36% → 74%** across 4 two-arm robots + an unseen three-finger gripper.

**Impact**: the answer to "**where does the data come from**" for the Gato → RoboCat → RT-2/VLA lineage; common ancestor of the π₀/RECAP/Skild S1/GR00T data pipelines; investing implication = **real-robot data closure is a second moat beyond the robot body itself**.

> This echoes the inference side of today's issue: the engine side is locking KV down as a security object, while the robotics side treats "data closure" as a moat — **both have turned "the loop" into a core asset, one a defensive loop, the other a growth loop.**

### Operator Explain: KTO (Kahneman-Tversky Optimization, ICML 2024 Best Paper)

**Positioning**: turns isolated 👍/👎 binary feedback directly into an alignment loss — **no pairing, no reward model, no sampling**.

**In production**: Zephyr / Tülu 3 / various open alignment pipelines; real-robot logs' success/failure episodes are naturally unpaired, so KTO's shape fits embodied data naturally.

**Key points**: `r_θ = Σ_t log(π_θ/π_ref)`, anchor `z_0 ≈ (1/2)·KL(π_ref‖π_θ)` must be **detached**; asymmetric **λ_U=1.33 > λ_D=1.0** (prospect-theory loss aversion); at a **9:1** positive/negative imbalance it is more stable than DPO.

### Performance Optimization: Preemption & Priority Scheduling (vLLM RECOMPUTE/SWAP + V1 priority + SGLang SLO-aware)

**Positioning**: a scheduling-layer solution for a finite KV block pool + uneven request value.

**Representative work**: vLLM (RECOMPUTE defaults to ≈ 1× prefill recompute), SGLang; **orthogonal and stackable** with Prefix Caching / PD disaggregation.

**Payoff**: controllable high-priority P99 TTFT and higher cluster utilization; **pitfall = preemption storms need admission-control backstop**.
