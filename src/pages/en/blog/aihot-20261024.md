## ★ Most Worth Your Attention Today

**The single most important line this round is DeepSeek open-sourcing the production-grade inference stack DeepInfer on 10-20 — a deep rewrite of vLLM, rather than either framework shipping a release itself; in the same window vLLM holds stable v0.32.0 + RC and SGLang holds v0.5.22 while mainline lands elastic EP hot-scaling.**

Three layers of fact:

1. **DeepInfer open-sourced (headline)**: open-sourced on 10-20, Apache 2.0, essentially a deep rewrite of vLLM with in-house kernels (FlashMLA / DeepGEMM / DeepEP / TileLang) and no dependency on generic transformers. Two public optimizations: ① **SWA Bounded Replay** (YOCO prefill truncation, V4.1 default KEEP_TOKENS=140 — on a cache hit only the retained suffix is recomputed, roughly halving long-context prefill compute); ② **Confidence-Scheduled Verification** (DSpark, draft defaults to 5 tokens + a confidence head schedules the verification window by confidence) — sharing lineage with this author's OpenInfer / DFlash / DSpark block-level / adaptive verification. Cost: it does not ship a KV system / PD / load balancer.
2. **Version and security (one stable, one forward, still no new tag)**: vLLM stable stays v0.32.0 (10-18, 814 commits / 363) + RC v0.32.1rc0 (10-18, only documenting the RL HTTP weight-transfer protocol #62267), no v0.32.1 stable in the window; SGLang stable v0.5.22 (10-19, 950 PRs / 245) remains Latest, no v0.5.23 in the window. Security debt carries over: CVE-2026-111391 (Dumper RCE, 0.5.10–0.5.22, CVSS 8.1) still has no fix → disable Dumper in production.
3. **Correctness fixes pile up (vLLM's three-in-three-days)**: #60613 (merged to main 10-23) fixes **DeepSeek-V4.1 prefill reading a stale sparse index causing FlashMLA's first 127 tokens to go NaN / illegal memory access**; after the fix on 4×GB200 it ran 900s / 13,801 requests continuously — a **must-upgrade** for anyone hitting V4.1's intermittent crashes; #57092 (10-23) fixes batch-invariant not being invariant under online FP8 MoE (per-expert scale stride=0 mis-reads expert 0), so RL rollouts / reproducible evals on FP8 MoE must be re-run; #63165 (10-23) fixes a shared-memory broadcast reader leaking ~23 MiB/h/process (ZMQ CONFLATE unpolled), explaining the slow memory creep on long-running TP / KV-connector deployments.

**Actionable conclusion**: teams running V4.1 should move vLLM to a build containing #60613 (already in main, just wait for RC/stable to cherry-pick); RL rollouts and reproducible evals on FP8 MoE must be re-run per #57092; long-running TP deployments should watch the #63165 memory-leak fix; kill the Dumper endpoint on the SGLang side; and for elastic EP hot-scaling you can go straight to the LMSYS recipe (reusing failure recovery + Mooncake PG + NIXL A2A, H100 / DS-V3-Lite FP8 measured 5.3–8.2× scale-up across a restart).

> Worth emphasizing: no new version number this round, but the signal of "a production stack rolling its own kernels" weighs more than any release — DeepInfer productizes the vLLM-deep-rewrite + in-house-operator path, the same philosophy as this author's DFlash / DSpark block scheduling; the vLLM side presses its increments onto "correctness fixes (V4.1 / FP8 MoE / memory leak) + PD elasticity", while the SGLang side presses onto "elastic EP hot-scaling + DSpark block verification". Both keep closing on "confidence/block adaptive verification + long-context KV trimming".

### Under the Hood: DeepInfer's Two Public Optimizations — writing "read-heavy, write-light" into the inference engine

- **SWA Bounded Replay**: YOCO prefill truncation, V4.1 default KEEP_TOKENS=140 — on a cache hit only the retained suffix is recomputed, roughly halving long-context prefill compute. It sits on the same main axis as vLLM / SGLang's "long-context KV trimming".
- **Confidence-Scheduled Verification**: the DSpark paradigm — draft defaults to 5 tokens + a confidence head schedules the verification window by confidence (DeepSeek-V4-Pro measured accept≈5). Same lineage as this author's OpenInfer / DFlash / DSpark block-level / adaptive verification — the shared answer is "verify by confidence / block, adaptively".
- **Cost**: DeepInfer does not ship a KV system / PD / load balancer; that part still needs a production stack to fill in (vLLM production-stack #669 LMCache + NIXL PD under review).

### Today's Highlight (1 sentence)

### Paper Core (SERA · Self-Evolving Robotic Agent)

- **One-line positioning**: USTC × Shanghai AI Lab × SJTU (arXiv:2610.29560) wraps the high-level VLM planner in an editable harness — maintaining task context within an episode, and across episodes proposing rule revisions via rollout and selecting the best by win-rate, **frozen after selection to prevent cheating**.
- **Core idea (3 lines)**:
  1. the VLA actuator is **frozen end-to-end, zero-gradient training** — leave the low-level action alone, only let "how the upper layer thinks" self-evolve;
  2. across episodes, rule revisions are proposed via rollout and **selected by win-rate** (not by gradient);
  3. frozen after selection, killing the "change the rules mid-match" cheat.
- **Result / impact**: RoboMME **51.38% vs 44.38% (+7pp)**; together with MemoryVLA / EvoVLA it forms the **VLA reliability trilogy**, establishing the "self-evolving planner" paradigm (DSPy thinking ported into robots).

### Operator Deep-Dive: Engram Lookup Memory (DeepSeek V4.1-Flash)

- **Positioning**: a 552B + 196B "external memory" — long-tail knowledge goes into a (k,v) table, ANN retrieval + gated fusion; memory shifts from "paying KV rent every step" to "store once, fetch on demand".
- **Lineage**: the kNN-LM / RETRO family.
- **Embodied mapping**: a robot is an extremely **read-heavy, write-light** workload; Engram ports "lookup memory" to the edge for direct relief.

### Performance Optimization: EPLB Expert Rebalancing (DeepSeek open-source)

- **Positioning**: MoE load imbalance (imbalance = max / mean) → redundant experts + greedy repacking; zero precision loss, **throughput ≈ improves by the imbalance factor**.

- **Embodied mapping**: cloud-brain concurrent inference capacity.
