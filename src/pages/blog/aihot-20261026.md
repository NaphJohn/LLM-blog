## ★ 今日最值得关注

**SGLang 低延迟 megakernel 把 DeepSeek-V4.1-Flash 的解码延迟再压 29%，而 llm-d 1.0 把 PD 分离/KV offload 收口成生产默认。**

这是今天两条最有方向感的线，且指向同一件事：**推理引擎进入"控制面收口 + 内核级微优化"的双轨阶段**。

三层事实：

1. **SGLang Low-Latency**：与 NVIDIA/AMD 共建的 megakernel 插件，把 V4.1-Flash 单用户 P90 tok/s 从 671 推到 928（GB300，**+1.38×**）/ 332→516（MI355X，**+1.56×**），**解码层延迟 96.8→68.4 µs（-29.3%）**。核心不是换算法，而是用 megakernel + 通信/计算重叠压低小 batch 的同步开销。
2. **llm-d 1.0 路由层**：把 PD 分离 + KV offload 收口为"标准引擎前的一层路由"——前缀感知路由 + KV offload 在 Ironwood TPU 上 TTFT **-85%、+2.4×**。
3. **同一天的对照**：vLLM 也沿着"决策端点进引擎"收敛（`/v1/systemone` 在 v0.32 默认开启，被解读为 agentic serving 控制面收口）。

**可执行结论**：想榨干 V4.1-Flash 的解码延迟，现在最短路径是 SGLang Low-Latency 插件；想做规模化 PD 分离部署，llm-d 1.0 已经把路由层标准化，不必自己造轮子。

### 原理：SGLang Low-Latency 的 megakernel 与 llm-d 1.0 的路由收口

本期最值得理解的技术解读，两条线一起看。

**SGLang Low-Latency**：NVIDIA 用 **PDL（Programmable Dependent Launch）** 让依赖内核在输入就绪前就预取权重、准备好 barrier；attention 输出经 **NVLink epilogue multicast** 直接发往对端、省去 HBM 写部分和；AMD 把整解码层塌缩为 **2 个持久 FlyDSL 内核**、all-reduce 折叠在内。一句话——**用 megakernel + 通信/计算重叠，压低小 batch 的同步开销**。

**llm-d 1.0**：把"前缀感知路由 + KV offload"做成标准引擎前的一层，Ironwood TPU 上 TTFT **-85%、+2.4×**。它印证一件事：**PD 分离的工程复杂度正在从"各厂自研"收敛成"开源路由层"**。

> 我的判断：这两条线合起来看，推理引擎的演进已经从"谁的 kernel 快"升级到"谁能把控制面收口 + 把内核压到极致"。megakernel 吃的是小 batch 的同步成本，llm-d 吃的是跨引擎的编排成本——两端同时发力，说明 2026 下半年的瓶颈已经不在单算子，而在"运行时怎么把状态搬来搬去"。

## 三、AI 论文 + 产业热点

### 论文核心：PINT（arXiv:2610.16355，中科院自动化所/中关村学院/复旦/清华）

**一句话**：用 M=32 个「可预测意图 token」当 VLM / 世界模型 / 动作头唯一窄接头，把视频生成世界模型的未来预测单向传给动作专家——不必深度融合，"共享一个意图就够"。

- **核心思想**：把 VLM 隐状态直接灌进视频生成模型（VGM）会毁掉其预训练生成通路；PINT 用 **M=32 个 Intent Token（d=2560，两个线性投影共 10.5M 参数）** 作唯一接口，只替换 VGM 的 prompt 条件化，保留原生扩散路径。
- **机制**：VGM 推理时只跑一次当帧并缓存逐层 K/V，Action Expert（DiT 30 层）单向逐层读取（层 l↔l）；三损失 L_action 1.0 / L_AR 0.1 / L_video 0.1；两阶段——S1 冻 VGM 逼视频梯度必须过 Intent、S2 冻 VLM+Intent 让两端自适应。
- **影响**：RoboTwin2.0 **Easy 68.6 / Hard 15.5 / Avg 42.1**（Fast-WAM 1.8% 的 8.6 倍）、LIBERO 98.0、LIBERO-Plus 79.5（7974/10030）；消融 S1-only 掉 10.1pp、w/o KV 掉 2.7pp。让"具身预训练"不必重造，对缺数据缺算力的团队是条降本路径。

### 算子讲解：MiniMax Sparse Attention（MSA，arXiv:2606.13392）

**块稀疏注意力**——indexer 打分 → 128-token 块 maxpool → Top-16 块 + 强制 local 块 = 每 query 固定 **2048 KV 预算**（与上下文长度无关）。

- **在用**：MiniMax **M3.1-Flash**（428B 总参 / 23B 激活，60 层，`-tp 4`）；对照 DeepSeek NSA / CSA2 / HCA。
- **关键点**：decode HBM 流量降到 **12.5%**（index/dense = 1/8）、1M 上下文注意力 FLOPs 降 **28.4×**，但实测 prefill **14.2×** / decode **7.6×**——实测只有 FLOPs 增益的 **1/3.7**，kernel 开销吃掉大头。
- **坑**：块大小须等于 KV block size；dense 硬跑属分布外、会掉质量（MSA 是训练期语义，必须原生稀疏训练）。

### 性能优化：张量并行 TP（Tensor Parallelism，Megatron-LM arXiv:1909.08053）

**列并行**（Y_i=X·A_i，前向零通信/反向 AllReduce）与**行并行**（Y=Σ_i X_i·A_i，前向 AllReduce）成对使用、f/g 共轭，每层前向 2 次、反向 2 次 AllReduce，ring 每 rank 收发 2(p−1)/p·N·bytes。

- **代表**：M3.1-Flash 官方 vLLM 配方 `-tp 4 --block-size 128 --kv-cache-dtype nvfp4`，428B NVFP4≈214GB → 4 卡每卡 54GB。
- **收益**=显存近线性除以 TP 度；**坑**=跨机用 TP 卡在以太网、GQA 的 KV 头须被 TP 度整除（M3.1 只有 4 个 KV 头 → **TP≤4**，比上一代更紧）。
