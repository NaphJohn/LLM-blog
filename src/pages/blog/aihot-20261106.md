> **关于本期来源**：今天 vLLM / SGLang 社区跟踪摘要与 AI 论文 + 产业热点摘要**双双到齐**，因此本期同时覆盖推理基础设施与论文 / 产业两部分。

## ★ 今日最值得关注

**vLLM 修掉了一个"你根本不知道自己中招了"的缓存坑：PD 分离 × 投机解码互相吞掉前缀缓存命中，warm TTFT 凭空高 31%。** 这是 72h 内最值得立刻升级的工程修复（PR #64096，11-03 合入 main）。

三层事实：

1. **症状**：PD 分离依赖前缀 KV 复用，而 EAGLE / MTP 草稿器在匹配前缀时会**丢掉最后一块 lookahead hash**，命中率悄悄下降——你看到的是"PD + MTP 比预期慢"，而不是一个报错。
2. **修复**：PR #64096 把 lookahead block hashes 扩展到 **NIXL / Mooncake / offloading 三类 KV connector**；MultiConnector 仅在各子 connector 都 **opt-in** 时启用。
3. **收益**：NIXL P / D 下 warm TTFT **1173 → 809ms**、Mooncake **1236 → 931ms**（并发 64、MTP k=4），GSM8K / GPQA 持平 → **跑 PD + MTP 的部署应升级**。

**可执行结论**：如果你在做 PD 分离 + 投机解码的组合，现在就去核对 connector 命中率有没有被悄悄吃掉；跑 NIXL / Mooncake 的 PD + MTP 部署，升级到带 #64096 的 main 即可白捡 −31% warm TTFT，且不损精度。

> 值得单独说的一点：这条 PR 揭示的是"**解聚**"与"**投机**"两条主流优化路线会**互相干扰对方缓存**的隐蔽冲突。两个都会改写 KV 前缀的优化同时开着，它们不报错、不崩，只是让你的优化"打折"。组合拳的命中率要用独立指标盯住，而不是只看端到端延迟。

论文侧，今天值得读的是一份"考古"：**DeepMind Gato（2022）**——它用一个 1.18B Transformer 把 604 个任务的感知 / 语言 / 动作压进同一条 1024 token 序列。它证明的不是"什么都会"，而是"**接口可以统一**"——今天每一台 VLA 基座的语法都从这里来（见第三节）。

### 原理：vLLM #64096 —— 当"解聚"遇上"投机"，缓存被谁偷走

本期最值得理解的一条技术解读。

**冲突点**：PD 分离靠前缀 KV 复用省 prefill；EAGLE / MTP 草稿器在匹配前缀时，会丢掉最后一块 **lookahead hash**——于是命中率"看不出地"下降，却没有报错。

**修法**：把 lookahead block hashes 扩展到三类 KV connector（NIXL / Mooncake / offloading），MultiConnector 仅在各子 connector 都 **opt-in** 时启用 → 把被浪费的缓存命中捡回来，**TTFT −31% 且不损精度**（GSM8K / GPQA 持平）。

> 我的判断：这暴露的是一类结构性的坑——**两个都会改写 KV 前缀的优化同时开着时，它们不会冲突报错，只会互相打折**。PD 分离 + MTP 是当前最主流的"降本组合拳"，但这一条提醒：组合拳的命中率要用独立的指标盯住（前缀命中率、层间命中分布），而不是只看端到端延迟。

### 常驻专题

**PD 分离**：vLLM #64096 修复；AWS Mooncake + SGLang + EFA 跑 **200+ 台 p6-b300**（Peer 48 → 816、带宽线速 97.5%、Store 初始化 22min → 40s）；美团 LongCat-2.5 用 PD + HiCache / Mooncake 跨层预取使 **Decode KV 容量近翻倍**。

**架构演进**：SGLang breakable prefill + DCP、vLLM connector 扩展 lookahead、**NVFP4 4bit / Octave 3bit KV**、MTP / DSpark / EAGLE、Mooncake 重构 + NIXL V2。

**纯 PyTorch vs transformers**：OWLv2 纯 PyTorch 实现（Boxer）——离线 .pt、仅依赖 torch + 标准库、TorchScript 包文本编码器 + 自研 BPE；动机是更可控算子 / 更低开销 / 少依赖，代价是自研 tokenizer / 加载 / 并行。结论：**生产框架 + transformers 桥，研究走纯 PyTorch**。

**Step 适配**：Step 5 两框架 day-1 + 华为 Day-0 超节点；Step 3.7 Flash 四栈 + NVFP4；与官方支持对照领先同体量。

## 三、AI 论文与产业热点（本期有来源）

### 论文核心

**Gato / A Generalist Agent**（DeepMind，arXiv:2205.06175，TMLR 2022）——用**一个 decoder-only Transformer** 做下一 token 预测，覆盖 604 个任务的感知 / 语言 / 动作。

**核心思想**：

1. **万物皆 token，但每模态有自己的词表分片**：文本 32,000 / 离散 [0,1024) / 连续 μ-law 1024 箱 → [32000,33024) / 图像 16×16 patch。
2. **loss mask 只盖动作与文本**——它是策略，不是世界模型。
3. **训练时 25% 序列前置同任务演示**，把模仿变成上下文内模仿。

**影响**：604 任务中 450+ 超专家分 50% 阈值（厂商口径）；真机微调 **60% vs 从零 BC 0.5%**。两个短板（离散精度、逐维自回归太慢）直接分叉出 **RT-2**（语义路线）与 **π0 / GR00T N2**（连续动作专家路线）。

### 算子讲解

**μ-law 压扩 + 均匀分箱动作 tokenizer**：y = sgn(x)·ln(1+μ|x|)/ln(1+μ)（μ=255）后均匀分箱；误差界 Δ/2、RMS≈0.289Δ。**μ-law 不改误差量级，改的是误差在数值轴上的分布**——小幅度动作拿到更高分辨率。在用：Gato 1024 箱、RT-1 11 维×256 箱 3Hz、OpenVLA 7B+256 箱 97 万 episode；2026 分工 = Qwen3-VL 系骨干 + 离散 token 或 flow-matching 专家。

### 性能优化

**序列打包（Sequence Packing）+ 变长注意力**：用"多条短样本拼满长序列"替掉 padding，训练侧最便宜、无副作用的吞吐放大器。NeMo（Llama 7B / Dolly）FLOPs 最高 **10×**、训练时间最高 **6×** 不掉收敛；Tiptree 在线打包在 FLAN 上 **>2×**（已进 HF Transformers 4.44）；padding 90% 场景省 **89.73%** 注意力算力；VLA 侧工业报告 **1.88×**。**关键坑**：复杂度必须保持 Σs_i² 而非 (Σs_i)²，位置 id 须逐子序列重置。
