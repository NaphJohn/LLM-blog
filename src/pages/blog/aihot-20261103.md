> **关于本期来源**：今天 vLLM / SGLang 社区跟踪摘要与 AI 论文 + 产业热点摘要**双双到齐**，因此本期同时覆盖推理基础设施与论文 / 产业两部分。

## ★ 今日最值得关注

**SGLang v0.5.23 把 PD 分离安全风暴踩在脚下发布——5 项 CVE，含一个 CVSS 9.2 的 Dumper RCE，官方说修好了，自动追踪器却仍把 0.5.23 标红。**

这是本期唯一一条"会直接把你的线上部署打穿"的问题，而且麻烦不在漏洞本身，而在**修复的可信度与可达性**。

三层事实：

1. **同日发布**：vLLM **v0.33.0** 与 SGLang **v0.5.23** 都在 **11-02** 发布（SGLang 的 tag 实际是 10-30，11-02 才上 PyPI）。
2. **安全风暴**：SGLang 同步曝 **PD / 路由 5 项 CVE**（112266 / 112267 / 112268 / 112269 / 112270）：Decode worker **SSRF**、router **Mesh HA 鉴权绕过**、**Mooncake KV 耗尽 / OOM 链**。官方 CNA 口径称影响 **≤0.5.22、已修于 0.5.23**，但自动化追踪器仍把 0.5.23 标红——**修复存疑**。
3. **影响**：跑 **PD 分离**或**公网暴露**的部署，不能因为升到 0.5.23 就以为万事大吉。

**可执行结论**：跑 PD 分离 / 公网暴露的 → **升 0.5.23 + 做鉴权与网络隔离加固**；vLLM 侧 **NIXL 连接器要求 ≥1.5**，push-NIXL + Mooncake EFA 镜像已上，旧 NIXL 部署需同步升级。

> 值得单独说的一点：这类"**官方说修好了，但追踪器仍标红**"的灰色地带，比漏洞本身更值得警惕。它意味着你的升级清单里必须有一行"**升级后仍然要独立验证 CVE 状态**"——而不是看版本号到 0.5.23 就勾掉。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：**11-02 同日发布**。vLLM **v0.33.0**（927 commits / 389 贡献者）；SGLang **v0.5.23**（1007 PRs / 257 贡献者，tag 10-30）。

### vLLM v0.33.0

**新特性**：

- **升 PyTorch 2.14、仅发 CUDA 13.0**（12.9 停发）——旧 CUDA 栈的部署需重做镜像

- **DFlash / DSpark 不再预留草稿槽、量化草稿 lm_head**（并发 1 解码 **+18%**）

**破坏性变更**：

### SGLang v0.5.23

**性能**：

- **DeepSeek-V4.1 在 GB300** 负载下 prefill 吞吐最高 **+1.5×**、**32K–64K 首 token 延迟 −28%**
- **Low-Latency 模式**（NVIDIA megakernel / AMD monokernel 插件）：单用户解码 **GB300 +44%**、**MI350X +75%**

**新特性**：

- 新增 **Muse Spark Open、Beam-1.0、MiniMax-M3.1-Flash、MiniCPM-V 4.7、FLUX.3** 等模型
- **Paged Experts**（opt-in）：超显存 MoE 跑在**单张消费级 GPU**，较 CPU offload 最高 **30×**
- 原生上 **Google TPU7x**（SGLang-TorchTPU，PyTorch 原生）
- 量化 MoE（**FP8 / NVFP4**）上挂 **LoRA**

### 原理：vLLM v0.33.0 的 FLy 有损验证 + XPress 精修器

本期最值得理解的一条技术解读。

**标准投机解码用修正拒绝采样「无损」保留目标模型分布**。FLy 放宽接受准则，让更多草稿 token 通过，以**微小分布偏差换 1.04–1.31× 解码吞吐**——适合 Agent 工具调用 / 草稿等**分布不敏感**场景；创意 / 安全场景仍需无损。

**XPress 精修器**在验证前「精修」DFlash / DSpark 块扩散草稿，提升接受率；配合「**不再预留草稿槽**」与**草稿 lm_head 量化**，单步真实产出与解码算力效率双升。

> 我的判断：投机解码正在从"无损优先"走向"按场景选择有损 / 无损"。这条线对 Agent 类负载（工具调用、草稿生成）是直接红利，但切换有损验证前，得先确认你的下游对分布偏差不敏感——否则创意或安全输出会悄悄变质。

### 常驻专题

**PD 分离**：SGLang v0.5.23 含 PD 修复 **#45973**，但同步曝 **5 项 PD / 路由 CVE**（见 ★）；llm-d 1.0 前缀 + 负载感知路由走 NIXL；vLLM push-NIXL + 新增 Mooncake EFA 镜像。

**架构演进**：低精度 KV（vLLM **NVFP4 4-bit** + AMD **Octave 3-bit**）+ SGLang Low-Latency **megakernel** + DFlash / DSpark 块扩散 + FLy / MTP；SGLang **Paged Experts** 与 **TPU7x** 落地，多模态 / 扩散成内建引擎。

**纯 PyTorch vs transformers**：nano-infer / Shrike / Qwen3-Light-Infer / GPT-PY 等**纯 PyTorch 自研推理栈持续涌现**，演示分页 KV、连续批、投机解码、量化从零实现；好处 = 可控算子 / 零 HF 版本耦合 / 便于定制 attention，代价 = 自实现 tokenizer / 加载 / 并行；横向 = 生产用框架 + transformers 作格式桥，研究 / 教学自研内核。

**Step 适配**：Step 3.7 Flash **四栈齐活**（vLLM stepfun37 镜像 / SGLang dev-step-3.7-flash / Transformers / llama.cpp）+ **NVFP4 量化版**（modelopt FP4 + FP8 KV，TP4）+ 海光 DCU cookbook；Step 5 Preview 双框架 day-0/1；**MTP 配置口径两栈不同**（vLLM 走 mtp 方法、SGLang 走 EAGLE 兼容层），迁移须重调 speculative 配置。

## 三、AI 论文与产业热点（本期有来源）

### 论文核心

**VIMA**（General Robot Manipulation with Multimodal Prompts，NVIDIA×Stanford，arXiv:2210.03094，ICML 2023）——把机器人任务统一为**「图文拼贴提示」+ 一个 Transformer 自回归输出动作**，是 VLA 谱系的 prompt 化源头：T5 编码 prompt、Mask R-CNN 出变长对象 token、解码器 cross-attn + 因果自注意力逐 token 出 pick / place 动作。VIMA-BENCH 17 任务 / 600K+ 轨迹 / 四级泛化；VIMA-200M 在四级上 82 / 82 / 79 / 49 vs 最强像素基线 57 / 36 / 30 / 8，L4 零样本 **2.9 倍**、少 **10 倍数据 2.7 倍**；Oracle≈VIMA 证明**对象级表征（非检测器）是数据效率关键**。影响：VIMA-BENCH 成多任务操作评测标准，接口思想流向 RT 系 / π0 / GO-1。

### 算子讲解

**SimPO**（arXiv:2405.14734，NeurIPS 2024）——**免 reference 的偏好优化**：奖励 = 长度归一化平均对数概率，L = −logσ(Δr − γ) 加目标 margin；修 DPO「奖励排序与似然排序仅约 **50% 一致**」的错位，且省一份模型前向（约 **20% 计算 / 10% 显存**）；Gemma-2-9B-it AlpacaEval2 LC **72.4%** / Arena-Hard **59.1%**（vs DPO **+6.4 / +7.5**）。β≈2.0–2.5、γ/β≈0.3–0.55；坑 = 长度归一化最敏感、无 KL 锚点防 reward hack。

### 性能优化

**PowerInfer-2**（上交大 IPADS，arXiv:2406.06282）——**手机端侧异构 MoE 推理**：稀疏激活 + 神经元簇细粒度计算，prefill 用 NPU 大簇 / decode 用 CPU 细簇，分段神经元缓存（LRU→UFS）+ 簇级流水线藏 I/O；TurboSparse-Mixtral-47B **11.68 token/s**、最高 **29.2×**、全驻省 **40%** 内存。具身关联 = 机器人板载 SoC 异构同构配方。
