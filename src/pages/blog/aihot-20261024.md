## ★ 今日最值得关注

**本期唯一一条"大新闻"来自 DeepSeek 10-20 开源的生产级推理栈 DeepInfer——它基于 vLLM 深度改写，而非两框架本身发版；同一窗口 vLLM 停 v0.32.0 稳定 + RC、SGLang 停 v0.5.22 但主线落地弹性 EP 热扩容。**

三层事实：

1. **DeepInfer 开源（头条）**：10-20 开源、Apache 2.0，本质是 vLLM 的深度改写，自研 kernels（FlashMLA / DeepGEMM / DeepEP / TileLang），脱离通用 transformers 依赖。两大公开优化：① **SWA Bounded Replay**（YOCO prefill 截断，V4.1 默认 KEEP_TOKENS=140，缓存命中只重算保留后缀，长上下文 prefill 计算近乎减半）；② **Confidence-Scheduled Verification**（DSpark，草稿默认 5 token + confidence head 按置信度调度验证窗口）——与本人 OpenInfer / DFlash / DSpark 块级 / 自适应验证范式同源。代价：不含 KV 系统 / PD / 负载均衡。
2. **版本与安全（一稳一进，仍无新 tag）**：vLLM 稳定仍 v0.32.0（10-18，814 commits / 363）+ RC v0.32.1rc0（10-18，仅文档化 RL HTTP 权重传输 #62267），窗口内无 v0.32.1 稳定版；SGLang 稳定 v0.5.22（10-19，950 PRs / 245）仍 Latest，窗口内无 v0.5.23。安全债延续：CVE-2026-111391（Dumper RCE，0.5.10–0.5.22，CVSS 8.1）仍无修复版 → 生产务必关 Dumper。
3. **正确性修复密集（vLLM 三天三连）**：#60613（10-23 合 main）修 **DeepSeek-V4.1 prefill 读陈旧稀疏索引致 FlashMLA 前 127 token NaN / 非法内存访问**，4×GB200 修复后连跑 900s / 13,801 请求——跑 V4.1 偶发崩溃的**必升项**；#57092（10-23）修 online FP8 MoE 下 batch-invariant 不 invariant（per-expert scale stride=0 误读 expert 0），FP8 MoE 上 RL rollout / 可复现评测需重跑；#63165（10-23）修共享内存广播读取器 ~23 MiB/h/进程泄漏（ZMQ CONFLATE 未轮询），长时 TP / KV-connector 部署内存缓增有定因。

**可执行结论**：跑 V4.1 的团队把 vLLM 升到含 #60613 的构建（main 已合，等 RC/stable 即可摘）；FP8 MoE 上的 RL rollout 与可复现评测必须按 #57092 重跑；长时 TP 部署盯住 #63165 修复的内存泄漏；SGLang 侧把 Dumper 端点彻底关掉；想上弹性 EP 热扩容的可直接看 LMSYS 方案（复用故障恢复 + Mooncake PG + NIXL A2A，H100 / DS-V3-Lite FP8 实测扩容 5.3–8.2× 停机重启）。

> 值得强调：本期没有新版本号，但"生产栈自己撸内核"的信号比发版更重——DeepInfer 把 vLLM 深度改写 + 自研算子这条路直接产品化，和本人 DFlash / DSpark 的块级调度是同一哲学；vLLM 一侧把增量压在"正确性修复（V4.1 / FP8 MoE / 内存泄漏）+ PD 弹性"，SGLang 一侧压在"弹性 EP 热扩容 + DSpark 块验证"。两边都继续围绕"按置信度 / 块自适应验证 + 长上下文 KV 裁剪"收口。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：本期 vLLM 稳定 v0.32.0 + RC v0.32.1rc0（仅文档增量），SGLang v0.5.22 仍 Latest（950 PRs / 245 贡献者）——主线在"正确性修复 + 弹性算力"收口，而非大版本号刷新。

### vLLM（v0.32.0 稳定保持 + v0.32.1rc0 文档增量）

**版本 / 安全落地**：

- **版本**：稳定仍 v0.32.0（10-18，814 commits / 363 贡献者），近 72h 无新稳定 tag；主线 v0.32.1rc0（10-18）主做 RL trainer HTTP 权重传输协议文档化（#62267，零磁盘权重直推，需 mTLS）。生产仍以 v0.32.0 为目标。
- **正确性修复（本期头条，三天三连）**：
  - **#60613（10-23 合 main）**：修 DeepSeek-V4.1 prefill 读陈旧稀疏索引 → FlashMLA 前 127 token NaN / 非法内存访问；4×GB200 修复后连跑 900s / 13,801 请求。跑 V4.1 偶发崩溃的**必升项**。
  - **#57092（10-23）**：修 online FP8 MoE 下 batch-invariant 不 invariant（per-expert scale stride=0 误读 expert 0）→ 同输入不同 batch 结果漂移；FP8 MoE 上 RL rollout / 可复现评测需重跑。
  - **#63165（10-23）**：修共享内存广播读取器 ~23 MiB/h/进程泄漏（ZMQ CONFLATE 未轮询）；长时 TP / KV-connector 部署内存缓增有定因。
- **投机解码**：#54163 修 DFlash 草稿在混合 Mamba 丢弃末前缀块 + refiner head 提速（Qwen3.5-4B 每轮缓存 0,0,0 → 0,560,560）；#54448 XPress（~80M）比裸 DSpark +18.5% 吞吐。

### SGLang（v0.5.22 仍 Latest · 950 PRs）

**新特性（已发版确认 + main 近窗）**：

- **v0.5.22（10-19，Latest）**：950 PRs / 245 贡献者，窗口内无 v0.5.23。
- **弹性算力（头条）**：10-23 LMSYS 博客发**弹性 EP 热扩容**——在线无停机 EP4 → EP6 / EP8，复用故障恢复 + Mooncake PG + NIXL A2A；H100 / DS-V3-Lite FP8 实测扩容 **5.3–8.2× 停机重启**，已合主干、缩容在审。
- **投机解码（已含 + 在研）**：DSpark 信心驱动块级验证（v0.5.22 已含），DeepSeek-V4-Pro TP8 B300 accept≈5 达 **383.7 tok/s**；DFlash 族（#42987 块验证）在 main 打磨。
- **PD 分离**：v0.5.22 内 PD 长提示 **+27% 吞吐 / 减半 p95 TTFT（#40703）**；DFlash 族在 main 打磨。
- **安全（务必处理）**：CVE-2026-111391（Dumper 表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版 → 生产务必关 Dumper。

### 原理：DeepInfer 的两大公开优化——把"读多写少"写进推理引擎

- **SWA Bounded Replay**：YOCO prefill 截断，V4.1 默认 KEEP_TOKENS=140——缓存命中时只重算保留后缀，使长上下文 prefill 计算近乎减半。它和 vLLM / SGLang 的"长上下文 KV 裁剪"是同一主线。
- **Confidence-Scheduled Verification**：DSpark 范式，草稿默认 5 token + confidence head 按置信度调度验证窗口（DeepSeek-V4-Pro 实测 accept≈5）。与本人 OpenInfer / DFlash / DSpark 块级 / 自适应验证同源——共同答案是"按置信度 / 块自适应验证"。
- **代价**：DeepInfer 不含 KV 系统 / PD / 负载均衡，这部分仍需生产栈补齐（vLLM production-stack #669 LMCache + NIXL PD 在审）。

> 我的判断：本期版本号一稳一进（vLLM 锁 v0.32.0、SGLang 守 v0.5.22 Latest），增量集中在"正确性修复（V4.1 / FP8 MoE / 内存泄漏）+ 弹性算力（SGLang EP 热扩容）"。DeepInfer 的"基于 vLLM 深度改写 + 自研内核"是生产极致优化的范本——代价是你要自己实现 KV / PD / 调度。和本人 DFlash / DSpark 的块级调度对照，思路完全同构。

### 常驻专题

**PD 分离**：vLLM push-NIXL 持续发酵（1P1D 最高 3× TTFT / +30%）+ #60613 / #57092 正确性修复 + production-stack #669 LMCache + NIXL PD 在审；SGLang v0.5.22 PD +27% / 减半 TTFT + DSpark NIXL + Mooncake。DeepInfer 生产栈 PD 未开源（闭源局限）。

**架构演进**：DeepInfer 的 SWA Bounded Replay + 置信度调度验证；vLLM / SGLang 持续 DFlash / DSpark 块验证 + MTP + 低精度 KV + EPD 多模态 + 弹性 EP。共同主线＝"按置信度 / 块自适应验证 + 长上下文 KV 裁剪"。

**PyTorch vs transformers**：DeepInfer 是本期最佳案例——主要基于 vLLM 深度改写、自研 kernels（FlashMLA / DeepGEMM / DeepEP / TileLang），脱离通用 transformers 依赖；代价＝需自行实现 KV / PD / 调度；结论＝生产极致优化走内核级定制 + 自研算子，研究 / 快适配走 transformers。

**Step 适配**：Step 5 day-0 / 1 双框架对齐 + 国产硬件 Day-0（昇腾 950 等）；DeepInfer 同样支持 Ascend 950，自主可控栈趋同。Step 系列本周无新模型发布，Step-3.7 Flash 仍是 Agent 旗舰。

## 三、AI 论文与产业热点

### 今日重点（1 句）

**机器人「大脑」从训练一次走向持续自进化：SERA 冻结执行器只改规划规则，与宇树自进化大模型、数采场景清单是同一条叙事。**

### 论文核心（SERA · Self-Evolving Robotic Agent）

- **一句话定位**：中科大 × 上海 AI 实验室 × 上交大（arXiv:2610.29560）给高层 VLM 规划器套一个可编辑 harness——episode 内维护任务上下文、跨 episode 用 rollout 提议并按胜率选优修订规则，**选后冻结防作弊**。
- **核心思想（3 行）**：
  1. VLA 执行器**全程冻结、零梯度训练**——不碰底层动作，只让"上层怎么想"自我进化；
  2. 跨 episode 用 rollout 提议规则修订，**按胜率选优**（而非梯度）；
  3. 选后冻结，杜绝"边比赛边改规则"的作弊。
- **结果 / 影响**：RoboMME **51.38% vs 44.38%（+7pp）**；与 MemoryVLA / EvoVLA 构成 **VLA 可靠性三部曲**，确立「规划器自进化」范式（DSPy 思想搬进机器人）。

### 算子讲解：Engram 查表记忆（DeepSeek V4.1-Flash）

- **定位**：552B + 196B 的"外挂记忆"——长尾知识放一个 (k,v) 表，ANN 检索 + 门控融合；记忆从「每步付 KV 租金」变「一次存按需取」。
- **谱系**：kNN-LM / RETRO 一脉。
- **具身映射**：机器人是极端**读多写少**的负载，Engram 把"查表记忆"搬进端侧直接减负。

### 性能优化：EPLB 专家重平衡（DeepSeek 开源）

- **定位**：MoE 负载不均（imbalance = max / mean）→ 冗余专家 + 贪婪重排装箱；零精度损失、**吞吐≈提升 imbalance 倍**。
- **互补**：与 aux-loss-free 偏置互补（**训练期 vs 部署期**两道保险）。
- **具身映射**：云脑并发推理容量。
