## ★ 今日最值得关注

**本期最关键的一条是 vLLM 合并了 NIXL GQA 草稿 KV 按头分片修复（10-20 合入 main）——这是「PD 分离 + 投机解码」同时开启下的静默解码劣化必升正确性修复，和本人 OpenInfer/DFlash/DSpark 同域；同期 SGLang 推出 --pd-stream-after-prefill（prefill 阶段即流推 KV，长上下文 agent 首 token 等待下降），DSv4.1 默认 MegaAttention PD 且 DSpark 接入 NIXL；论文侧 DiT（ICCV 2023 最佳论文）证明扩散模型换 Transformer 主干后遵守缩放定律，其直系后代正是 π0/GR00T 的流匹配动作专家。**

三层事实：

1. **版本与安全（两框架稳定版坐实、无新 tag）**：**vLLM 稳定版仍 v0.32.0（10-18，814 commits / 363 贡献者）**，最新 RC 为 v0.32.1rc0（10-18，仅文档化 RL trainer HTTP 权重传输协议 #62267），无 v0.32.1 稳定版；**SGLang 稳定版仍 v0.5.22（10-16），窗口内无 v0.5.23**。更关键的是 **CVE-2026-111391（Dumper 表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版**——生产务必关闭 Dumper。
2. **架构演进（PD 分离 + 投机「正确性 + 弹性」双重加固）**：**vLLM #NIXL GQA 草稿 KV 按 head 分片（10-20 合入 main）** 修复 PD 分离 + 投机解码下 GQA 草稿 KV 按头错位导致的静默解码劣化；另合入 **NIXL pull sleep #59635（10-19）**，pull 模式 PD 空闲 sleep，省显存/电费、支撑弹性扩缩容。**SGLang #45102 --pd-stream-after-prefill（10-19）** prefill 阶段即向 decode 流式推 KV，降低首 token 等待；**DSv4.1 Default PD to MegaAttention（10-19）+ DSpark 接入 NIXL 后端 #43734**。
3. **论文信号**：**DiT（Scalable Diffusion Models with Transformers，arXiv:2212.09748，ICCV 2023 最佳论文）** 把 U-Net 换成 Transformer 主干，潜空间 patchify + adaLN-Zero，DiT-XL/2 FID 2.27 SOTA、Gflops-FID 可外推——Sora/SD3/FLUX/视频世界模型的直系祖先，π0/GR00T 的动作专家本质就是一个小 DiT。

**可执行结论**：生产继续锁 **v0.32.0（vLLM）/ v0.5.22（SGLang）**，但跑 **PD 分离 + 投机解码** 的必须升到含 GQA 分片修复的版本，上线前用 lm-eval 等复核投机接受率与输出质量；SGLang 侧把 Dumper 端点彻底关掉。DiT 的「扩散主干遵守缩放定律」结论可迁移到本人 VLA 流匹配动作专家路线——蒸馏/缓存/量化全都作用在它身上。

> 值得强调：本期两框架都没有大版本号刷新，增量全部压在「PD 分离 + 投机解码」这条主轴上——vLLM 补的是**正确性**（GQA 分片错位静默劣化）和**弹性**（pull sleep），SGLang 补的是**首 token 延迟**（prefill 即流推 KV）。这条线正是 OpenInfer/DFlash/DSpark 的主战场，GQA 分片修复和我们是同一类必升项。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：本期 **vLLM 稳定 v0.32.0 + RC v0.32.1rc0（仅文档增量），SGLang 稳定 v0.5.22（无 v0.5.23）**——主线在「PD 分离 + 投机解码的正确性 + 弹性加固」方向收口，而非大版本号刷新。

### vLLM（v0.32.0 稳定版保持 + v0.32.1rc0 文档增量）

**版本 / 安全落地**：

- **版本**：**稳定版仍 v0.32.0（10-18，814 commits / 363 贡献者）**，窗口内无新稳定 tag；主线 10-18 切 v0.32.1rc0 主做 RL trainer HTTP 权重传输协议文档化（#62267，RL 热更新权重零磁盘直推，需配 mTLS）。影响：生产仍以 **v0.32.0** 为目标。
- **重要 PR（PD+投机 正确性必升）**：**NIXL GQA 草稿 KV 按 head 分片修复（10-20 合入 main）**——PD 分离 + 投机解码下，草稿（eagle/MTP）KV 跨实例 NIXL 传输若未按 head 对齐分片，decode 端会读错注意力头 → 静默劣化；修复在传输前按 head 维度对齐分片。OpenInfer/DFlash/DSpark 同域必升。
- **PD 弹性**：**NIXL pull sleep #59635（10-19）**——pull 模式 PD 空闲 sleep，省显存/电费、支撑弹性扩缩容。
- **性能 / 安全**：**Enable PDL for fused MoE top-k gating #59737** + **MegaAttn MXFP8 #60118（10-19）**；pre-commit 拦截硬编码 trust_remote_code；v0.32.0 三 GHSA / 默认关 CORS 延续。

### SGLang（v0.5.22 · 版本号坐实 + main PD 新旋钮）

**新特性（已发版确认 + main 近窗）**：

- **v0.5.22（10-16，Latest）**：稳定版坐实，窗口内无 v0.5.23。
- **main 近窗（PD 首 token 延迟）**：**sgl-router 新增 --pd-stream-after-prefill #45102（10-19）**——prefill 阶段即向 decode 流式推 KV，降低首 token 等待，长上下文 agent 收益明显。
- **main 近窗（DSv4.1）**：**deepseek-v4.1 Default PD to MegaAttention（10-19）** + **[DeepSeek-V4.1] Admit NIXL backend for DSpark PD #43734**——DSv4.1 默认 MegaAttention PD，DSpark 投机 PD 接入 NIXL。
- **安全（务必处理）**：**CVE-2026-111391（Dumper 调试端点表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版**——生产务必关闭 Dumper 调试端点。

### 原理：vLLM NIXL GQA 草稿 KV 分头分片修复——「PD 分离 + 投机」静默劣化的根因

- **做法**：PD 分离下草稿（eagle/MTP）KV 跨实例经 NIXL 传输时，GQA 的多查询头需按 head 维度对齐分片；若分片未对齐，decode 端会把不同头的 K/V 拼错位置 → 注意力算错但**不报错**，表现为输出质量静默劣化。
- **修复**：在 NIXL 传输前按 head 维度对齐草稿 KV 分片，decode 端读取与训练分布一致。
- **定位**：这是「PD 分离 + 投机解码」同时开启的**必升正确性修复**，和 OpenInfer/DFlash/DSpark 在 PD 下的 KV 一致性是同一类问题。上线前建议用 lm-eval 等评测工具复核投机接受率与输出质量（与 10-19 Paradigm #41133「吞 token」修复同类——都是高并发/PD 下的正确性，而非吞吐）。

> 我的判断：本期版本号稳（v0.32.0 / v0.5.22），增量集中在「PD 分离 + 投机」正确性与弹性四条线——vLLM 补 GQA 分片（正确性）+ pull sleep（弹性），SGLang 补 prefill 即流推 KV（首 token 延迟）+ DSv4.1 MegaAttention PD。投机解码仍是双引擎共同主轴（vLLM FLy+MTP 修复 / SGLang DFlash 块级验证 #42987 + DSpark Markov 头融合），近期还可对照 vLLM+NVIDIA Kimi K3 GB300 解码路径（CuTe DSL，23→13 kernel，842 tok/s、1.73×，#61867，10-16）。SGLang 这边没有新版本，CVE-2026-111391 未修是悬在头上的安全债，关 Dumper 是唯一解。

### 常驻专题

**PD 分离**：vLLM 双向 KV + push-NIXL（多轮 agent TTFT 1.6–3.3×）+ NIXL pull sleep + GQA 草稿分片；SGLang --pd-stream-after-prefill + DSv4.1 MegaAttention + DSpark NIXL 后端；两端均走向「流式 / 双向 / 弹性 + 投机可分离」。

**架构演进**：投机解码成共同主轴（vLLM FLy+MTP 修复 / SGLang DFlash 块级验证 #42987 + DSpark Markov 头融合）；近期对照 vLLM+NVIDIA Kimi K3 GB300 解码路径（CuTe DSL，23→13 kernel，842 tok/s、1.73×，#61867，10-16）。

**PyTorch vs transformers**：窗口内 vLLM/SGLang 主线程无「脱离 transformers」PR；社区纯 PyTorch 自研栈（Qwen3-Light-Infer / liteinfer / nano-infer）持续涌现，属独立教学/轻量项目；生产仍以 vLLM/SGLang（transformers 后端可关）为主。

**Step 适配**：Step 5 day-0 双框架对齐（差异在 KV offload 与首启 FlashInfer 编译）；Step3-VL-10B vLLM 正式支持（#32329）+ FP8 + SGLang cookbook，多模态 VLM 单卡可跑；Step-Video/Step-Audio 窗口内无新增。

## 三、AI 论文与产业热点

### 今日重点（1 句）

**DiT（ICCV 2023 最佳论文，arXiv:2212.09748）证明扩散模型换 Transformer 主干后遵守缩放定律，其直系后代正是机器人 VLA 的流匹配动作专家；产业面 Optimus V3 宣布量产就绪、10/22 财报为最大变量。**

### 论文核心（DiT · arXiv:2212.09748）

- **一句话定位**：**扩散模型的可扩展主干**——把 U-Net 换成 Transformer，证明扩散同样遵守 scaling law，直接催生了 Sora/SD3/FLUX 与视频世界模型。
- **做法**：潜空间 patchify（把 latent 当 token）+ **adaLN-Zero**（条件回归出 γβ 做层归一化缩放，门控 α 零初始化恒等起步，不破坏预训练分布）；DiT-XL/2 FID 2.27 SOTA，且 **Gflops-FID 可外推**——算力翻一倍、质量可预测地变好。
- **结果 / 影响**：Sora/SD3/FLUX/视频世界模型的直系祖先；**π0/GR00T 的动作专家本质就是一个小 DiT**（流匹配），蒸馏/缓存/量化全都作用在它身上——与本人 VLA 路线同构，先把「扩散主干遵守缩放定律」这个结论钉死，再谈动作专家的降本增效。

### 算子讲解：aux-loss-free 负载均衡偏置（DeepSeek V3/V4）

- **定位**：MoE 路由负载均衡的「零辅助损失」路线——**偏置 b_i 只进路由选择、门控值不含 b_i**，每步按 `b_i −= γ·sign(load_i − mean)` 反馈纠偏。
- **关键点**：主梯度零污染（不引入辅助损失扭曲主任务），比标准 aux-loss 更干净；GLM 同族、Qwen3 走轻量 aux 路线。坑 = γ 太大震荡、太小纠偏慢，需随 batch 负载动态调。

### 性能优化：序列并行 / Ring Attention

- **定位**：长序列训练激活沿序列切分，**Ulysses** 切 head 通信 O(N·d/P)、**Ring Attention** KV 环传 + 计算通信重叠；Ulysses 比 Megatron-SP 序列长 4×/吞吐 +5×，DeepSeek V3 长序列吞吐 3–4×。
- **收益**：VLA / 世界模型长视频训练的基建——长序列是具身长时程任务的天花板，序列并行直接决定能不能把整段演示塞进一个 batch。
