## ★ 今日最值得关注

**Shrike 与 NanoInfer 同框：自研推理栈正在从 PPT 走向可用工程。**

近 72h 两框架稳定版均维持 11-02 收口（vLLM v0.33.0 / SGLang v0.5.23），无新发版；主线在峰会预热 + main 硬化。真正值得盯的是**两条「脱离框架」的自研推理栈同时浮现**：

1. **Shrike（纯 PyTorch）**：零依赖实现 MHA / RoPE / SwiGLU、PagedAttention（16-token 定长块）、连续批处理、投机解码、OpenAI 兼容 API；注意力用 torch.compile 自写非连续 KV 内核，多序列 KV 用 copy-on-write 共享省显存。
2. **NanoInfer（纯 CUDA）**：无 PyTorch、无 TensorRT，手工 CUDA kernel 实现 GPT-2 INT8 在 A100 达 **1180 tok/s、0.85 ms/token（约 TensorRT FP16）**。

**可执行结论**：两条线共同印证「离开 transformers、极致可控」已从概念走向可用工程——生产用 vLLM / SGLang + transformers 作格式桥，研究 / 极致优化用纯 PyTorch / CUDA 自研内核。

> 值得单独说的一点：又是「**能力在 main、稳定线滞后**」的一天。Kimi K3.1 Pro 的官方 recipe 要求 vLLM 0.34.0+，但稳定线仍是 0.33.0——自托管团队的依赖管理里必须保留一条从 main 拿热修 / 新能力的应急路径，否则要么卡在旧版、要么被「能跑但不对齐」悄悄吃掉训练质量。

### 原理：Shrike 把 PagedAttention 做成 16-token 定长块

本期最值得理解的一条技术解读。

Shrike 的 PagedAttention 实现：

- **16-token 定长块**，块分配器管空闲 / 回收 / 共享；
- **注意力用 torch.compile 自写非连续 KV 内核**，绕开框架的融合限制；
- **多序列 KV 用 copy-on-write 共享**省显存。

动机 = 可读性 + 可定制 attention / 采样 + 去除依赖耦合；代价 = 需自己实现 tokenizer / 模型加载 / 并行。

> 我的判断：这类「生产框架 + transformers 桥 vs 研究纯 PyTorch / CUDA」的分工正在固化。它不取代生产框架，但给「要改 attention、要抠采样、要去版本耦合」的团队一条干净路——代价是你得自己扛 tokenizer / 并行。NanoInfer 进一步把这条路推到「连 PyTorch 都不用」的极致。

### 常驻专题

**PD 分离**：vLLM push-NIXL + MRV2；SGLang v0.5.23 PD + KVShard + DSpark-NIXL + Mooncake；llm-d 1.0（IBM GLM-5.2 5–10×、前缀命中 98%、17000 节点 2.9×）。窗口内无新 PD 安全补丁，CVE-2026-111391 修复仍仅在 main。

## 三、AI论文与产业热点

### 论文核心 · BLIP-2：可学习 query 桥接范式

**Salesforce, ICML 2023, arXiv:2301.12597**

- 一句话定位：用轻量 Q-Former 桥接冻结单模态巨人，只训翻译官不训巨人——参数比 Flamingo-80B 少 **54 倍**、零样本 VQAv2 反超 **8.7%**。
- 核心思想：① 32 个可学习 query cross-attn 向冻结 ViT 取信息 → 定长 32 token 视觉摘要（信息瓶颈）；② 两阶段 = ITC / ITM / ITG 三损失表征学习（同权重异注意力掩码）→ OPT / FlanT5 生成学习（ITG 续训）；③ 去桥消融 VQA 显著掉分，桥不可省。
- 影响：InstructBLIP / MiniGPT-4 / mPLUG-Owl 直系；EmbodiedGPT 580-query 变体进具身；教训 = 瓶颈有损 → Qwen-VL 转全 token 路线；端侧 VLA 视觉压缩思想源头。

### 算子讲解 · SigLIP 2 四路损失

**arXiv:2502.14786**：定位 = 视觉塔同时具备对齐 / 生成 / 定位能力；在用模型 = Qwen3-VL 视觉塔底座；关键点 = L_cap 生成性语义 + L_loc 自蒸馏掩码预测 + L_dbg 在线去偏（负样本梯度衰减），蒸馏须 stop-gradient。

### 性能优化 · CacheGen

**SIGCOMM 2024, arXiv:2310.07240**：定位 = KV cache 跨机传输带宽 / 时延瓶颈；代表工作 = UChicago，与 H2O / LLMLingua 叠加再省 **3.3~4.2x** 带宽；收益 = KV **3.5~4.3x** 压缩、总时延 **3.2~3.7x**、比 8-bit 量化再快 **1.67~1.81x**。
