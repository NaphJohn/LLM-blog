## ★ 今日最值得关注

**本期最关键的一条是 SGLang v0.5.22 正式标记 Latest（10-19，950 PRs / 245 贡献者）——这是继 v0.5.21 之后又一座大版本里程碑，且主线顺势合入平头哥 T-HEAD SAIL（真武 AI 芯片）初始支持（#43826，10-20），国产推理平台首进双引擎；同期 vLLM 主线推进 EPD（Encode-Prefill-Decode）多模态分离式服务（#62573 新增 metadata-only audio-in-video），把重型多模态编码器从 prefill/decode GPU 上卸载；阶跃 Step-Audio-R1.1 登顶语音推理榜（96.4%）；论文侧 MemoryVLA（arXiv:2508.19236）给 VLA 装双记忆系统、长时程真机任务 +26，产业面特斯拉 Optimus 弗里蒙特正式投产、具身量产元年实质催化。**

三层事实：

1. **版本与安全（SGLang 大版本坐实、vLLM 稳定版锁 v0.32.0）**：**SGLang v0.5.22 正式标记 Latest（10-19，950 PRs / 245 贡献者）**，新增 Clef、PPLX-Decider，提升 DeepSeek-V4.1 吞吐；**vLLM 稳定版仍 v0.32.0（10-18）+ RC v0.32.1rc0（10-18，仅文档化 RL HTTP 权重传输协议 #62267）**，窗口内无新稳定 tag。安全债延续：**CVE-2026-111391（Dumper 表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版**——生产务必关闭 Dumper。
2. **架构演进（EPD 多模态分离 + 国产平台首进双引擎）**：**vLLM #62573（EPD metadata-only audio-in-video）** 在 PD 分离基础上把多模态 Encode 拆成独立阶段/池子，重型编码器不再阻塞 prefill/decode GPU；**SGLang #43826 T-HEAD SAIL 初始支持** 让真武 AI 芯片跑进 SGLang 默认支持矩阵（vLLM 侧暂无对应国产芯片 PR），**KVShard PD 传输 #38473 + 按未缓存 token 路由 #45103 + DSpark PD 接 NIXL #43734** 继续收口 PD 弹性。
3. **论文信号**：**MemoryVLA（清华 Gao Huang 组 × Dexmal，arXiv:2508.19236）** 给 VLA 装上「海马体」式双记忆系统（工作记忆 + PCMB 记忆库），长时程真机任务 +26、LIBERO 96.5%、Bridge +14.6——记忆成为 VLA 继「看得懂、动得准」之后的第三竞争维度。

**可执行结论**：生产继续锁 **v0.32.0（vLLM）/ v0.5.22（SGLang）**；跑长上下文多模态（Step-3-VL / Step-Video / audio-in-video）的可提前评估 EPD 三阶段独立扩缩容；SGLang 侧把 Dumper 端点彻底关掉，并关注 T-HEAD SAIL 是否能带来国产卡部署红利。MemoryVLA 的「双记忆」思路可直接迁移到本人 VLA 路线——长时程任务的天花板正是「逐帧失忆」。

> 值得强调：本期 SGLang 抢到了「大版本 + 国产平台」双头条，vLLM 则把增量压在「多模态分离」这条主轴（EPD），双方都未刷新版本号以外的叙事——SGLang 950 PRs 是窗口内体量最大的单版本，国产 T-HEAD SAIL 进 SGLang 也暗示推理引擎的国产化军备竞赛正在升温。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：本期 **vLLM 稳定 v0.32.0 + RC v0.32.1rc0（仅文档增量），SGLang v0.5.22 正式标记 Latest（950 PRs / 245 贡献者）**——主线在「多模态分离（EPD）+ PD 弹性 + 国产平台」方向收口，而非大版本号刷新。

### vLLM（v0.32.0 稳定版保持 + v0.32.1rc0 文档增量）

**版本 / 安全落地**：

- **版本**：**稳定版仍 v0.32.0（10-18，814 commits / 363 贡献者）**，窗口内无新稳定 tag；主线 10-18 切 v0.32.1rc0 主做 RL trainer HTTP 权重传输协议文档化（#62267，RL 热更新权重零磁盘直推，需配 mTLS）。影响：生产仍以 **v0.32.0** 为目标。
- **重要 PR（多模态分离 EPD）**：**#62573 EPD metadata-only audio-in-video（合入 main）**——在 PD 分离基础上把多模态 Encode（视觉/音频编码器）独立成阶段/池子，重型编码器不再阻塞 prefill/decode GPU，本期新增「仅元数据」的 audio-in-video 支持。利好 Step-3-VL、Step-Video、audio-in-video 等长上下文多模态部署。
- **性能 / 调度**：**AMX 长上下文 MTP 调度 #59082**、**cooperative TopK 候选溢出精确性修复 #59645**、**Transformers 上探 5.20.0 #61983**；vllm-metal 随 v0.32.0 升级，新增 **TurboQuant GQA decode 内核 #1174**、DiffusionGemma 在 Apple Silicon jev 决策（中位延迟 < 0.2s）；**ROCm AITER v1.26.0 #62486**。

### SGLang（v0.5.22 正式 Latest · 950 PRs + 国产平台首进）

**新特性（已发版确认 + main 近窗）**：

- **v0.5.22（10-19，Latest）**：**950 PRs / 245 贡献者**，新增 Clef、PPLX-Decider，提升 DeepSeek-V4.1 吞吐；窗口内无 v0.5.23。
- **main 近窗（国产平台）**：**#43826 T-HEAD SAIL（平头哥真武 AI 芯片）初始支持（10-20）**——国产推理卡首进 SGLang 默认支持矩阵。
- **main 近窗（PD 弹性）**：**KVShard PD 传输 #38473**、**sgl-router 按未缓存 token 路由 #45103**、**DSpark PD 接入 NIXL 后端 #43734**。
- **安全（务必处理）**：**CVE-2026-111391（Dumper 调试端点表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版**——生产务必关闭 Dumper 调试端点。

### 原理：vLLM EPD 多模态分离式服务——把「重型编码器」从热路径上卸下来

- **做法**：在 PD 分离基础上，把多模态 Encode（视觉/音频编码器）也独立成一个阶段/池子（EPD = Encode-Prefill-Decode）。编码 / 预填充 / 解码三阶段可独立扩缩容——重型 ViT/音频塔不再和 LLM 抢同一块 prefill/decode GPU；本期 #62573 新增 metadata-only audio-in-video 支持，进一步把多模态元数据与 token 流解耦。
- **影响**：长上下文多模态（Step-3-VL / Step-Video / audio-in-video）部署的首 token 与吞吐不再被编码器峰值拖死，编码池可单独扩、decode 池可单独缩。
- **定位**：与「把 Python 从热路径剥离（MRV2 / Rust core）」同源——都是把非 LLM 计算从推理热路径上隔离出去，提升 GPU 利用率。

> 我的判断：本期版本号一稳一进（vLLM 锁 v0.32.0、SGLang 进 v0.5.22 Latest），增量集中在「多模态分离（vLLM EPD）+ 国产平台（SGLang T-HEAD SAIL）+ PD 弹性」三条线。投机解码仍是双引擎共同主轴（vLLM FLy+MTP / SGLang DFlash 块级验证 #42987 + DSpark），本期未大动，但 DeepSeek-V4.1 MegaAttention（#60118）与 TurboQuant GQA decode 内核（#1174）持续把量化/投机压进内核层。SGLang 950 PRs 是窗口内体量最大的单版本，T-HEAD SAIL 进默认支持矩阵则把国产推理军备竞赛摆上台面。

### 常驻专题

**PD 分离**：vLLM EPD（#62573）+ KV Offload 异步 + push-NIXL（稳定）；SGLang KVShard（#38473）+ 按未缓存 token 路由（#45103）+ DSpark PD 接 NIXL（#43734）+ DeepSeek-V4.1 默认 PD MegaAttention；两端均走向「流式 / 双向 / 弹性 + 投机可分离」。

**架构演进**：EPD 多模态分离；投机 DFlash V2 / DSpark / MTP；量化 NVFP4 / FP8 / MXFP4 + TurboQuant GQA decode 内核（#1174）；DeepSeek-V4.1 MegaAttention（#60118）。

**PyTorch vs transformers**：窗口内 vLLM #61983 仍依赖 Transformers 5.20.0，未见脱离 PR；社区纯 PyTorch 自研（Qwen3-Light-Infer / nano-infer / GleamLM）持续涌现，属独立教学/轻量项目；生产仍以 vLLM/SGLang（transformers 后端可关）为主，结论「自研核心 + 标准格式导出」折中。

**Step 适配**：Step 5 Preview 双框架 day-1/2 对齐（vLLM recipes #1122 + PR #61727 草稿；SGLang cookbook）；Step3-VL-10B vLLM 官方支持；Step 3.7 Flash 生产 Agent 旗舰；**Step-Audio-R1.1 登顶语音推理榜（96.4%）**；差异在 PD 传输范式与国产芯片覆盖（SGLang 已点 T-HEAD SAIL）。

## 三、AI 论文与产业热点

### 今日重点（1 句）

**MemoryVLA（arXiv:2508.19236）给 VLA 装上「海马体」式双记忆系统、长时程真机任务 +26，记忆成为 VLA 第三竞争维度；产业面特斯拉 Optimus 弗里蒙特正式投产、具身量产元年实质催化。**

### 论文核心（MemoryVLA · arXiv:2508.19236）

- **一句话定位**：**长时程机器人操作的记忆框架**——机器人操作是非马尔可夫的，主流 VLA 逐帧失忆导致重复/跳步，MemoryVLA 用双记忆系统把「上下文」留住。
- **做法**：**Cognition-Memory-Action**——VLM 编码感知 + 认知 token（工作记忆）→ **PCMB 记忆库**（细节 + 语义）检索 / 门控融合 / 巩固 → 扩散动作专家；记忆库让 agent 在长序列里不丢前文。
- **结果 / 影响**：LIBERO 96.5%、Bridge +14.6、真机 84%、长时程 +26，已集成 Dexbotic。记忆成为 VLA 继「看得懂、动得准」之后的**第三竞争维度**——直接命中长时程装配、多步烹饪等真实场景。

### 算子讲解：FiLM 条件调制

- **定位**：条件信息逐通道 γ/β 调制特征，**O(N) 替代 cross-attention**——轻量地把任务/语言/本体条件融入视觉特征；RT-1 语言条件、RT-X 本体 embedding、**DiT adaLN-Zero（= FiLM + 零初始化）**、MemoryVLA 门控变体都在用。
- **关键点**：**γ 零初始化恒等起步**——训练初期不破坏预训练分布，条件强度由网络自己学。

### 性能优化：热冷权重分离 / 稀疏激活（PowerInfer / Apple LLM in a Flash）

- **定位**：激活呈幂律稀疏——**热权重常驻 GPU、冷权重按需异步预取**，把 DRAM 占用压到 1/4~1/10、首 token 加速 4~25×。
- **收益**：具身 VLA 端侧部署「三件套」之一（量化 + 投机 + 热冷分离），直接决定能不能在车载/机器人本体的有限显存上跑起大模型。

### 产业热点（具身公司 / 产业链速递 · 置顶）

- **【具身①】特斯拉 Optimus**：**弗里蒙特正式投产**，2027 底周产 2 万目标 → 利好 002050（三花）/ 601689（拓普）/ 600699（均胜）订单；
- **【具身②】工博会进厂潮**：智元 G2 龙旗并线（上纬 688585）、乐聚/宇树产线演示，行业从「能演示」转向「稳定好用」；
- **【具身③】DeepSeek 开源 DeepInfer**：38 美元/卡时、毛利 ~82%；战配宇树 688836 + 拟领投 Winverse，OpenAI 官宣做人形；
- **【通用】** DeepSeek V4.1 Flash KV 缓存缩 437 倍；TorchTPU 开源；Mistral Voxtral 3 语音 Agent。
