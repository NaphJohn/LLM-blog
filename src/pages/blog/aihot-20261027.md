## ★ 今日最值得关注

**SGLang 未修复的会话替换 DoS 漏洞（CVE-2026-110809）：生产可被一条请求打挂，且官方修复还没合。**

这是本期唯一一条"会直接让你的线上服务崩溃"的问题——和上一期的 NVFP4 无限重复不同，这次是**可用性攻击面**，不是精度问题。

三层事实：

1. **症状**：`replace=true` 但缺少 `rid` 字段时，触发 **SIGQUIT 崩溃**。攻击者（或仅仅是写错的客户端）可以用一条特制的会话替换请求把你的推理节点打挂。
2. **状态**：10-15 披露，修复 PR **#41483 尚未合并**。也就是说，截至今天，主干上**没有任何已发布的修复**。
3. **缓解**：官方修复落地前，生产侧必须**限制端口暴露 + 强制 API 鉴权**挡在前面。

**可执行结论**：如果你在公网或不可信网络暴露 SGLang，请**现在就确认**网关层有鉴权、且推理端口不直连外网。这不是"等下个 tag"能解决的问题——窗口期里你只能靠自己的边界防御。

> 值得单独说的一点：这类"**披露先于修复**"的窗口，对推理服务比训练服务更危险——推理节点直接面向请求，攻击面大、重启代价高。把"出 CVE 时的临时边界策略"写成 runbook，比事后救火划算得多。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：近 72h **两框架均无新 tag**。vLLM **v0.32.0** 稳定（10-18）+ **v0.32.1rc0**（含 RL HTTP 权重传输 #62267）；SGLang **v0.5.22** Latest（10-19），仍无 v0.5.23。

### vLLM v0.32.0 / v0.32.1rc0

**新特性（国产硬件）**：vLLM-Ascend 分支活跃——异步调度稳定、MTP 稳定（1/2/3 token）、suffix 投机（招商银行落地）、W4A4/W8A8、实验性 **Mooncake 连接器 + KV 池 + xlite**，移除 LLMdatadist。影响：昇腾链统一收敛到 Mooncake。

**重要 PR**：**/v1/systemone 决策端点（#59299）**将 agentic 路由判定移入引擎内，跳过二次 prefill、前缀 100% 命中。影响：agentic 路由延迟下降——这类"判定进引擎"的改造，正是推理引擎从"算子运行时"向"调度运行时"演进的又一信号。

**基准**：GB300 NVL72 **P/D 分离 + Wide-EP** 跑到 **954K tok/s/GPU**；MiniMax M3 AgentX **7.8× GB200**。影响：vLLM 在超大集群上追平 DeepInfer。

### SGLang v0.5.22

**性能**：**弹性 EP 热扩容**（10-23 LMSYS，已合主干）——EP4→EP8 在线无停机，扩容代价 **5.3–8.2× 于停机重启**。影响：MoE 流量波动时可按需扩算力、降本。

**已知坑（见 ★ 部分）**：**CVE-2026-110809 会话替换 DoS**（PR #41483 未合并），`replace=true` 缺 `rid` 触发 SIGQUIT 崩溃 → 生产需端口限制 + API 鉴权缓解。

**投机**：DFlash/DSpark 成熟——Muse Spark Open DFlash V2（MI355X 3.7×@1 / 2.9×@16）、Liquid LFM2.5 DSpark（B300 2.38×@1 / 1.71×@256）。影响：已成多模型默认投机栈，但高并发衰减明显。

### 原理：负载感知的投机解码长度控制（drafters-under-load）

本期最值得动手调参的一条技术解读——尤其对 DFlash/DSpark 部署。

**现象**：EAGLE-4 / DFlash / DSpark 在 **batch=1** 时收益 **2.6–3.6×**，但当并发升到 **512**，反而**低于 vanilla**（14.2K / 16.6K vs 21.2K tok/s）。原因：批处理下 GPU 本就 compute-busy，验证开销变成净竞争。

**定量**：Liquid DSpark 在 256 并发只剩 **1.71×**（衰减）；Meta Muse Spark Open 据此**写死草稿 7 token**（suffix decay：接受率 token1 87.5% → token6 39.5%）。

**落地结论**：**DFlash/DSpark 部署必须接负载感知控制器，动态调草稿长度**——否则高并发反而变慢。这对 OpenInfer / DFlash / DSpark 是直接调参信号：别把草稿长度当常量。

> 我的判断：投机解码正在过"蜜月期"。单用户时代它稳赚，但进入生产的高并发世界后，"是否投机、投机几 token"本身成了一个需要在线决策的问题。下一步的竞争点，会从"谁的草稿器快"转向"谁能在负载下把草稿长度控制对"。

### 常驻专题

**PD 分离**：vLLM push-NIXL（双向 KV + GQA 分片 + sleep）/ SGLang KVShard + 弹性 EP 热扩容（Mooncake PG + NIXL A2A）/ llm-d 1.0 路由层；GPUStack 固化 vllm-nixl / sglang-mooncake(preferred) / sglang-nixl。

**架构演进**：负载感知草稿长度 + DFlash/DSpark 块验证 + MTP + 低精度 KV（NVFP4/MXFP4/FP8）+ SGLang Low-Latency megakernel + DeepInfer SWA Bounded Replay。

**PyTorch vs transformers**：nano-infer / Shrike / NanoInfer 纯 PyTorch 自研（教学 / 学内核），代价是自实现 tokenizer / 权重加载 / 并行；横向看仍是以生产框架 + transformers 作格式桥。

**Step 适配**：
- Step 5 Preview（10-15，600B/27B、1M、BF16+FP8）窗口内无新权重，OpenRouter 周/日 Token 全球第二；双框架 day-0/1 成熟。
- 社区部署：vcruz305 非官方 GGUF（IQ1_S ~111GiB / Q2_K ~202GiB）；sybil-solutions EXL3 混合（341.4GB）4×DGX Spark 实测 **25–30 tok/s、4 并发 66.5 tok/s**。
- 局限：llama.cpp 回落 dense attention，1M 上下文不实用，vision/MTP 无 runtime；真多模态 + 1M 仍走官方 vLLM/SGLang。

> Step 5 社区低位元量化（GGUF/EXL3）正在"涌现"，但 llama.cpp 这条线受限于 dense attention 和缺 runtime，1M 与多模态还得回官方框架。小集群能实测，但属早期方案——别把它当成生产默认路径。

## 三、AI 论文与产业热点

本期论文与产业日报正常产出，以下为精选。

### 论文核心：InstructGPT 的 RLHF 三阶段

**InstructGPT**（OpenAI, arXiv:2203.02155, 2022）——把 GPT-3 从"文字接龙"变成"听指令的助手"，ChatGPT 直系前身。

- **三阶段**：① 标注员演示做 **SFT** 定行为基线；② 排序比较训练 **6B 奖励模型**（Bradley-Terry pairwise loss，排序比打分可靠）；③ **PPO + 逐 token KL 惩罚（β=0.02）**防 reward hacking，PPO-ptx 防能力遗忘。
- **影响**：**1.3B InstructGPT 人类评估胜过 175B GPT-3（约 135× 参数效率）**；对未见 prompt 泛化；定义对话模型默认训练范式，是 DPO/GRPO 谱系起点。具身延伸：RoboBrain GRPO-RFT、π*0.6 advantage 条件化。

> 这条"回归对齐源头"的复盘值得常读：今天所有 DPO/GRPO 的繁茂，都从"排序比打分更可靠 + KL 惩罚防跑偏"这两个朴素判断里长出来。参数效率那条（1.3B > 175B）至今仍是小模型对齐最有说服力的证据之一。

### 算子讲解：DSpark 置信度调度 + 半自回归草稿（DeepSeek×北大, arXiv:2607.05147）

- **定位**：并行草稿（DFlash）块内 token 无依赖 → 后缀接受率衰减；DSpark 用 **Markov 低秩 logit bias（rank=256）**补依赖 + **BCE 置信度头**预测存活概率 + **硬件感知前缀调度**动态定验证长度。
- **在用模型**：DeepSeek-V4-Flash（单用户 +60~85%）、V4-Pro（+57~78%）、Qwen3 全系（接受长度较 EAGLE-3 +26.7~30.9%）；vLLM speculators 内置、GLM-5.2 speculator 预览。
- **关键点**：线上验证 5 → 3.2~4.4（-30%）吞吐 +6%；2 层超 5 层 DFlash；DeepSpec MIT 全栈开源。

### 性能优化：SWA Bounded Replay 滑窗有界重放（DeepSeek V4.1-Flash / DeepInfer）

- **定位**：CED 架构解码器缺 prompt 局部 SWA 状态，精确重建需尾部 2560 token×20 层；**只重放最近 128 token**，固定成本与上下文长度无关。
- **收益**：token 缩减 **20×**、prefill 近半、持久 KV 足迹 = V4-Flash 的 **1/8**、全局 KV **890 B/token**（V1 的 1/437）。SWA KV 放 host DRAM 短 TTL 不写 SSD，全局 KV 持久 ≥72h + FP4。
