## ★ 今日最值得关注

**vLLM 在"压成本"上又往前走一步，SGLang 在"曝风险"上原地不动。**

同一天同一帧里，两条线的反差最值得你今天动手处理：

1. **vLLM**：v0.33 进入 RC 收尾，今日发 **v0.33.0rc1**；主线 **NVFP4 4-bit KV** 把长上下文同卡容量压到约 **1/4**（实测 MiniMax M3.1 Flash 4×B300 @256K 并发序列 28→76，约 **2.7×**；每 token KV 61,440→34,560 字节，**-43.75%**）。
2. **SGLang**：最新仍是 **v0.5.22（10-19）**，窗口内无 v0.5.23；更关键的是它仍背着 **CVE-2026-111391**——`dumper _evaluate_filter()` 用 `eval` 直接造成 **RCE（CVSS 9.2 v4 / 8.1 v3）**，影响 **0.5.10–0.5.22**，多家核验 **至今无确认修复版**。

**可执行结论**：要跑 SGLang 且开了 Dumper 的，**立刻 `unset DUMPER_SERVER_PORT` 并封掉公网 `/dumper/configure`**（跟踪 issue #44188）；要上 NVFP4 长上下文的，优先 vLLM v0.33 主线——这一轮 SGLang 在"把活做完"上明显落后。

> 值得单独说的一点：SGLang 已经 **10 天没出新版本**，却顶着一个 CVSS 9.2 的未修 RCE；vLLM 则在 RC 里持续把低精度 KV 路线落地。两框架低精度 KV 路线趋同（都奔 NVFP4 ~4× 密度），但"SGLang 把 KV 显式暴露给外部 router、vLLM 走 MRV2 内置"的架构分歧，正让两端在可靠性和攻击面上的差距拉大。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：vLLM 稳定 **v0.32.0（10-18）** + RC **v0.32.1rc0**，今日新增 **v0.33.0rc1**；SGLang 仍 **v0.5.22（10-19）** Latest，最近可考 release 为 v0.5.21（10-01，779 PRs）。

### vLLM v0.33 RC

**新特性 / 性能**：

- 主线 **NVFP4 4-bit KV** + **MRV2（Elastic EP 在线扩缩容）** + **MiniMax M3.1 Flash day-0**，长上下文同卡容量约 **4×**。
- **push-NIXL 连接器**最高 **3× TTFT / 约 30% TPOT**；vLLM-Ascend 异步调度稳定、MTP 稳定 1/2/3 token。

**破坏性变更（升级前必读）**：

| 变更 | 影响 |
|---|---|
| **Python 3.10 弃用**（最低 3.11） | 旧环境需重做运行底座 |
| **transformers≥5.16.1、tokenizers≥0.23.2** | 自定义模型定义大概率要改 |
| **max_tokens 语义改「输出上限」** | 下游若当「总上限」用会算错 |
| **cascade attention / mamba_cache_mode="all" 移除** | 相关配置需迁移 |

> ⚠️ **小显存 / 自定义模型用户**：transformers 已进 v5（移除 TF/Flax、`apply_chat_template` 改返 `BatchEncoding`、`load_in_4bit/8bit` 移除）。版本漂移会咬人——**务必 pin `transformers==5.16.1+`**。生产用框架 + transformers 作格式桥，极致优化再走纯 PyTorch 自研内核（DeepInfer / nano-infer）。

### 原理：NVFP4 4-bit KV 怎么把密度翻 4×

**路径**：`vo_split` 把 512 宽头拆两次 256，逐层 **amax/6.0 标定** + `llm-compressor` + `compressed-tensors` 存盘，密度翻约 **4×**（含标度块约 **4.5 bit/token**）。

代价明确：**标定错则模型发散**（5090 误差可到 0.0047 量级）。这意味着 NVFP4 不是"开了就省"，而是"标定对了才省"——上线前必须拿真实负载复测 KV 精度。

## 三、AI 论文与产业热点

### 论文核心：FlowVLA（HKUST-GZ, arXiv:2508.18269）

给**下一帧预测插显式光流中间步 `v_t → f_t → v_t+1`**。三个要点：① 运动推理与外观生成解耦（治像素复制陷阱）；② 运动步直接监督 + 帧流交错因果链；③ 图/流共用 VQ-GAN tokenizer、动作用 FAST。

成绩：**LIBERO 88.1 / SimplerEnv 74.0 / 真机 44.0**，**1/3 步数到峰值、50% 数据 +55%**。影响：确立"中间表示显式 / 有监督 / 在因果链上"三准则，世界模型成为动作头的**物理先验引擎**。

### 算子讲解：DFlash 块扩散草稿（Z Lab, ICML 2026）

草稿侧从自回归换 **5 层块扩散**，一次前向并行出整块 + 目标模型隐藏态 KV 注入每层；**无损 >6×**、vs EAGLE-3 至多 2.5×；vLLM/SGLang 已集成，Qwen3.5/3.6/Kimi K2.5 草稿头可用。

### 性能优化：KV 驱逐算法（H2O / SnapKV）

"有些 KV 干脆不存"：**H2O** 重击者 + 滑窗（保留 20% 吞吐 29×）；**SnapKV** 观察窗 prefill 末锁定 KV 池（16K 生成 3.6× / 内存 8.2×）；推理型模型上 **SnapKV-Decoding** 最优。这与 NVFP4 4-bit KV 是"省 KV 内存"的两条互补路线。
