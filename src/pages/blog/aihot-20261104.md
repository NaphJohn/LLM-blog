## ★ 今日最值得关注

**前一天 PD 分离 5-CVE 风暴里最凶的那条 Dumper RCE，一天后仍未定论——修复 #44205 还只躺在 main，0.5.23 的 tag 早于它，各家口径还在打架。升 0.5.23 是必要但不充分条件。**

这是本期唯一一条"会直接把你的线上部署打穿"的问题，而且麻烦不在漏洞本身，而在**修复的可信度与可达性又僵了一天**。

三层事实：

1. **漏洞本体**：`Dumper` 的 `eval()` RCE，**CVE-2026-111391**，CVSS **9.2**。
2. **口径打架**：cybersecuretoday 称「**0.5.22+ 已修**」；Wiz / SentinelOne / VulnDB 仍把 **0.5.10–0.5.22** 列在受影响区间；而真正的修复 PR **#44205**（AST 求值器替换 `eval`）**只进了 main，没进 0.5.23 的 tag**。
3. **影响**：你以为昨天升到 0.5.23 就万事大吉，但那条 tag 早于修复——**升 0.5.23 ≠ 已修**。

**可执行结论**：跑 `Dumper` 或公网暴露的部署 → **升 0.5.23 + 必须 `unset DUMPER_SERVER_PORT`**，最稳妥是从 **main 构建**；别再只看版本号到 0.5.23 就勾掉。

> 值得单独说的一点：这已经是连续第二天「**官方/追踪器口径对不上**」的灰色地带。它印证了一条铁律——你的升级清单里必须有「**升级后独立复核 CVE 状态**」这一行，而不是看版本号到 0.5.23 就关工单。当修复 PR 落在 main 而你装的是 tag，版本号本身已经不能当安全凭证用了。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：**vLLM v0.33.0（11-02）仍是 latest stable，无新 tag**；**SGLang v0.5.23（11-02 发布 / tag 10-30）仍是 latest，无 v0.5.24**。发版次日，两边主线都转向「工程硬化」。

### vLLM v0.33.0（发版次日主线）

**工程硬化（破坏性，须留意）**：

- **CI 强制锁依赖 hash（不可变引用）**——升级须锁死依赖版本，漂移会被 CI 拒绝。
- **移除 QuTLASS / fp_quant，改跑 QuIP NVFP4 on Hummingbird**——量化后端有迁移成本，老量化配置需改。

**新特性**：

### SGLang v0.5.23

**安全（见 ★）**：CVE-2026-111391 各源口径仍不一致，修复 PR #44205 仅进 main → **升 0.5.23 + `unset DUMPER_SERVER_PORT`**，或直接从 main 构建。

**新特性**：

- 落地页新推 **Qwen3.8-Flash-Next**（Qwen4 预览，176B / 6B 活跃，SWA+Gated DeltaNet+MTP）、**MiniMax-H3**（视频 + 音频扩散）、**Kimi-K3**、**Inkling**（975B / 41B、1M、文本 + 图像 + 音频）cookbook。

### 原理：vLLM 的 DSpark 块扩散投机解码（Kimi-K3 day-0 实测）

本期最值得理解的一条技术解读——也是块扩散草稿成主线的硬证据。

**结构**：块扩散（block-diffusion）主干 + **低秩 Markov 修正头** + **硬件感知 confidence 头**；单步非因果主干一次提出 **8 token**，块级接受验证（`rejection_sample_method="block"`）。

**实测（GB300 NVL72）**：

- 单流数学推理 **110 → 435 tok/s（约 4×）**
- 并发下聚合吞吐最高 **3.5×**
- 9 域宏平均接受 **4.11 token/轮**（数学 6.42、HumanEval 4.96）

**代价**：需训 **5B / 5 层**草稿模型；**仅在采样配置有效**——greedy 下 block 验证失效。

> 我的判断：块扩散草稿正在从「概念」变成「可 day-0 落地的量化红利」。但 Kimi-K3 的 3.14× / 4× 数字背后有前提——它吃采样、吃专用草稿模型、吃 GB300 这类大机。把这条线搬到你自己的 7B/70B 上之前，先确认你愿意为草稿模型付出训练成本，以及你的服务是采样而非 greedy。

### 常驻专题

**PD 分离（llm-d 1.0 真实量化收益落地）**：IBM Research 用 llm-d 服务 **GLM-5.2（744B / 390B 活跃）**，每 token 成本比商业 API 低 **5–10×**、峰值 **>660 万 tok/分**、**3000 编码 agent 零抢占**；前缀缓存命中近 **98%**；250 并发分层 KV 卸载 **13.9×** 吞吐；**AWS SageMaker HyperPod +70% tok/s** vs 标准 vLLM。vLLM push-NIXL + SGLang KVShard / 弹性 EP 维持。

**架构演进**：低精度 KV（vLLM **NVFP4** / AMD **Octave 3-bit** + SGLang **Native NVFP4 Elastic EP**）+ DSpark / DFlash2 块扩散 + FLy / MTP + SGLang **Low-Latency megakernel**；**块扩散草稿成主线**。

## 三、AI 论文与产业热点（本期有来源）

### 论文核心

**Flamingo**（DeepMind，arXiv:2204.14198，NeurIPS 2022）——证明**冻结的 70B 语言模型 + 零初始化门控 + 1.5% 新参数**就能长出「眼睛」：冻结视觉塔 + 冻结 LM，只训 **Perceiver Resampler**（64 latent 定长压缩）与 **GATED XATTN-DENSE**（tanh(α) 门控、α 零初始化），约 1.5% 参数拿到 16 个多模态任务的 few-shot SOTA。核心思想：定长压缩让视觉成本与分辨率**解耦**；零初始化门控保证第 0 步与原 LM 等价、不训坏语言能力；逐图掩码让「训练少图、测试多图」可泛化。其 few-shot 能力其实是被**图文交错网页数据**喂出来的（去掉那一路掉 **17.3 分**）。影响：16 基准中 6 个超微调 SOTA、9 个 few-shot 基准全刷新（COCO CIDEr 84.3→113.8、VQAv2 56.3→67.6）；「冻结大件 + 训连接件」成 VLM 标准模板，Resampler / 门控注入沿用至今（Qwen-VL、Helix、VLA 视觉 token 预算）。

### 算子讲解

**GRPO**（arXiv:2402.03300）｜定位：删掉 PPO 的 critic，用同题 **G 条 rollout 的组内标准化**当优势（A_i=(r_i−mean)/std），KL 用 **k3 估计**直接进损失。在用模型：DeepSeekMath / V3.2 / V4 系 RL、Qwen 系后训练、TRL 默认 G=8、RoboBrain 2.0 的 GRPO-RFT。关键点：常驻模型 4→3、GSM8K 82.9→88.2 / MATH 46.8→51.7、R1-Zero AIME 15.6→71.0；坑 = **全对 / 全错组优势归零**、KL 不可折入 reward。

### 性能优化

**ZeRO++**（arXiv:2306.10209）｜定位：ZeRO-3 通信 **3M** 太贵，用 **qwZ（INT8 权重）+ hpZ（节点内副本，跨节点 all-gather 归零）+ qgZ（INT4 梯度、先节点内 reduce 再跨节点、到达后全精度累加）**压到 **0.75M**。代表收益：384 卡 GPT-3 级 **45%+ 峰值算力**、最高 **2.16×**（10–138B 区间 2.4×）、低带宽集群追平 4× 带宽；MixZ++ LoRA **3.3×**。具身关联 = 多厂区低带宽集群的 VLA 分布式微调。
