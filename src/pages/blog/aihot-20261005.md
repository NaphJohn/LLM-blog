## ★ 今日最值得关注

**近 24h 无新正式版本，窗口级主线（SGLang v0.5.21 / vLLM 0.31 线 MRV2 默认化）已在上轮详列；本期主轴是 vLLM 把「HiSparse+MTP+FULL 图」静默 KV 污染的关键修复落地 rc4、rc5 锁 transformers 版本上限，SGLang 仍坐 v0.5.21 但 main 在 PD 弹性与硬件拓宽上密集提交，Step 5 Preview 距 10-15 开源仅 10 天。其中最硬的一条：vLLM v0.31.0rc4 修的 #56158 是「稀疏注意力+投机解码+CUDA 图」三件套叠在一起才会触发的静默乱码——跑这类组合必须升级，否则高并发长上下文会悄悄吐错答案。**

三层事实：

1. **版本与安全落地**：**vLLM v0.31.0rc4（#56158）修复 HiSparse+MTP+FULL CUDA 图下 host KV 镜像未同步导致的静默生成污染**——FULL 图回放绕过 Python 路径的每步重建，新写 KV 未拷回 host，溢出读取到未写入数据；GLM-5.3 16×H200 @1024 并发、约 13.9k 上下文复现。同一线 **rc5（#59614）给 transformers 加版本上限**，印证「保留并锁版本 transformers 后端路径」。稳定锚仍是 **v0.30.0**。
2. **SGLang 与 Step 倒计时**：**SGLang 仍坐 v0.5.21（10-01，779 PRs / 227 贡献者）**，近 72h 无 v0.5.22；main 在 **#41691（10-05）NIXL peer 失效后重载元数据**（PD 生产弹性 + 自愈）与 Apple Silicon MPS 标准测试、CUDA PyTorch 栈升 2.14、sgl-router KV 事件前记账上密集提交。**Step 5 Preview 开源倒计时 10 天（10-15）**，社区 HF 镜像已 day-0，Step-3.7-Flash 双框架成熟仍为生产主力。
3. **论文信号**：**DexVLA（arXiv:2502.05855）把 1B 扩散动作专家从 VLM 解耦**，三阶段课程学习覆盖单臂/双手/灵巧手、可叠衣服等长程任务，优于 Octo/OpenVLA/Diffusion Policy；配套 **Symmetric Memory（Mooncake）零拷贝 KV 池（TTFT 降 2–22×）** 与 **Tile 级 Kernel 融合（HBM traffic 降 2–5×）** 两张工程底牌。

**可执行结论**：部署「稀疏注意力 + 投机解码 + CUDA 图」任一组合，**先升到含 #56158 的 rc4+**，并做长上下文高并发回归、盯投机接受率异常下跌；SGLang 生产继续锁 **v0.5.21**；Step 5 权重 10-15 落地后用 `--reasoning-parser stepfun` 双框架直接跑。

> 值得强调：#56158 的根因是「HiSparse 每步在 Python eager 路径清空 per-batch host 镜像元数据，但 FULL 图回放跳过了这步准备」，属于「调度/缓存热路径去 Python」趋势里的一个反面教材——一旦把准备动作藏进图回放，正确性就靠守卫兜着。vLLM 0.31 的 MRV2 默认化 + 移除 PagedAttention 正是一路把这类簿记迁到 GPU-Native/Triton，方向一致；今天这枚 bug 提醒：迁移途中旧路径仍会在图回放里咬人。

### 原理：vLLM #56158——「HiSparse+MTP+FULL 图」静默乱码根因与修复（图回放绕过的正确性坑）

- **根因**：HiSparse 每步在 **Python eager 路径清空 per-batch host 镜像元数据**，FULL 图回放**绕过该准备** → 新写 KV 未拷到 host → 溢出读取到**未写入数据** → 静默乱码。复现：GLM-5.3 16×H200 @1024 并发，约 **13.9k 上下文**触发。
- **修复**：`run_fullgraph()` 前**重建镜像状态 + 守卫**；部署稀疏注意力/投机解码须做**长上下文高并发回归**，盯**投机接受率异常下跌**。

> 我的判断：这是「调度/缓存热路径去 Python」趋势里的典型案例——簿记一旦进图回放就脱离 Python 守卫，正确性只能靠显式重建 + 守卫兜着。vLLM 0.31 把 MRV2 设默认 + 移除 PagedAttention，正是把这类簿记迁到 GPU-Native/Triton 的彻底解法；迁移途中旧路径（FULL 图）仍会在长上下文高并发下咬人，所以 rc4 的修复优先级高于功能增量。

### 常驻专题

**PD 分离**：SGLang **#41691 peer 失效重载元数据 + #40703 prefill-complete decode KV 分配**；vLLM 0.31 修 **HiSparse 正确性（#56158）**——走向**可验证、可弹性、可自愈**。

**架构演进**：vLLM **MRV2 默认化 + 移除 PagedAttention + HiSparse 修复**；SGLang **Rust 前缀缓存 + 候选打分 + 混合 SWA 池 KV 尺寸调整 + Apple Silicon（MPS 标准测试）**。

**PyTorch vs transformers**：无脱离 PR；vLLM rc5 加 **transformers 版本上限**、SGLang 升 **5.17.0**——模型层收敛 transformers、性能层留引擎 kernel，边界重分层结论维持。

## 三、AI 论文与产业热点

### 今日重点（1 句）

**DexVLA 用「可插拔扩散动作专家」把 VLA 推进到五指灵巧手与长程叠衣操作，配套 Symmetric Memory 零拷贝 KV 池与 Tile 级 Kernel 融合两张工程底牌降本提效，具身产业热点聚焦量产交付与估值分化（FieldAI 拟百亿估值融资、优必选出货目标上调、宇树被小摩首予低配、小鹏机器人融资 9 亿美元、波士顿动力 Atlas 计划部署 2.5 万台）。**

### 论文核心（DexVLA · arXiv:2502.05855）

- **一句话定位**：把 **1B 扩散动作专家从 VLM 解耦**，VLM 管感知/语义、扩散专家管灵巧手细粒度动作，互不绑架。
- **核心做法**：**三阶段课程学习**（跨本体预训练 → VLA 对齐 → 任务后训练），覆盖单臂/双手/**五指灵巧手**，可完成叠衣服等**长程操作**，优于 Octo / OpenVLA / Diffusion Policy。
- **影响**：动作生成能力成为具身智能下一瓶颈，**灵巧手供应链（减速器/电机/传感器）**直接受益。

### 算子讲解：Symmetric Memory（Mooncake 对称内存）

- **定位**：PD 分离下的**共享 KV 内存池**，Prefill/Decode 之间 **零拷贝读写**，支撑 DeepSeek V4 / Kimi K3 / vLLM 0.22+ 长上下文服务。
- **意义**：把 KV 从「每副本各自占有」变「跨角色共享」，Prefill 写完 Decode 直接读，**TTFT 可降 2–22×**；与本人 OpenInfer/DFlash/DSpark 同属「KV 池化 + 跨节点零拷贝」大方向。

### 性能优化：Tile 级 Kernel 融合

- **定位**：把 **GEMM → bias → activation → norm → residual** 合并为单 kernel，**HBM traffic 降 2–5×**；代表工作 FlashAttention / CUTLASS / SGLang JIT / CuTile。
- **意义**：对**端侧 VLA 降时延**至关重要——灵巧手控制要高频低延迟，融合 kernel 把多次显存往返压成一次，是端侧落地的硬门槛。

### 产业热点（具身公司 / 产业链速递 · 置顶）

- **【具身】FieldAI**：拟融资 **7 亿美元、估值 100 亿美元**；**【具身】优必选 09880.HK**：被 JPM 上调 **Walker S 出货目标至 5,000–20,000 台**；**【具身】宇树 688836**：被小摩**首予「低配」、目标价 300 元**；**【具身】小鹏机器人 09868**：融资 **9 亿美元**；**【具身】波士顿动力 Atlas**：计划部署 **2.5 万台**。
