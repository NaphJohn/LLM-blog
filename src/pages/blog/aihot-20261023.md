## ★ 今日最值得关注

**本期最关键的一条是 vLLM 的 push-based NIXL KV 传输（社区 10-19 起广泛传播，已合入 main）把 PD 分离 TTFT 拉到最高 3×、TPOT ~30%，配合 10-22 合入的「P/D disagg KV block leak 修复」，PD 分离在 vLLM 侧从「实验特性」走向生产可落地——而同一窗口 SGLang 主线在 DFlash/DSpark 上做细活（block verification #42987、DSpark markov 重构 #43620–43790），论文侧 DeepSeek-V4.1-Flash 用因果编码器-解码器把全局 KV 压到 890 B/token，产业面特斯拉 Optimus 弗里蒙特进初期爬坡、工信部称全年人形产量预计破 10 万台。**

三层事实：

1. **PD 分离从实验到生产（vLLM push-NIXL + KV 漏块修复）**：push-based NIXL KV 传输（= decode 分配时即向 prefill 注册目标块、prefill 算完 KV 后立即后台线程推，去掉 pull 模式 router 转发→decode 分配→NIXL READ 的串行往返）在 Qwen3-32B 1P1D P5en+EFA 实测最高 3× TTFT（1744→540ms @8QPS/16k）、TPOT 10.4→7ms；10-22 合入的 KV block leak 容错修复让开了容错的 PD 生产部署不再漏块。
2. **版本与安全（一稳一进）**：vLLM 稳定仍 v0.32.0（10-18）+ RC v0.32.1rc0（10-18，仅文档化 RL HTTP 权重传输 #62267），近 72h 无新 tag；SGLang 稳定 v0.5.22（10-19，950 PRs / 245 贡献者）仍 Latest，近 72h 无新 tag。安全债延续：CVE-2026-111391（Dumper RCE，0.5.10–0.5.22，CVSS 8.1）仍无修复版 → 生产务必关 Dumper。
3. **论文信号**：DeepSeek-V4.1-Flash（因果编码器-解码器，MIT，552B backbone + 196B Engram，1M 上下文）把 40 层切成 20 层因果编码器 + 20 层解码器，prefill 只激活 8B、decode 才用 16B，全局 KV 890 B/token（V4-Flash 的 1/4、V1 的 1/437，1M 上下文仅 0.83 GB）——「按负载分配容量」成为 Transformer 之外的新设计维度。

**可执行结论**：想上 PD 分离的团队现在可以把 vLLM push-NIXL 拉起来试（长 prompt 8k+ + 高并发 + RDMA 直接可试），但记住它只降时延不增吞吐，且最坏情况关了前缀缓存；生产仍锁 v0.32.0 / v0.5.22，SGLang 侧把 Dumper 端点彻底关掉。DeepSeek-V4.1-Flash 的 CED 范式（CSA2 三模式 + 跨层共享 KV）直接启示本人 LLM/推理路线——长上下文成本曲线被「读多写少」重新定义。

> 值得强调：本期没有新版本号，但 vLLM 把 PD 分离从「能跑」推到「敢上生产」（push-NIXL + KV 漏块修复），SGLang 则在投机解码（DFlash block verification / DSpark markov 重构）上静水深流——两边都把增量压在「PD 弹性 + 投机可分离」这条主轴。论文侧 DeepSeek-V4.1-Flash 把「激活参数 / KV 容量按负载分配」写进架构，和本人 DFlash/DSpark 的块级调度是同一哲学。

- **安全（务必处理）**：CVE-2026-111391（Dumper 表达式求值注入，0.5.10–0.5.22，CVSS 8.1）仍无修复版 → 生产务必关 Dumper。

### 原理：vLLM push-based NIXL KV 传输——把「串行往返」从关键路径上拿掉

- **做法**：pull 模式下，router 转发 → decode 分配块 → NIXL READ 是串行的；push 模式把「decode 分配时即向 prefill 注册目标块」提前，prefill 算完 KV 后立即由后台线程推过去，decode 不再等那一轮往返。
- **实测**：1P1D P5en+EFA Qwen3-32B 最高 3× TTFT（1744→540ms @8QPS/16k）、~30% TPOT（10.4→7ms）。
- **边界**：仅降时延不增吞吐；需长 prompt（8k+）+ 高并发 + RDMA；最坏情况关了前缀缓存——意味着它和前缀命中是互斥优化，部署前要先想清楚负载画像。

> 我的判断：本期版本号一稳一进（vLLM 锁 v0.32.0、SGLang 守 v0.5.22 Latest），增量集中在「PD 分离弹性（vLLM push-NIXL + KV 漏块修复）+ 投机解码（SGLang DFlash block verification / DSpark markov 重构）」。量化（FP8/MXFP4/NVFP4）与 DeepSeek-V4.1 FlashMLA 稀疏 prefill 持续把压力压到内核层。push-NIXL 的「去串行往返」和 MRV2「剥离 Python 热路径」同源——都是把非 LLM 瓶颈从关键路径上隔离出去。SGLang 950 PRs 仍是窗口内体量最大的单版本，但本期安静地做投机解码的细活。

## 三、AI 论文与产业热点

### 今日重点（1 句）

**DeepSeek-V4.1-Flash 用「因果编码器-解码器」把 prefill 与 decode 拆成两种负载（8B / 16B 不对称激活），把全局 KV 压到 890 B/token —— 这不是省显存的小技巧，而是把「机器人是极端读多写少的 AI 用户」这件事写进了网络拓扑。**

### 论文核心（DeepSeek-V4.1-Flash · Causal Encoder-Decoder）

- **一句话定位**：40 层切成 20 层因果编码器 + 20 层解码器，prefill 只激活 8B、decode 才用 16B——把「按负载分配容量」做成架构级的硬约束。
- **核心思想（3 行）**：
  1. 解码器的全局 KV 只从编码器最终隐状态**投影一次**、20 层共享，不再逐层自建；
  2. **CSA2** 给每层静态指定 Full/Reindex/Reuse 三模式，主 KV 与 Top-K 索引跨层复用，分层索引让深层成本与上下文长度解耦；
  3. **SWA Bounded Replay** 只重放最近 128 token，把重算代价钉成常数。
- **结果 / 影响**：全局 KV **890 B/token** = V4-Flash 的 1/4、V1 的 1/437，1M 上下文仅 0.83 GB；「按负载分配容量」成为 Transformer 之外的新设计维度——直接呼应本人 DFlash/DSpark 的块级 KV 调度。

### 算子讲解：FP4 / MXFP4 块浮点量化

- **定位**：把权重/KV 压到 4 bit，在 Blackwell 张量核上 GEMM 与带宽同时翻倍，靠块级浮点缩放补回动态范围（E2M1 元素 + 每 16 元素一个 E4M3 scale）。
- **在用模型**：DeepSeek V4.1-Flash（主 KV，每 16 通道一个 E4M3 scale）、DeepInfer/DeepGEMM、NVIDIA Blackwell（MXFP4/NVFP4 硬件级）、Qwen3 系端侧 Flash 版。
- **关键点**：有效位宽 4+8/B（B=16 → 4.5 bit），实测压缩率 56.2% 而非 50%；与 INT4 per-group 的根本区别是 scale 本身为浮点，可自适应极端量程。

### 性能优化：KV Cache 跨层共享（Layer-Shared KV）

- **定位**：decode 是 memory-bound，每步要读所有层的 KV；让相邻层共用一份，把「读 KV 的层数」从 L 降到 f（gain=L/f）。
- **代表工作**：CSA2 三模式 + 分层索引（V4.1-Flash）；**MLIPS**（arXiv:2610.27438，1.14–1.40×、GPU 能耗 −14.8~−27.4%）；**MOSAIC**（arXiv:2607.09029，prefill 1.76× / decode 2.54×）。
- **收益**：与 FP4、SWA 不落盘乘性叠加，才凑出 1/4 的 KV 成本；索引共享过深会掉任务精度。

### 产业热点（具身速递 · 置顶）

- **【具身①】特斯拉 Optimus**：弗里蒙特进初期爬坡（首线年产能 100 万台，对外交付 2027 底）→ 利好 002050（三花）/ 601689（拓普）；
- **【具身②】宇树 / 智元 / 小鹏**：宇树（688836）H2-X 发布 + 三大布局；智元七日七项成果、开源首个真实场景 Physical Agent 数据集（→ 688585）；小鹏 IRON 0.2s 重推理、预判 6 秒（→ 09660）；
