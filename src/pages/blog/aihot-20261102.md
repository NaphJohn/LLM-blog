## ★ 今日最值得关注

**SGLang × Cloudflare 协同披露了一起 PD 分离下的真实跨请求 KV 缓存泄露事故——不是 PoC，是真有 155 个响应泄露了别人的 KV。而那个 CVSS 9.2 的 Dumper RCE 还没闭环。**

这是本期唯一一条"会直接把别人会话的 KV 吐给你的请求"的问题，而且它和 9 月、10 月那几次一样——危险不在漏洞本身，而在**修复的可得性**。

四层事实：

1. **事故本体**：Cloudflare 上下文窗口 **1,048,576 tokens**，但 prefill KV 池只有 **681,280**。SGLang 在 PD 模式下准入只判断 `finished()`、不看 `rejected`，被拒请求仍被误准入；prefill 只算 1 token 占位符就标记"传输完成"，decode 却读满预留的 8 页——其中 1–7 页残留的是**别人的 KV**。事故窗口 **08-27 → 09-09**，**155 个响应受影响**。
2. **修复**：SGLang **v0.5.23**（10-30 Stable）含 PD 健壮性修复 **#45973**，以及跨请求 KV 隔离 **#36988 / #38935**（拒绝请求在 bootstrap/分配/KV 传输前终止；decode 校验传输 token 数 == 预留数）。
3. **缓解（现在就能做）**：升级 **v0.5.22+** 并启用 **`--disaggregation-enable-kv-checksum`** / **`--kv-canary`**，对 KV 做完整性校验 + 金丝雀探测。
4. **高危同伴 · Dumper RCE（CVE-2026-111391, CVSS 9.2）**：影响 **0.5.10–0.5.22** 全部可装版本，修复 PR **#44205**（AST 求值器替换 `eval()`）已合 main，但各源对其是否进 v0.5.23 说法不一；缓解 = `unset DUMPER_SERVER_PORT` + 独立 `admin_api_key` + 封 `/dumper/configure`。

**可执行结论**：只要你在跑 **PD 分离 + KV 传输后端**，请求隔离与 KV 完整性校验就是**必选项**，不是可选项。

> 值得单独说的一点：本周两框架无新重大功能发版，主线是"**安全 + 稳定收敛**"。KV 缓存从"性能优化对象"变成"一等安全对象"——这意味着你的威胁模型里必须加一条：PD 模式下，KV 传输通道本身就是一个需要校验、需要隔离、需要审计的攻击面。

### 原理：PD 分离下跨请求 KV 泄露的根因

本期最值得理解的一条工程复盘——它把"PD 分离怎么漏"从黑话讲成了可复现的事故。

**根因链**：

1. **池子不够大**：Cloudflare 上下文 **1,048,576 tokens**，prefill KV 池仅 **681,280**——注定有请求排不进完整的预留。
2. **准入判据有洞**：PD 模式下 SGLang 准入只看 `finished()` 而非 `rejected`；被拒请求存进 `to_finish`，使其 `finished()` 仍为 False，于是被**误准入**了本该终止的请求。
3. **占位符骗过传输**：prefill 只算 **1 token 占位符**就标记"传输完成"并发 1 页 KV；decode 却按预留读满 **8 页**，其中 **1–7 页残留他人 KV** → 泄露。

**修复两刀**：① 被拒请求在 bootstrap / 分配 / KV 传输**之前**就终止（#36988/#38935）；② decode 端校验 **传输 token 数 == 预留数**，对不上就拒绝。

> 我的判断：这条根因链是典型的"优化假设撞上边界条件"——为了多并发而做的预留 + 占位符优化，在池子告急时被准入判据的漏洞放大成了跨请求泄露。它再次印证：**任何跨实例共享 KV 的架构，请求隔离与 KV 完整性校验都不是锦上添花，而是地基。**

### 论文核心：RoboCat（DeepMind, arXiv:2306.11709, 2023-06）

**一句话定位**：会"自己攒数据"的机器人基础模型——把机器人学习从**纯监督**变成**自我改进的数据飞轮**。

**核心思想**：① Gato 1.18B 多模态 decoder-only，图像 16×16 patch + 动作 256 bin 离散化，全序列 next-token；② **数据飞轮**：新任务 100 条演示微调衍生模型 → 真机自采 **10,000 条轨迹**（成败同权）→ 回灌从零重训下一代，共 **4 代**；③ **未见任务成功率 36% → 74%**，跨 4 种两爪臂 + 未见三指夹爪。

**影响**：Gato → RoboCat → RT-2/VLA 谱系的"**数据从哪来**"答案；π₀/RECAP/Skild S1/GR00T 数据管线共同祖先；投资含义 = **真机数据闭环是本体之外的第二护城河**。

> 这条和本期推理侧遥相呼应：引擎侧在把 KV 当安全对象严防死守，机器人侧却把"数据闭环"当成护城河——**两边都把"循环"做成了核心资产，只是一个是防守循环，一个是生长循环。**

### 算子讲解：KTO（Kahneman-Tversky Optimization, ICML 2024 最佳论文）

**定位**：把孤立的 👍/👎 二元反馈直接变成对齐损失——**免配对、免 RM、免采样**。

**在用模型**：Zephyr / Tülu 3 / 各开源对齐管线；真机日志的成败 episode 天然不成对，KTO 形态天然贴合具身数据。

**关键点**：`r_θ = Σ_t log(π_θ/π_ref)`，锚点 `z_0 ≈ (1/2)·KL(π_ref‖π_θ)` 须 **detach**；非对称 **λ_U=1.33 > λ_D=1.0**（前景理论损失厌恶）；正负 **9:1** 悬殊时比 DPO 更稳。

### 性能优化：抢占与优先级调度（vLLM RECOMPUTE/SWAP + V1 优先级 + SGLang SLO-aware）

**定位**：KV 块池有限 + 请求价值不均时的调度层解法。

**代表工作**：vLLM（RECOMPUTE 默认 ≈ 1× prefill 重算）、SGLang；与 Prefix Caching / PD 分离**正交叠加**。

**收益**：高优 P99 TTFT 可控、集群利用率提升；**坑 = 抢占风暴需准入控制兜底**。
