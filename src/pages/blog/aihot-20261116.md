## ★ 今日最值得关注

**vLLM v0.34.0rc3 修好了 Kimi-K3 DSpark 的启动 OOM——但同一个 RC 里，显存默认值也被悄悄改了。删 workaround 之前，先看清你的部署方式。**

这是今天唯一一条"能让你立刻改配置"的修复，麻烦不在修复本身，而在它和一处破坏性变更**同时**到达。

三层事实：

1. **症状**：Kimi-K3 DSpark 在 **TP4 / 4×B200** 上启动期 **3/3 CUDA OOM**，此前只能靠 `gpu_memory_utilization=0.90` 这类 workaround 挤显存。
2. **修复**：PR **#67485**（11-13）修好启动期显存分配，**3/3 OOM → 6/6 启动成功**，每卡回收约 **9 GiB** KV 空间 → workaround 可以删了。
3. **但**：**rc2 起大多数场景不再默认设置 `gpu_memory_utilization`**（原默认约 0.9）。Python API 部署若原先依赖默认值，现在需**显式传参**，否则容量行为会变。同时 **PR #67035 移除 TeleChat2/3**，v0.34.0 为最后支持版，TeleChat 必须 pin。

**可执行结论**：K3.1 Pro 仍需 nightly（稳定版 v0.33.0 只含 K3 代码）；RC 可做回归，但别上生产。升级时显式设置显存参数、重测容量，不要依赖默认值。

> 值得单独说的一点：**修复和破坏性变更同处一个 RC**，是升级最容易翻车的组合——你把 workaround 删了，默认值却也变了，等于同时动了两处跟容量相关的配置。这种版本要当成"迁移"而不是"更新"来对待。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：周末两框架**均无新稳定版**。vLLM 稳定版仍 **v0.33.0**，**v0.34.0 推进到 rc3**（11-13）；SGLang tag 仍 **v0.5.23**，但已官宣 **v1.0** 里程碑并开放稳定性 tracker。

### vLLM v0.34.0 RC

**新特性 / 重要 PR**：

- **rc0：Gemma / StableLM 迁回 Transformers 后端**——收编上游定义、降维护成本，代价是融合算子短期回归。
- **rc1：XPU 投机解码 NaN 修复**——`greedy_argmax` 把 NaN 当 `-inf` 处理，修了跨硬件乱码风险。
- **rc3 / PR #67485：启动期 CUDA OOM 修复**——Kimi-K3 DSpark TP4 在 4×B200 从 3/3 OOM → 6/6 启动，每卡回收约 9 GiB KV（见 ★）。

**破坏性变更**：

| 变更 | PR | 影响 |
|---|---|---|
| **rc2 起大多数场景不再默认设 `gpu_memory_utilization`**（原约 0.9） | — | Python API 部署需显式传参 |
| **移除 TeleChat2 / 3** | #67035 | v0.34.0 为最后支持版，须 pin |

**性能**：**DeepSeek-V4.1 DeepGEMM 预热只编译可达 kernel**，GB200 上 **68.4s → 11.2s**——弹性扩缩容冷启动更快，对按请求计费的推理服务尤其值钱。

> ⚠️ **小显存 / 依赖默认值的**：这一版同时动了显存分配逻辑和默认值，两件事都会改变你的显存峰值。升级后按"迁移"流程重测容量。

### SGLang（v1.0 官宣 / tag v0.5.23）

**里程碑 / 待 tag**：**v1.0 稳定性 tracker 11-12 开放**，核心特性冻结；**无效配置由静默覆盖改为启动报错 / 4xx**；弃用 `sgl-model-gateway` → `sgl-router`。但 GitHub tag 仍停在 **v0.5.23**。

**峰会生态**：首届 Summit（11/12–13）发布 **v1.0 + Miles v0.2**，官方称 **330+ 机构采用、首日 217 个模型**——多为 v0.5.x 既有能力整合包装，等 notes 核实。

**安全提醒**：**CVE-2026-111391（CVSS 9.2）仍无补丁版**——临时处置：关 dumper 端口 + 设 admin key。

> "无效配置从静默覆盖改成启动报错"这条，比 v1.0 三个字重要得多：它意味着升级后原本被悄悄吞掉的错误参数会直接**启动失败**。现在就该把启动参数审计一遍。

### 原理：Evolving Infra 的对称服务引擎

本期最值得理解的一条技术解读，也是本周最硬核的进展。

**痛点**：传统 PD 分离做角色切换（P↔D）要重启实例、丢 KV，Dynamo 实测 **681–754s**。

**做法**：基于 SGLang 的**对称引擎**用**单一调度 loop 兼做 P/D**，角色切换只改 router 请求类型——**不重启、不丢 KV，6.2s 完成**。

三个支撑点：

1. **共享 host KV 池**：L1 HBM / L2 主机内存，复用 Mooncake RDMA。
2. **排队期异步 KV fetch**：中位 **7ms**，藏进 **0.7–2.2s** 的队列等待里，几乎不额外占延迟。
3. **前缀树引用计数目录**：避免 LRU 误驱逐正在跑的 Agent 上下文。

**结果**：36×GB300 上多智能体延迟降 **4.1×**。

> 我的判断：这条改写的不是"又一个加速比"，而是**瓶颈的定义**——Agent 集群的瓶颈已从单次吞吐，转向**角色切换速度与 KV 生命周期管理**。681–754s 到 6.2s 是约两个数量级的差距，谁还停留在"重启式 PD"，谁就在 Agent 场景里被甩开。

### 常驻专题

**PD 分离**：Evolving Infra 自适应 PD 为本周头条；vLLM rc3 的 KV 预热 OOM 修复同属分离式容量规划；共识为**长提示走 PD、短提示本地算、KV-cache 感知路由 + fp8 KV 减半传输**。

**架构演进**：对称引擎 + 分层 KV + agent 感知目录；SGLang v1.0 把 Rust 关键路径 / megakernel / HiCache 正式化；vLLM DFlash / DSpark 投机、FLy 有损验证、低精度 KV 持续推进。

**PyTorch vs transformers**：vLLM 把 Gemma / StableLM **迁回 Transformers**（收敛定义层），对比新纯 PyTorch 引擎 **YASAKANI**（单卡 5090 跑 Qwen3.8-27B 自测领先）；结论＝**生产收敛到"Transformers 定义 + 自研 runtime / 算子"，纯自研 niche 化**。

**Step 适配**：

- **Step 3.7 Flash** 四格式权重 + NVFP4 & MTP 实测 **1.13×–1.45×**。
- **Step 5 Preview** 双框架 Day-0/1 + StepFun 稀疏注意力内核进 SGLang + 国产算力 Day-0；窗口内无新权重。

> YASAKANI 那条值得看：**单张 5090 跑 Qwen3.8-27B 自测领先**，说明纯自研栈在极限优化场景仍有生命力——但它没有改变生产框架的收敛方向，反而印证了"定义层交给 Transformers、runtime 自己写"的分工。

## 三、AI 论文 + 产业热点

**今日重点（1 句）**：OpenVLA-OFT 证明具身智能的"来不及"可以不换模型、只改解码配方解决——7B VLA 双臂真机跑满 25Hz、吞吐 26×、LIBERO 反涨 20.6pt；同日产业侧资本尺子正从叙事换成交付。

### 论文核心

**OpenVLA-OFT**（Stanford, arXiv:2502.19645, RSS 2025）｜ 不换底座、只换微调配方的 VLA 加速范式：**并行解码 + 动作分块 + 连续动作 + L1 回归**。核心 3 行：① 动作 token 之间改**双向掩码**，K·D 个 token 一次前向全出，把 K·D 次权重读取压成 1 次；② 分块（LIBERO K=8 / ALOHA K=25）+ 滚动时域，一次"想一段"天然降低误差累积，所以**加速同时涨点**；③ 连续动作 + 纯 L1 替代扩散 / 流匹配（50 步去噪 1.91s，1 步 LIBERO-Long 归零）。结果：**LIBERO 76.5% → 97.1%、吞吐 26×**、ALOHA 领先 π0 / RDT-1B / ACT / DP 最多 15pt。影响：单模型 + 块并行即可吃 25Hz，不必上双系统。

### 算子讲解

**DeepStack**（Qwen3-VL）｜ 只把 ViT 最后一层交给 LLM 会丢笔画 / 边缘 / 纹理，DeepStack 把**三个中间层特征以残差加法注入 LLM 前三个 decoder 层**｜在用模型：**Qwen3-VL 全系**（4B 层位 [5,11,17]，30B-A3B [8,16,24]）｜关键点：① **零 token 增量**、序列长度不变，只多三次按位置加法；② `deepstack_visual_indexes` 是 **ViT 层号而非 LM 注入层号**，端侧导图漏 merger norm 会致"框整体偏移"。

### 性能优化

**EPD 三段解耦**（SGLang / vLLM EC connector / NVIDIA Dynamo）｜ 视觉编码是独立第三阶段——**compute-bound、不产生 KV、输出是图像的纯函数**，可独立扩容 + 跨请求缓存｜代表工作：SGLang `--encoder-only/--language-only` + Mooncake 传输 + `--enable-mm-global-cache`；vLLM `ec_transfer`｜收益：独立扩容 + 消除图像对文本的队头阻塞 + embedding 级复用；emb 约 **8 MB/图**，跨机传输须先算账。
