## ★ 今日最值得关注

**SGLang 在峰会把"生产级"正式化到了 v1.0，但 GitHub 官方 tag 还停在 v0.5.23——这是一次"官宣待 tag"的里程碑，不是可以立刻升级的版本。**

这条的麻烦不在技术，而在**可达性**：

1. **官宣**：首届 SGLang Summit（11/12–13，旧金山）宣布 v1.0——330+ 机构、首日 217 个模型、同场发布 Miles v0.2；三支柱是 Rust 重写关键路径 + 零开销调度 + 投机解码 / megakernel + HiCache 分层缓存 + PD 分离。
2. **但 tag 没动**：GitHub Releases 官方 tag 仍停在 **v0.5.23**，release notes 待发。也就是说，v1.0 内核大多是 v0.5.x 既有能力的整合，仓库里还找不到对应 tag。
3. **安全没补**：SGLang 仍背着 **CVE-2026-111391**（仅 main 修复、无补丁版、v0.5.23 未修），v1.0 公告对修复只字未提；同一天 vLLM 没有同级漏洞。

**可执行结论**：把 v1.0 当"路线图确认"，别当"可装版本"。要升级就等 tag + release notes，期间继续用 v0.5.23 并盯 CVE。

> 顺带一句：这种"**峰会画饼、仓库没 tag**"的节奏，和当年 v0.5.x 大版本前的状态很像。对生产用户真正重要的不是发布会 PPT，而是 `git tag` 和 release notes 哪天落地——在那之前，v1.0 只是叙事，不是二进制。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：vLLM **v0.34.0rc0–rc2**（11/9–12 发布，GitHub Latest 仍标 **v0.33.0**）；SGLang 峰会宣布 **v1.0**，但官方 tag 仍 **v0.5.23**。

### vLLM v0.34.0 RC

**新特性 / 重要 PR**：

- **rc0：Gemma / StableLM 迁移至 Transformers 后端**（#66393）——方向是收编上游定义、降维护成本，代价是融合算子短期回归。
- **rc1：XPU 投机解码修复**——`greedy_argmax` 把 NaN 当 `-inf`，修了跨硬件乱码风险。
- **模型支持**：**Kimi K3.1 Pro 需 vLLM ≥ 0.34.0**（MXFP4、TP8、盘上约 1.56 TB）；稳定版 v0.33.0 只含 K3 代码，跑不了 K3.1 Pro。

**破坏性变更**：本周期无明确 breaking 清单见 release notes；但 rc0 的"迁回 Transformers 后端"意味着依赖自定义模型定义 / 融合算子的下游要重测——属于**隐性破坏性**（见常驻专题）。

> ⚠️ **要跑 Kimi K3.1 Pro 的**：稳定版 v0.33.0 不够，得用 ≥0.34.0（目前是 RC）。TP8 + 1.56 TB 盘上权重意味着你得先确认机器能装下，再决定追不追 RC。

### SGLang（v1.0 官宣 / tag v0.5.23）

**架构 / 性能（v1.0 三支柱）**：

- **零开销调度 + Rust 重写关键路径 + 投机解码 + megakernel**；
- **HiCache 分层缓存**：把长 Agent 历史存到显存之外；
- **PD 分离 + 多并行**。

**社区信号**：参会者转述 SGLang 约 **95% 合并 PR 由智能体编写**（vibe coding），一年前基本手写——这条比任何 benchmark 都更能说明社区产能的质变。

**已知坑（见 ★ 部分）**：v1.0 只是官宣、tag 仍是 v0.5.23 且 **CVE-2026-111391 未修**，升级前请按"官宣待 tag"处理。

### 原理：HiCache 分层 KV 缓存

本期最值得理解的一条技术解读。

**路径**：**GPU HBM → 主机内存 → 更低层存储**。

核心思路：把 KV 按**热 / 冷分层**，Agent 每一轮只拉回"新后缀 + 被选历史块"，而不是把整段长上下文永久占在显存里。

> 它和 vLLM 的"低精度 KV + 前缀缓存"是**互补**而非替代：vLLM 走"压缩体积"路线，SGLang 走"分层 offload"路线。Step 5 的稀疏注意力（3 滑窗 + 1 稀疏层）则是同一思想的**模型侧**对应设计。

收益很直接：**长上下文 Agent 负载不再为每个冷会话永久占用最贵的显存**。代价是冷恢复要付一次 I/O 尾延迟，落到 P99——交互体验最敏感的那条线。DeepSeek-V4-Flash 多轮实测 15.5× 吞吐、命中 98%，Novita 编码 Agent TTFT -56%，说明这招在 Agent 场景已经跑通。

### 常驻专题

**PD 分离**：vLLM push-NIXL + MRV2（需 NIXL 1.5+）；SGLang v0.5.21 起 PD 实例热切换（#28403）+ KVShard + DSpark-NIXL + Mooncake + sgl-router（Rust）缓存感知；Step 5 路由层按 KV 事件复用前缀；Summit 推 NVIDIA Dynamo + SGLang + Vera Rubin 方案。

**架构演进**：SGLang Rust 关键路径 + megakernel 列为头条；MTP / EAGLE / DFlash / DSpark 投机分化；NVFP4 4-bit + ROCM_OCTAVE 3–4bit 低精度 KV；Step 5 混合注意力为代表的长上下文新架构。

**PyTorch vs transformers**：**反向信号**——vLLM v0.34.0rc0 把 Gemma / StableLM **迁回 Transformers 后端**（统一定义、降维护），代价是融合算子短期回归。结论：**生产框架收敛到"Transformers 定义 + 自研 runtime"**，纯 PyTorch 栈退回研究 / 极致优化 niche。

**Step 适配**：

- **Step 3.7 Flash**（198B MoE）四格式权重（BF16 / FP8 / NVFP4 / GGUF，Apache 2.0）+ 官方 vLLM / SGLang 部署命令；NVFP4 + MTP 实测 **1.13×–1.45×**。
- **Step 5 Preview**（600B / 27B 激活、1M ctx、图文）**双框架 Day-0**：SGLang 贡献 StepFun 稀疏注意力内核，FlashInfer TRT-LLM ~299 tok/s、MegaMoE @64 ~740 tok/s/GPU、MTP 接受 2.85。
- 端侧 / 多模态：Step-3-VL-10B 本地（RTX 4090 24GB）活跃；Step-Video / Audio 华为昇腾 Day-0 适配推进。

> Step 这条值得单独看：**对 vLLM 和 SGLang 一视同仁、双框架 Day-0**，国产算力（昇腾 / 摩尔线程）也是 Day-0——这是"框架中立 + 国产硬件优先"的打法，和当年只绑一个框架的路线完全不同。

## 三、AI 论文 + 产业热点

**今日重点（1 句）**：InstructBLIP 用"指令进 Q-Former"这一处最小改动让 VLM 在 13 个未见数据集零样本全 SOTA，而具身智能产业链进入 Walker S2 量产交付 + G1-D 数采工具链的"大脑 / 数据"兑现期。

### 论文核心

**InstructBLIP**（Salesforce, arXiv:2305.06500）｜ 第一篇系统研究视觉-语言指令微调的工作。核心 3 行：① 指令文本喂进 Q-Former 的 cross-attention，而非只进 LLM；② 同图换指令 → 不同 32 个视觉 token，指令成了视觉特征的筛选器；③ 消融证明"去指令感知"只伤 held-out → 收益即泛化。影响：确立 VLM 指令微调范式（Qwen-VL 等引用），也是 RT-2 / OpenVLA / Hi Robot 语言条件化视觉的源头。

**算子讲解 · Perceiver Resampler**（Flamingo）｜ 任意帧特征 → 恒定 64 latent，让 LM 输入长度稳定。关键点：① 零初始化 tanh 门控保冻结权重；② 定长 = 信息瓶颈，但端侧 VLA 需要恒定控制延迟（SmolVLA 64 token 同思路）。

**性能优化 · SGLang HiCache 三级分层 KV** ｜ 解决 RadixAttention 前缀缓存的 GPU 显存容量天花板（L1 GPU / L2 DRAM / L3 集群存储 + HiRadixTree）；DeepSeek-V4-Flash 多轮 15.5× 吞吐、命中 98%，Novita 编码 Agent TTFT -56%。

3. **行情扩散**：资金从本体转向感知-仿真-数据环节（凡拓数创 +137%、海天瑞声 +68%）；Gemini Robotics 2.5 奔驰工厂分拣 96% → 数据 / 仿真"卖水人"逻辑。
