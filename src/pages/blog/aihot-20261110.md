## ★ 今日最值得关注

**低精度 KV cache 双线收口——vLLM 铺满全架构，SGLang 熔持久内核，Step 3.7 Flash 第一次把 NVFP4+MTP 双框架 day-0/1 跑通。**

近 72h 两框架稳定版仍收口 11-02（vLLM v0.33.0 / SGLang v0.5.23），无新发版；主线在峰会预热 + 低精度 KV 双线收口。真正值得盯的是**同一条主线在两个引擎上同时成型**：

1. **vLLM v0.33.0 把低精度 KV 铺满全架构**：NVFP4 KV 覆盖 SM8x/SM12x/SM90，AMD 新增 ROCM_OCTAVE 3–4bit KV（RX 7900 XTX 达 FP16 的 4.6× token 量），GLM-5.3-Flash 默认 FP8 KV（端到端吞吐 +9.8%）；影响：长上下文 / 高并发「不动硬件」即可约 4 倍扩容显存。
2. **SGLang v0.5.23 低延迟**：可选 NVIDIA megakernel / AMD monokernel 把 DSv4.1-Flash 解码融合为持久内核，GB300 单用户解码 +44%、MI350X +75%；DSv4.1 在 GB300 prefill +1.5x、32K–64K TTFT -28%。
3. **Step 3.7 Flash 双框架 day-0/1**：vLLM stepfun37 镜像 / 0.34 nightly、SGLang dev-step-3.7-flash，四格式权重，NVFP4+MTP 实测 1.13x–1.45x decode 提速，llama.cpp 已上游。

**可执行结论**：低精度 KV 与融合持久内核是本月共同主线，长上下文 / Agent / RAG 优先开低精度 KV 往往比换卡更划算；代价是极少量误差（Step NVFP4+MTP 质量在噪声内）。

> 值得单独说的一点：又是「**能力在 main、稳定线滞后**」的一天。Kimi K3.1 Pro 的官方 recipe 要求 vLLM 0.34.0+，但稳定线仍是 0.33.0——自托管团队的依赖管理里必须保留一条从 main 拿热修 / 新能力的应急路径，否则要么卡在旧版、要么被「能跑但不对齐」悄悄吃掉训练质量。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：近 72h **无新稳定版**。vLLM **v0.33.0**（11-02）；SGLang **v0.5.23**（11-02）。**SGLang Summit 2026 定档 11/12–13 旧金山**，议题含 Dynamo+GB200 NVL72 PD 分离 / MTP。

### vLLM

**版本 / 特性（v0.33.0）**：

- 低精度 KV 铺满全架构：NVFP4 KV 覆盖 SM8x/SM12x/SM90，AMD 新增 ROCM_OCTAVE 3–4bit KV（RX 7900 XTX 达 FP16 的 4.6× token 量），GLM-5.3-Flash 默认 FP8 KV（端到端吞吐 +9.8%）。
- MRV2 在 ROCm 成默认，prefill 上下文并行下 decode-only 全 CUDA 图比 eager 快 **2.6×**（#62377）；transformers 后端支持 MTP 草稿（#61270）。
- 生态：Kinference（vLLM + K8s 开源控制面）延续，从单机引擎走向多租户编排层。

**破坏性变更（0.32–0.33，升级前须逐条核对）**：

**社区**：Kimi K3.1 Pro recipe（11-05）要求 vLLM **0.34.0+**，当前稳定版仍 0.33.0，需专用镜像或 nightly → 追新模型得自己拉 nightly，生产建议锁 v0.33.0 防 CUDA13 依赖漂移。

### SGLang

**性能 / 版本（v0.5.23 低延迟）**：

- 可选 **NVIDIA megakernel / AMD monokernel** 把 DSv4.1-Flash 解码融合为**持久内核**，GB300 单用户解码 **+44%**、MI350X **+75%**；DSv4.1 在 GB300 prefill **+1.5x**、32K–64K TTFT **-28%**。
- 新增模型：**Muse Spark Open**（46 SWA + 16 全注意力、图 / 视频、DFlash V2、EPD / PD 分离）、Beam-1.0、MiniMax-M3.1-Flash、MiniCPM-V 4.7。
- 重要 PR：**#47960** DSV4 top-k 默认 exact（108 B300 shape 中位快 3.5%）；**#45828** Hopper FP8 GEMV 单流 decode +7.3%；**#47853** HALOps MXFP8 后端使 DSv4-Flash mean TTFT 较 DeepGEMM 减半。
- 事件：SGLang Summit 2026 本周三 / 四旧金山，议题含 Dynamo+GB200 NVL72 PD 分离 / MTP。

### 原理：低精度 KV cache 为什么能约 4× 扩容显存

本期最值得理解的一条技术解读。

**推理显存 ≈ 固定权重 + 随并发 × 上下文线性增长的 KV cache**；FP16 → FP8 → 4bit 两次减半，使同卡上下文容量约 **4 倍**。vLLM v0.33.0 把 NVFP4 / ROCM_OCTAVE 3-4bit 铺开全架构，GLM-5.3-Flash fp8_ds_mla 吞吐最高 **+31%**。

代价是极少量误差（Step NVFP4+MTP 质量在噪声内），长上下文 / Agent / RAG 场景优先开低精度 KV 往往比换卡更划算。

> 我的判断：低精度 KV 与融合持久内核是本月两框架的共同主线。它不要求换硬件，却能把长上下文 / Agent 负载的显存上限推高约 4×——但前提是接受极少量数值误差。对 RAG / Agent 这类「上下文长、对偶发精度不敏感」的负载，先开低精度 KV 比堆卡更划算。

### 常驻专题

**PD 分离**：vLLM push-NIXL + MRV2（NIXL 1.5+）；SGLang v0.5.23 PD + KVShard + DSpark-NIXL + Mooncake，长提示 +27% 吞吐 / p95 TTFT 减半，新增 prefill_complete 分配策略；Step 无独立方案。

**架构演进**：NVFP4 4-bit KV + ROCM_OCTAVE 3-4bit + DSpark monokernel + MTP + DFlash V2；低精度 KV 与融合持久内核是本月共同主线。

**PyTorch vs transformers**：上周 Shrike / NanoInfer 印证自研栈可行，本周无新 PR；vLLM 依赖 transformers>=5.16.1,<5.20.0 须 pin。

## 三、AI论文与产业热点

### 论文核心 · Concertina：动作即连续 latent token

**arXiv:2611.07513（2026-11-05，代码 / 权重开源）**

- 一句话定位：把「一个控制步的 D=20 动作向量」编码成扩散 VLM 隐藏空间里的**一个连续 latent token**，用骨干原生的「打码—补全」算子重建动作块，取消动作分词器与动作专家。
- 核心思想三行：① 动作块 = 一串连续 latent token，生成动作退化为「补全被遮 token」；② 块内双向、块间因果，[C, Z̃, Z] 打包一次前向监督 M 个块；③ 损失落在物理坐标上（平移:旋转:夹爪 = 500:10:1，1/t 反加权），非 token 交叉熵。
- 关键数：动作参数 9.49M / **0.21%**（π0 16.51%、X-VLA 35.10%）；LIBERO **98.15%**、LIBERO-Plus 85.9%（8615/10030）、CALVIN AvgLen 4.142（SR@5 64.9% 仍弱于 X-VLA 78.8%）。
- 影响：VLA 参数量账本可能重写（不必「7B 骨干 + 3B 专家」），端侧显存 / 延迟预算松动；与双系统 S1/S2 路线正面竞争。风险：基准趋饱和，RoboColosseum 显示跨本体排名一致性仅 Kendall W=0.24。

### 算子讲解 · 掩码扩散（Masked Diffusion / absorbing-state）

- 定位：把串行生成改成「整块打码—并行补全」，是 LLaDA / Dream / BARD-VL / DiffusionGemma 的共同地基。
- 在用模型：LLaDA 8B（w(t)=1/t，半自回归 32 位块）、Dream 7B（Qwen2.5-7B 扩散化 + CART）、BARD-VL（Qwen3-VL 块合并 4→8→16→32 + 混合噪声学「改错」）、DiffusionGemma（256 token 块、1000+ tok/s）。
- 关键点：省的是串行深度（L→T）不是 FLOPs——每步全长双向且无 KV cache；双向性是 AR 结构上做不到的能力，但 commit 规则会引入采样器偏置。

### 性能优化 · 模型级联路由（Cascade / Router）

- 定位：优化「单位成功任务成本」，而非单次前向 kernel。
- 代表工作与收益：RouteLLM 省 85% 成本保 95% GPT-4 质量（仅 14% 请求需前沿），FrugalGPT 最高 98%；生产诚实区间 40~70%（Cursor 60%、Ramp 40%）。
