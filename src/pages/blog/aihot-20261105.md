> **关于本期来源**：今天 vLLM / SGLang 社区跟踪摘要与 AI 论文 + 产业热点摘要**双双到齐**，因此本期同时覆盖推理基础设施与论文 / 产业两部分。

## ★ 今日最值得关注

**vLLM v0.33.0 在 11-02 正式转正稳定版——但它是「带刺」的升级：一篮子破坏性变更（Python 3.10 弃用、依赖门槛 transformers≥5.16.1、max_tokens 语义从「预留窗口」改成「输出上限」）意味着存量部署不是「升就完事」，而是「升之前先对账」。** 同日 SGLang 0.5.23 把 PD 分离推到生产级——两个框架不再比谁的草稿快，而是比谁的分离式部署更稳、更省、可观测。

三层事实：

1. **版本本体**：vLLM v0.33.0（11-02，从 rc3 转正，前稳定版 v0.32.0 是 10-17）；SGLang v0.5.23（11-02 正式发布，tag 10-30）窗口内无新 tag，维持既有结论；Step 系列也无新权重。
2. **破坏性变更（会直接打断线上）**：Python 3.10 不再支持（最低 3.11，支持至 3.14）；依赖门槛 transformers≥5.16.1、tokenizers≥0.23.2；`max_tokens` 语义反转——长提示 + 大 max_tokens 不再被拒，计费 / 截断逻辑要重对；移除 cascade attention、mamba_cache_mode="all"、torch.compile 序列并行、AsyncTP 编译 pass、一批旧废弃 API 与 LoRA Tensorizer；Responses API 流式事件改名；Rust 前端 qwen3_xml 改解析 Qwen3-Coder XML（JSON 改用 qwen3_json）。
3. **共同主线**：PD 分离同步推向生产级（vLLM NIXL V2 跨层 KV + Mooncake 内置 bootstrap；SGLang KVShard），投机解码（MTP / EAGLE / DFlash）+ 低延迟内核融合。

**可执行结论**：跑存量 vLLM 部署 → 升 0.33.0 前先核对破坏性清单（尤其 max_tokens 语义与 Python 版本），别只看版本号到 0.33.0 就过工单；新装默认更省显存（共享内存张量竞技场、GLM-5.x SM100 默认 FP8 KV）但行为漂移要留意。

> 值得单独说的一点：这印证了一条铁律——版本号的「稳定」不等于「对你零成本」。当 max_tokens 从「预留窗口」变成「输出上限」，你的计费 / 截断逻辑可能在升级后悄悄变样；当 Python 3.10 被弃用，你的老镜像可能直接起不来。升级清单里必须有「破坏性变更逐项对账」这一行，而不是把版本号当安全 / 可用凭证。

## 二、vLLM & SGLang 社区跟踪

**版本状态**：**vLLM v0.33.0（11-02）转正为 latest stable，无新 tag**；**SGLang v0.5.23（11-02 发布 / tag 10-30）仍是 latest，无 v0.5.24**；Step 系列窗口内无新权重 / 新发版。发版后两边主线都转向「工程硬化 + PD 分离推生产」。

### vLLM v0.33.0（转正主线）

**破坏性变更（部署必读）**：

- **Python 3.10 不再支持**（最低 3.11，支持至 3.14）——老镜像可能直接起不来。
- **依赖门槛拉高**：transformers≥5.16.1、tokenizers≥0.23.2。
- **`max_tokens` 语义反转**：由「预留上下文窗口」改为「输出上限」——长提示 + 大 max_tokens 不再被拒，**计费 / 截断逻辑需重对**。
- **移除**：cascade attention、mamba_cache_mode="all"、torch.compile 序列并行与 AsyncTP 编译 pass、一批旧废弃 API 与 LoRA Tensorizer 支持。
- **改名 / 改行为**：Responses API 流式事件改名；Rust 前端 qwen3_xml 现解析 Qwen3-Coder XML（JSON 改用 qwen3_json）。

**新默认行为（更省更快，但漂移需留意）**：

- 共享内存张量竞技场默认开启。
- GLM-5.x 在 SM100 上 `--kv-cache-dtype auto` 默认走 FP8；ROCm 上 MRV2 默认；SM90 上 Humming 内核优先于 Marlin。

**新特性 / 性能（量化内核广度）**：

- **AlphaMoE NVFP4 MoE 融合批处理内核**（2-stage 输出缓冲 + 256B L2 promotion、up kernel 提前加载 top-k）：据 PR 在 GB300 / B200 上 NVFP4 MoE 最高约 **1.133×**、W8A8 MoE 约 **1.078×**。
- 新增 unquantized / MXFP4 / WNA16 / scaled_mm / FP8 MoE 内核、ARM KleidiAI INT4、NVFP4 / FP8 上 Turing、TP>4 的 FP4 GEMM → **低精度 MoE 在更广硬件（NVIDIA / AMD / Intel / ARM / IBM Z）提速、成本下降**。

**PD 分离改进（可落地 + 可观测）**：

- Mooncake connector 重构带 bootstrap server（#31034）；NIXL Connector V2 跨层 KV 缓存布局（#33339）；KV offloading connector 指标（#27942）；P / D 分离带标签 prompt token 指标（#33290）→ 大规模分离式部署更易落地、可观测性增强。

### SGLang v0.5.23

**无新发版，维持 11-02 结论**：DeepSeek-V4.1 性能 + 低延迟 megakernel / monokernel + Paged Experts + TPU7x + 量化 MoE LoRA + HiCache L3 + KVShard / PD 增强。

**常驻结论**：PD 分离需配 KV 完整性校验（`--disaggregation-enable-kv-checksum` / `--kv-canary`）；DeepSeek-V4.1 默认在 PD 下启用 MegaAttention 并要求 prefill 与 decode **同时升级**（KV 布局握手），decoder **SWA bounded replay 默认开**（数值与完整 prefill 不完全一致，可用 `--no-enable-decoder-swa-bounded-replay` 关闭）。

### 阶跃 Step 系列（窗口内无新权重）

- SGLang v0.5.23 已将 **Step 5 Preview** 列入「preview 模型」支持清单；官方 README 给出 vLLM / SGLang / Transformers 生产部署矩阵（FP8 单 H200 8 卡 DP2×TP4 EP8、BF16 双 H200 16 卡等）。
- **实测参考**：OpenZeka 测 Step 5 Preview（DGX B300 FP8、vLLM TP4、MTP k=3）单请求 **145.1 tok/s**、TTFT **51ms**，预估容量 **512（chat）/ 141（agentic）**；Artificial Analysis 智能指数 **43.7**。

### 原理：PD 分离在两大框架同步推向生产级

本期最值得理解的一条技术主线——两个框架同一天把分离式部署从「能跑」推到「可生产」。

- **vLLM NIXL Connector V2「跨层 KV 缓存布局」**：多层 KV 连续布局、减少传输描述符、提升 RDMA 有效带宽；Mooncake connector **内置 bootstrap server**，免外部引导、降低连接建立失败。
- **SGLang v0.5.23 KVShard**：MTP KV 分片 + 0SM KV Cache Allgather + PD 传输免主机同步，预建解码批次输入直接拷至 GPU。
- **机制共性**：都是「减少 KV 传输元数据开销 + 削减 CPU 介入」→ 直接提升分离式部署有效吞吐、降低 TTFT。

### 常驻专题

**PD 分离**：vLLM v0.33.0 落地 Mooncake 重构（#31034）+ NIXL V2 跨层 KV（#33339）+ P / D 带标签指标（#33290）；SGLang v0.5.23 以 KVShard（MTP KV 分片 / 0SM Allgather / 免主机同步）+ NIXL 每 GPU UCX 设备选择 + Mooncake 默认失败会话探测推进。量化收益：SGLang CP QSA（CP4 8K 预填充延迟 -26.5%）、KVShard 0SM Allgather。

**架构演进**：vLLM 低精度 MoE 内核（NVFP4 / W8A8 融合批处理 ~1.13× / 1.08×、FP8 block quant、ModelOpt MXFP8、Turing 上 NVFP4 / FP8）；SGLang 低延迟 megakernel / monokernel（DeepSeek-V4.1-Flash 单用户解码 GB300 +44% / MI350X +75%）、FlashAttention draft-extend CUDA 图捕获（bs1 单层 MoE drafter ~1.5× 解码吞吐）、Breakable CUDA Graph（V4.1 GB300 TP4 8K 预填充 +33%、+DP 注意力 +37% / +50%）、DFlash / DFlash2 CUDA 注意力 DP、确定性种子化拒绝采样。

**纯 PyTorch vs transformers**：TensorRT-LLM 自 v1.0.0（2025-09-24）转 PyTorch 默认后端、v1.3.0rc20（2026-06-30）起移除 TensorRT 后端、现 PyTorch 为唯一执行后端；Step 5 Preview 自带 standalone Transformers 实现（inference / model.py + vision_encoder.py + kernel.py 的 Triton / CUDA 算子），即模型方自研 PyTorch 推理栈。动机：更可控算子、更低开销、便于定制 attention / 采样、减少依赖与版本耦合；代价：需自实现 tokenizer / 模型加载 / 并行。结论：生产用框架 + transformers 作桥，研究 / 教学 / 极致可控走纯 PyTorch 自研内核。

**Step 适配**：SGLang v0.5.23 将 Step 5 Preview 列入 preview 支持；Step 5 Preview 与 Step 3.7 Flash 均有官方 vLLM / SGLang 部署指南，配专用 stepfun / step3p5 reasoning / tool-call parser 与 MTP / EAGLE 投机解码，均依赖 `--trust-remote-code`；Step 3.7 Flash 近一等公民、Step 5 Preview 经 v0.5.23 进 SGLang 官方清单；国产硬件 Day-0 矩阵（昇腾 / 沐曦 / 壁仞 / 摩尔线程 / 海光）持续。

## 三、AI 论文与产业热点（本期有来源）

### 论文核心

**GR-2**（ByteDance Research，arXiv:2410.06158，2024-10）——视频生成预训练 → VLA 联合微调的字节路线代表作。Stage1 在 **38M 视频（50B+ token）** 上做「文本 + 当前帧 → 自回归预测未来 VQGAN 帧 token」；Stage2 在约 **5000 条轨迹** 上同时预测未来帧与 cVAE 动作轨迹，视频预测保留为伴随任务 = 物理一致性 grounding。影响：与 RT 系（VLM 预训练）、π0 系（流匹配动作专家）构成三条 VLA 路线；**105 任务 97.7%**、小样本 50 轨迹 / 任务 **73.9%**、bin-picking **79.0% vs GR-1 33.3%**、CALVIN **85.9%**；字节 Seed GR-3 延续。

### 算子讲解

**InfoNCE 对比损失**（Oord 2018，arXiv:1807.03748）｜定位：把「拉近正对、推远负对」变成 batch 内 softmax 分类。在用模型：CLIP（τ 可学习初始 0.07、logit scale 截断 100）、SigLIP（sigmoid 变体）、Qwen3-VL SigLIP2、OpenVLA / Flamingo 视觉对齐前置。关键点：batch 互为负样本（CLIP 32768 batch → **32767 免费负样本**）；小 batch 用 MoCo 队列；τ 别手调死值；具身 = VLA 视觉塔 / 端侧小视觉塔蒸馏地基。

### 性能优化

**vLLM V1 统一调度器体系**（2025-01 alpha）｜定位：prefill + decode 合并单队列，解决混合负载 prefill 抢 decode 瓶颈；chunked prefill + 零开销前缀缓存默认开。代表工作：vLLM V1 alpha（FA-3、disaggregated prefill）；与 DeepSeek V4-Flash PD 分离 + DSpark 组合成「调度层 + 算法层」标杆。收益：长 prompt 不再阻塞生成会话；多机器人场景共享前缀白捡缓存命中，控制指令高优保 **10Hz VLA 控制流**。

## 四、一句话结论

**版本平静、但升级有刺的一天：正是 vLLM v0.33.0 把 PD 分离健壮性（Mooncake 重构 + NIXL V2 跨层 KV 布局）与量化内核广度（NVFP4 / W8A8 ~1.13× / 1.08×、ARM INT4、Turing FP4）收敛成稳定版，SGLang 0.5.23 以 KVShard 把分离式部署推到生产级，两个框架转向「比谁更稳更省」；而反面的刺是 v0.33.0 那一篮子破坏性变更（Python 3.10 弃用、max_tokens 语义反转、依赖门槛拉高）——跑存量 vLLM 的部署，请现在就逐项对账破坏性清单再升级，别把「稳定版」当零成本凭证。论文侧 GR-2 用 3800 万条视频当物理教材，与 AGLT 挂牌、优必选 Thinker-Sim、宇树自进化同日共振，资金正把机器人定价重心移向「数据与仿真」。**
