## ★ 今日最值得关注

**vLLM v0.34.0 稳定版落地了——extensible KV cache 默认开启、Model Runner V1 被移除。这是本周两个框架里唯一的稳定版，但「默认开启」四个字同时带来吞吐红利和一道必须做的迁移。**

这是今天唯一一条能让你立刻决定"要不要上生产"的发布，麻烦不在版本号，而在它一次改了三件跟容量和启动有关的事。

三层事实：

1. **落地**：v0.34.0 于 11-16 23:22（UTC）发布，**1061 commits / 412 贡献者**；**extensible KV cache 默认开启**（#56492）、**Model Runner V2 独占**；**10 个新模型**（Mistral Large 4、MiniMax-M3.1-Flash、Nemotron-3.5-Transcribe 等），**Kimi K3.1 Pro 进正式版**——K3.1 Pro 终于可以脱离 nightly、用官方镜像。
2. **红利**：H200 上 MiniMax-M3 的 KV 缓存 **433k → 672k tokens**；**Step5 NVFP4 MoE 在 4×GB200 上最高 1.95× decode**（#65152），**GLM-5.3-Flash 1.6× 吞吐**（#60895）、**TTFT 1.24–1.40×**（#63956）。
3. **代价**：这不是免费午餐——缓存变大后工作集更容易超出 L2 / 带宽舒适区，**并发 128 时 TPOT +6–18%**；同时 **Model Runner V1 被移除**（#63373），**自定义 V1 logits processor 必须迁移，否则启动失败**。

**可执行结论**：批量吞吐业务直接吃默认开启的红利；单流低延迟要做 A/B，必要时用 `--no-enable-extensible-kv-cache` 或 `--gpu-memory-utilization 0.9` 回退。升级前先审计有没有自定义 V1 logits processor。

> 值得单独说的一点：**SGLang 的 v1.0 已经官宣一周，tag 还停在 v0.5.23**（11-02，1007 PR / 257 人），notes 未落地、CVE-2026-111391 未补。同一周里 vLLM 把稳定版往前推了一大步、SGLang 还停在"已官宣、未 tag"——**谁在按发布节奏交付、谁还停留在公告，今天这条时间线说得很清楚。**

### 原理：Extensible KV cache 的"容量换时延"

本期最值得理解的一条技术解读。

**做法**（#56492）：把 KV 显存从"启动前按 `gpu_memory_utilization` 估算"改为"**warmup + CUDA graph 捕获后读实际空闲内存再定容**"。H200 MiniMax-M3 因此 **433k → 672k tokens**。

本质是**容量换时延**：cache 变大后工作集更容易超出 L2 / 带宽舒适区，所以**并发 128 时 TPOT +6–18%**。

> 我的判断：这条改动的正确用法是按业务形态分叉——**批量吞吐业务默认开启最划算，单流低延迟必须 A/B**。它把"显存该留多少"从人工拍脑袋变成运行时实测，但代价是把一部分确定性换成了尾延迟的波动。别把它当成无脑的免费加速。

### 常驻专题

**PD 分离**：vLLM v0.34.0 支持 **MiniMax-M3.1-Flash prefill / decode 不同 TP**（#64475）；**Kimi-K3.1-Pro 3P1D 生产配方**（NIXL + Mooncake RDMA + ZMQ 前缀路由）；**Evolving Infra 对称引擎角色切换 6.2s vs Dynamo 681–754s**、**36×GB300 多智能体延迟降 4.1×**。

**架构演进**：SGLang **Megakernel（2.14×）+ Unified Memory**；vLLM **DSA 稀疏注意力**（Kimi K3.1 Pro 24 层、长上下文读取约 1/4 字节）+ 低精度 KV + **MTP / DSpark / DFlash** 投机解码。

**PyTorch vs transformers**：本周**无新脱离 transformers 的 PR**；vLLM 把 **Gemma / StableLM 收编回 Transformers 后端**（依赖收紧到 hf_hub≥2.0.0），SGLang 反向用 **Rust 关键路径 + CUDA megakernel** 绕开 Python 开销。结论＝**覆盖度选 transformers 桥、极致低延迟选自研内核**。

**Step 适配**：**Step5** 官方 **1.95×** 量化性能背书 + 双框架 Day-0/1 + 国产算力 Day-0；**Step3.7 Flash** 四格式双栈镜像 + NVFP4/MTP **1.13–1.45×**；**Step3-VL-10B** 双框架部署齐备。留意 **Step5 自定义商用许可**。

## 三、AI 论文 + 产业热点

**今日重点（1 句）**：BLIP-3 用"去 Q-Former + 统一自回归"的架构减法证明多模态胜负手在数据而非桥接器——同一思想正沿 VLA 骨干轻量化路线渗入具身智能；产业侧华为云开源世界模型、京东双11 人形销量 +700% 给出放量口径。

### 论文核心

**BLIP-3 / xGen-MM**（Salesforce, arXiv:2408.08872, 2024-08）｜ 开源 4B 级多模态基座，BLIP 谱系（BLIP-2 → InstructBLIP → BLIP-3）收官。三步减法 + 加法：① **Q-Former（188M / ITC+ITM+ITG 三损失）→ Perceiver Resampler**（128 tok / 视图、任意分辨率 ≤12 patch 拼接、预算 128×(1+n)≤1664）；② **全阶段统一自回归损失** `L=-Σ log p(x_t|x<t,V)`，视觉 token 作特殊 token 直接进序列，SigLIP 冻结 + phi3-mini 3.8B；③ **数据工程补位**——MINT-1T 32.5% / KALE 25% / OCR-200M 5% / GROUNDING-50M 5% / OBELICS 17.5%，四阶段 100B tok → HD 30B → SFT 3M → DPO 安全版。影响：**"骨干减负、数据增重"直通 π0 / π0.5 / SmolVLA 的 VLA 轻量化路线**；图文交错输入＝机器人多视角 + 指令 + 历史帧的雏形。

### 算子讲解

**ITM 头**（Image-Text Matching）｜ 图文匹配二分类头，`s = w^T·h(img,text) + BCE`，用 ITC 相似度挖困难负例；检索两阶段＝**ITC 粗排 → ITM 精排**｜在用：**BLIP-1/2、ALBEF、InstructBLIP**；**BLIP-3 / CLIP / SigLIP 已弃用**，思想延续为 reranker / 幻觉过滤头｜关键点：收益几乎全来自困难负例质量；判别/生成头梯度打架正是 BLIP-3 做减法的动机；具身关联＝**VLA 指令执行校验器**。

### 性能优化

**多模态 Embedding 缓存**｜ 图像是纯函数 → encoder 输出按内容哈希缓存，命中即跳过 compute-bound 的 ViT 前向（≈**8 MB/图** bf16 @1024×4096）；叠加视觉 token 前缀 KV 复用，连 prefill 一起省｜代表工作：**SGLang `--enable-mm-global-cache`**（EPD encoder 段天然缓存点）、vLLM 多模态前缀缓存｜收益：图未变、问题在变的高频模式下 TTFT 大降，且与 PD / EPD / 前缀缓存正交。
